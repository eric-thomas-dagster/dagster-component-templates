# AgentCardWorkspaceComponent

Bulk-declare a whole fleet of hosted agents from one external manifest, instead of one [`AgentCardComponent`](../agent_card/README.md) YAML per agent. Same relationship `snowflake_workspace`/`stripe_workspace` have to their single-asset siblings: one config block emits many assets.

The manifest is a flat JSON array of agent-card objects in the exact same shape `AgentCardComponent` emits (`agent_id`, `name`, `description`, `skills`, `invocation`, ...) — so a platform team can maintain one central registry (every MCP server, every hosted agent, across every project) at a URL, and any project's `AgenticPipelineComponent` `delegate` step can discover and route to all of them.

This component only brings in an external registry. It does not also scan for sibling `AgentCardComponent` instances — that stays `delegate`'s job, which already merges both sources. Because `delegate`'s sibling scan reads `metadata["agent_card"]` off any `AssetSpec` in the folder, the specs this component bulk-emits are picked up by that scan automatically — no changes to `delegate` needed.

## Example

```yaml
type: dagster_community_components.AgentCardWorkspaceComponent
attributes:
  manifest_url: https://internal.example.com/agents/manifest.json
  include_tags: [customer-support]
  max_agents: 50
  group_name: agent_registry
```

Or from a local file (e.g. checked into the same repo as the pipeline that will call `delegate`):

```yaml
type: dagster_community_components.AgentCardWorkspaceComponent
attributes:
  manifest_path: ./agents_manifest.json
```

## Manifest shape

```json
[
  {
    "agent_id": "refund_lookup_agent",
    "name": "Refund Lookup Agent",
    "description": "Looks up refund status and policy exceptions for e-commerce orders.",
    "skills": [
      {"id": "lookup_refund_status", "name": "Lookup refund status", "description": "...", "tags": ["refunds", "customer-support"]}
    ],
    "invocation": {
      "mcp_server": {"name": "refunds-mcp", "type": "http", "url": "https://internal.example.com/mcp", "headers_env": {"Authorization": "REFUNDS_MCP_TOKEN"}},
      "tool_name": "lookup_refund"
    }
  }
]
```

See `sample_agent_manifest.json` in this folder for a fuller fixture (MCP- and HTTP-hosted entries, used as the integration-test fixture for this component and for `delegate`).

## Use it with `delegate`

Point an `AgenticPipelineComponent` `delegate` step's `registry.manifest_url`/`manifest_path` at the same manifest this component reads, or just rely on sibling-discovery (`discover_siblings: true`, the default) to pick up whatever this component emitted in the same defs folder — no extra wiring required either way.
