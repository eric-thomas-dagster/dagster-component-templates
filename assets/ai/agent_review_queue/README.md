# agent_review_queue

The **review queue** for agentic pipelines. [`agentic_pipeline`](../agentic_pipeline/README.md)'s `approve` op writes a pending record to
`<approval_dir>/pending/<key>.json` whenever a human decision is needed. This asset gathers those records — across as many approval
directories as you give it, local or `s3://` / `gs://` / `abfs://` — into a DataFrame you can open in the Dagster UI: *what is waiting for a
person, for how long, and what happens if nobody answers.* An asset check flags reviews that are overdue.

It is **read-only**. It never approves or rejects anything; a person (or a Slack bot, Retool form, CLI…) decides by writing the token file named
in each row's `approve_path`:

```bash
echo '{"approved": true, "approver": "eric@dagsterlabs.com", "reason": "PO confirmed"}' > approvals/INV-2291.json
```

```yaml
type: dagster_community_components.AgentReviewQueueComponent
attributes:
  asset_name: agent_review_queue
  approval_dirs: [./approvals, s3://acme-agents/billing-approvals]
  overdue_after_minutes: 60
  overdue_severity: WARN
  cron_schedule: "*/5 * * * *"
```

## What you get

| Output | |
|---|---|
| DataFrame | one row per pending review: `approval_dir, key, step, summary, requested_at, expires_at, age_minutes, overdue, on_timeout, approve_path` |
| Metadata | `pending_count`, `overdue_count`, `oldest_age_minutes`, a markdown preview of the queue |
| Asset check `no_overdue_reviews` | fails (WARN or ERROR) when any review is older than `overdue_after_minutes` **or** past its own `expires_at`; lists the overdue keys. Attach a Dagster+ alert policy to it to notify someone. |
| Schedule (optional) | `cron_schedule` re-materializes the queue so it stays current |

An unreadable pending record is shown as overdue rather than hidden. A review leaves the queue when its gate runs and finds the token (the token
stays as the audit record).

## How it fits

`agentic_pipeline` → `decide` (named outcome) → `approve` with `when:` (only exceptions reach a person) → **this queue** → a person writes the token →
the next run continues. See [`governed_invoice_matching`](../agentic_pipeline/examples/governed_invoice_matching/README.md).

**Verified:** the tests (`tests/`) use the real `approve` op to write the pending records and read them back, including `memory://` (fsspec) storage,
overdue-by-age, overdue-by-expiry, and the asset check. Not run against a live cloud bucket.
