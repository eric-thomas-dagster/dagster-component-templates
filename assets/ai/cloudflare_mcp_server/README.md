# CloudflareMcpServer

A local **stdio MCP server** that proxies to Cloudflare's own hosted MCP server
(`https://mcp.cloudflare.com/mcp`), authenticated with a static **Cloudflare API token** — no
OAuth, no token refresh, no sign-in CLI. Confirmed directly against Cloudflare's own docs: for
CI/CD or automation, Cloudflare's own documentation recommends creating an API token (My Profile →
API Tokens) scoped to the permissions the run needs, and passing it as a bearer token — exactly
what this component does.

```yaml
type: dagster_community_components.CloudflareMcpServerComponent
attributes:
  resource_key: cloudflare_mcp
  api_token_env_var: CLOUDFLARE_API_TOKEN
```

Then, in any MCP-aware component (anthropic_agent / openai_agent / litellm_agent / gemini_agent /
agentic_pipeline) instead of an inline `server:` spec:

```yaml
server_resource_key: cloudflare_mcp
```

## Generic tool passthrough, not one tool per Cloudflare product

Cloudflare's own hosted MCP server already fronts 2,500+ endpoints across every Cloudflare
product behind its own two meta-tools (`search`/`execute`), rather than one tool per operation.
This proxy exposes that same shape generically so it keeps working if Cloudflare's own tool
surface changes:

- `list_remote_tools` — lists the Cloudflare MCP tools currently available (name + description).
- `call_remote_tool(tool_name, arguments)` — calls one by name with a JSON-object of arguments.

## `allow`

Restrict which Cloudflare MCP tools are callable, independent of what Cloudflare's hosted server
exposes:

```yaml
allow:
  - search
```

## Per-server usage guidance (`instructions`)

Set `instructions` here, once, instead of pasting the same guidance into every agent that uses
this server via `server_resource_key`. The litellm/openai/anthropic/gemini agent components read
it off the resolved resource and append it to their system prompt under a heading with this
resource's `resource_key` name.
