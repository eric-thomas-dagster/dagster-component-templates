# ComfyUI Workflow Run

Submits a [ComfyUI](https://www.comfy.org/) workflow -- the node graph you build in ComfyUI's own UI, exported in **API format** -- to a ComfyUI server as a Dagster asset: queues it, polls for completion, and downloads every generated image.

## The workflow graph is where the sophistication lives, not this component

ComfyUI's real power -- checkpoints, LoRAs, ControlNet, inpainting/masking, img2img, upscaling, batching -- is all encoded in the node graph JSON itself. This component doesn't reimplement any of that as separate Dagster fields; it submits whatever graph you give it. What it adds is `node_overrides`: a way to change *specific node inputs* at materialize time (e.g. swap a `CLIPTextEncode` node's prompt text, or a seed), with the same `{partition_key}`/`{partition_date}`/`{partition_start}`/`{partition_end}` token substitution every other source component in this registry uses -- so one exported workflow can be reused across many materializations instead of hand-editing JSON per run.

## Example YAML

```yaml
type: dagster_community_components.ComfyUIWorkflowRunAssetComponent
attributes:
  asset_name: product_hero_image
  comfyui_url: http://comfyui-server:8188
  workflow_path: workflows/product_hero.json
  node_overrides:
    "6":
      text: "a studio product photo on a white background, {partition_key}"
  partition_type: dynamic
  dynamic_partition_name: products
  output_dir: /data/comfyui_output
  group_name: creative
  kinds: [comfyui, image]
```

## Exporting a workflow

In ComfyUI's UI: enable Dev Mode (Settings -> Enable Dev mode options), then "Save (API Format)" on the graph you've built. That JSON file is what `workflow_path` points to (or inline it directly under `workflow:`).

## Composing with the rest of this registry

This is a building block, not a bespoke "agentic image pipeline" -- pair it with [`agentic_pipeline`](../agentic_pipeline/README.md) (an LLM step decides the prompt/params via `node_overrides`) and an existing vision op like `image_llm_extractor` (critiques the generated result, optionally triggering another run) using this registry's normal `source:`/`inputs:` chaining. No new orchestration primitives needed.

## Failure handling

ComfyUI reports two different kinds of failure, both handled explicitly:
- **Graph validation failure** (`node_errors` in the `/prompt` response) -- raised immediately, before ever polling. Means the graph itself is broken (missing node, bad input type).
- **Execution failure** (`status.status_str == "error"` once the history entry completes) -- the graph was valid but a node failed while running.

Set `fail_on_node_errors: false` / `fail_on_execution_error: false` to materialize anyway instead.
