# dagster_api_check_tools

Confirms Dagster names exist in the INSTALLED Dagster version (with their real signatures), and scans Python source for removed, deprecated or superseded Dagster API usage -- so an agent proposing a code change checks against reality instead of guessing a name that doesn't exist (models suggest things like `AssetAutoMaterializePolicy`, which was never real) or suggesting an already-deprecated replacement.

| Tool | Answers |
|---|---|
| `check_dagster_api(names)` | for each dotted name (`dg.X` is treated as `dagster.X`): does it exist in the installed version, and if so, its real signature |
| `scan_source(path, source)` | removed / deprecated / superseded Dagster API usage in one file's source text -- import of a name that no longer exists, a deprecated or superseded class/function, or a deprecated keyword argument on a call |
| `scan_sources(files)` | same, batched across several `{path, source}` entries in one call, deduplicated and sorted |

Every result is a compact dict; failures come back as `{"error": "..."}`, never an exception.

## Not coupled to any repo-hosting service

`scan_source`/`scan_sources` take source text directly -- the caller supplies it (from [`github_pr_tools`](../github_pr_tools)'s `get_pull_request` file patches, a local read, any MCP filesystem server, ...) rather than this component fetching files itself. One tool, reusable regardless of where the code lives.

## Using from Claude Code (`claude mcp add`)

```bash
claude mcp add dagster-api-check -- python -m dagster_community_components.assets.ai.dagster_api_check_tools.component
```

No environment variables are required -- both tools are pure introspection against the `dagster` package already installed in whatever Python environment the server runs in.

## As a Dagster resource

```yaml
type: dagster_community_components.DagsterApiCheckToolsComponent
attributes: {}
```
`context.resources.dagster_api_check_tools.call("check_dagster_api", {"names": ["dg.AutomationCondition.eager"]})`.

## Wiring it into an agent

Same dual-mode shape as `agentic_pipeline_authoring_tools`/`dagster_instance_tools`/`dagster_workflow_tools`: `component.py` is itself a stdio MCP server (`pip install mcp`; verified with mcp 1.30.0 and 2.3.0).

```yaml
- id: propose_change
  op: tool_use_loop
  model: gpt-4o-mini
  api_key_env_var: OPENAI_API_KEY
  prompt_template: "Draft a Dagster code change that {text}. Call check_dagster_api for every Dagster name before you use it in a snippet; if a name does not exist, use one that does."
  mcp_servers:
    - name: apicheck
      type: stdio
      command: [python, -m, dagster_community_components.assets.ai.dagster_api_check_tools.component]
```

Tools are namespaced by the loop as `apicheck__check_dagster_api`, etc.

## Referencing it by key (`mcp_server_resource_key`)

Same convention as the other dual-mode tool components -- set `mcp_server_resource_key` to register a second, [`MCPServerResource`](../../../resources/mcp_server_resource)-shaped resource under that key.

```yaml
type: dagster_community_components.DagsterApiCheckToolsComponent
attributes:
  mcp_server_resource_key: dagster_api_check_tools_mcp
```
Then, in any MCP-aware component: `server_resource_key: dagster_api_check_tools_mcp`.

## How this is built

`check_dagster_api` resolves each dotted name against the real, installed `dagster` package via `importlib`/`getattr` and reports `inspect.signature(...)`. `scan_source` walks the file's AST tracking `import dagster` / `from dagster import ...` aliases, then checks every attribute-chain usage and import against `dagster._annotations` (`is_deprecated`/`get_deprecated_info`, `is_superseded`/`get_superseded_info`, `has_deprecated_params`/`get_deprecated_param_info`) -- the same machinery Dagster's own deprecation warnings are built from, not a hand-maintained list that would drift from the real package.

## Safety

Read-only: every check is introspection against the installed package plus AST parsing of text handed to it -- no file I/O, no network call, no code execution. `allow` is a hard allow-list; `max_result_chars` bounds every result (a large batched scan can otherwise be sizable).
