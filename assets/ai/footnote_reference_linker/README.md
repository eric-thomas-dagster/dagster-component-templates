# FootnoteReferenceLinkerComponent

Detects footnotes on each page of a PDF -- a marker (a number, symbol such as `*`, `†`, `‡`, or a bracketed number like `[12]`) plus its explanatory footnote text -- and links each one back to the exact short snippet of body text its marker appears after, so a reviewer (or a downstream UI) can jump from body text to its footnote. Useful for academic papers, financial reports, legal agreements, and diligence materials, where a footnote can change the meaning of the body text it attaches to.

Mechanism: page text is extracted via `pdfplumber` (same library used by `pdf_text_extractor` and `structured_document_extractor`), then ONE `litellm` call PER PAGE asks the model to identify every footnote on that page and the exact verbatim body-text snippet its marker appears immediately after. Output explodes one upstream row into one row per footnote-reference pair (same "explode" shape `document_chunker` and `document_section_splitter` use).

**Honesty note**: footnote detection from raw extracted text alone is NOT reliably deterministic -- there is no visual/layout signal available here (font size, vertical position on the page, superscript rendering) the way a human reviewer or a layout-aware OCR model would see it. Detection quality is model-dependent, not guaranteed complete or correct.

**Body-reference bounding box**: once the model names a `body_reference_snippet`, this component calls pdfplumber's own `page.extract_words()` directly and matches the snippet against a contiguous run of words -- case-insensitive, whitespace-normalized, exact/near-exact substring match only, no fuzzy/embedding matching. When the snippet doesn't match closely enough, the row is still emitted (marker and footnote_text are still useful without a bbox) with `body_reference_bbox` left `null` -- a bbox is never fabricated for a failed match.

## Output columns

- Passthrough columns (configurable via `passthrough_columns`; defaults to every upstream column except `column`)
- `page_number` -- 1-based page number the footnote was found on
- `marker` -- the footnote marker text (e.g. `"3"`, `"*"`, `"[12]"`)
- `footnote_text` -- the footnote's own explanatory text
- `body_reference_snippet` -- the short verbatim body-text snippet the marker appeared after
- `body_reference_bbox` -- JSON string of `{"x0", "x1", "top", "bottom"}` (PDF page coordinates), or `null` when the snippet couldn't be located as a contiguous run of words
