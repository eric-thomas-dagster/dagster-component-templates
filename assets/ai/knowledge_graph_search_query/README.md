# KnowledgeGraphSearchQueryComponent

A graph-only mirror of [`hybrid_knowledge_search_query`](../hybrid_knowledge_search_query/README.md),
for testing a knowledge graph built by `knowledge_graph_builder` from a run
**without configuring any vector-store settings at all**.

One asset per materialization: fuzzy-matches an entity name via an
already-registered `KnowledgeGraphSearchResource`'s `search_entities()`, then
expands its neighborhood via `get_neighbors(entity, hops, relation)` -- both
reported as run metadata.

Requires a `KnowledgeGraphSearchServerComponent` already registered under
`graph_resource_key` in the same code location. This component only
references that resource via Dagster's own resource-injection
(`required_resource_keys`) -- it has no graph-store client code of its own.

## Launchpad run config

Every static field (`entity`/`entity_type`/`hops`/`relation`) can be
overridden per run via `KnowledgeGraphSearchQueryRunConfig`:

```yaml
ops:
  support_kg_ask:
    config:
      entity: "Acme Corp"
      hops: 2
```

`entity` must be set either statically on the component or via this run
config for every run -- a run with neither fails clearly.

## Run metadata

The asset reports `entities_matched` (JSON, `search_entities`'s raw hits),
`query_entity` (what was searched for) and `resolved_entity` (the matched
entity name `get_neighbors` actually expanded -- the first fuzzy match, or
the raw query term itself when nothing matched), `neighbors` (JSON,
`get_neighbors`'s raw hits), and `neighbor_error` (non-empty when
`resolved_entity` wasn't found in the graph at all).

## Example YAML

```yaml
type: dagster_community_components.KnowledgeGraphSearchQueryComponent
attributes:
  asset_name: support_kg_ask
  graph_resource_key: support_kg_search
  entity: "Acme Corp"
  hops: 2
```
