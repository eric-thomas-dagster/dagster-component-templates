# Mammouth LLM

Per-row LLM inference via [Mammouth AI](https://mammouth.ai) (mammouth.ai) — a real, OpenAI-compatible multi-model-routing API. One API key, one endpoint (`POST https://api.mammouth.ai/v1/chat/completions`), and the underlying model is selected simply by passing its name straight through in `model`. Drop-in peer of `openai_llm` / `anthropic_llm` / `gemini_llm` / `groq_llm` / `openrouter_llm`.

```yaml
type: dagster_component_templates.MammouthLLMComponent
attributes:
  asset_name: support_ticket_summaries
  upstream_asset_key: support_tickets
  api_key_env_var: MAMMOUTH_API_KEY
  text_model: mammouth-recommended
  system_prompt: "Summarize the customer's issue in one sentence."
  input_column: ticket_body
  output_column: ticket_summary
```

## Model routing

Mammouth's whole differentiator versus a single-vendor native component (`openai_llm`, `anthropic_llm`, `gemini_llm`, ...) is that one key and one endpoint route to many underlying models -- just pass the model name straight through in `text_model`:

| `text_model` value | Routes to |
|---|---|
| `mammouth-recommended` (default) | Whatever model Mammouth currently considers best for its price -- Mammouth manages this pointer, not you |
| `gpt-5.4` | OpenAI |
| `claude-opus-5-5` | Anthropic |
| `gemini-3.8-flash` | Google |
| `mistral-medium-3-5` | Mistral |

This is the same "pass the vendor's own model id straight through, no per-provider SDK" shape as `openrouter_llm` -- unlike OpenRouter's `<provider>/<model>` slash-namespaced ids, Mammouth takes the bare underlying model name.

## Verified against primary docs

Confirmed via `https://info.mammouth.ai/docs/api-quick-start/` (fetched while building this component):

- Base URL: `https://api.mammouth.ai/v1`
- Auth: `Authorization: Bearer <API_KEY>` -- get a key at `https://mammouth.ai/app/account/settings/api`
- `POST /v1/chat/completions` is the standard OpenAI Chat Completions wire shape: request `model` / `messages` (`role`, `content`) / `temperature` / `max_tokens` / `top_p` / `stream`; response `choices[0].message.content` + `usage` (`prompt_tokens`, `completion_tokens`, `total_tokens`)
- Rate limit exceeded returns HTTP `429`
- Usage/cost check: `GET https://api.mammouth.ai/key/info`

Because the wire format is fully OpenAI-compatible, this component uses the stock `openai` Python client with just a base URL + API key swap, exactly like `openrouter_llm` and `perplexity_llm`.

## When to pick Mammouth vs other LLM components

| Provider | Best for |
|---|---|
| **`mammouth_llm`** | Simple multi-model routing with bare underlying model names + a "best model for the price" auto-pick alias |
| `openrouter_llm` | One key for 100+ models across all providers, provider-routing controls, leaderboard attribution |
| `openai_llm` | gpt-5.4, structured outputs, broad ecosystem |
| `anthropic_llm` | Claude (long context, prompt caching) |
| `gemini_llm` | Free Gemini quota, multimodal |
| `groq_llm` | Lowest latency, large batch jobs on a budget |
| `mistral_llm` | EU-hosted workloads, open-weights lineage, Codestral for code |
| `perplexity_llm` | Real-time web-grounded answers with citations |
| `litellm_inference_asset` | Local (non-gateway) multi-vendor routing, fallback, comparison |

## Sister components

- `openai_llm`, `anthropic_llm`, `gemini_llm`, `groq_llm`, `mistral_llm`, `perplexity_llm` -- native single-vendor peers.
- `openrouter_llm` -- the other multi-vendor-routing gateway in this repo; same architecture (one key, one OpenAI-compatible endpoint, bare model id passthrough), different routing surface (slash-namespaced ids + provider-preference controls vs Mammouth's bare ids + a managed "recommended" alias).
- `litellm_inference_asset` -- generic local multi-vendor router (no hosted gateway).
