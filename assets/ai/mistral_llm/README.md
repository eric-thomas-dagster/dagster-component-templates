# Mistral LLM

Native Mistral AI LLM inference via Mistral's OpenAI-compatible API. Drop-in peer of `openai_llm` / `anthropic_llm` / `gemini_llm` / `groq_llm`.

Mistral's API is wire-compatible with OpenAI's Chat Completions format at `POST https://api.mistral.ai/v1/chat/completions`: the same `choices[].message.content` / `usage` response shape. Swap in a Mistral API key and model name and the standard `openai` Python client works unchanged — no dedicated resource needed.

```yaml
type: dagster_component_templates.MistralLLMComponent
attributes:
  asset_name: ticket_summaries
  upstream_asset_key: support_tickets
  api_key_env_var: MISTRAL_API_KEY
  text_model: mistral-large-latest
  system_prompt: "You are a customer-support analyst. One sentence, under 20 words."
  input_column: ticket_text
  output_column: summary
```

## Common Mistral models

| Model | Strength |
|---|---|
| `mistral-large-latest` (default) | Flagship, best general-purpose reasoning |
| `mistral-medium-latest` | Balanced cost/quality |
| `mistral-small-latest` | Fast, cheap, good for simple extraction/classification |
| `open-mistral-nemo` | Open-weights, 128K context |
| `codestral-latest` | Code generation / completion, large context |
| `ministral-8b-latest` / `ministral-3b-latest` | Edge / on-device sized models |

`-latest` aliases always resolve to Mistral's current release in that tier, so this component doesn't need to track exact dated model ids. Full list: https://docs.mistral.ai/getting-started/models/

## When to pick Mistral vs other native LLM components

| Provider | Best for |
|---|---|
| **`mistral_llm`** | EU-hosted/GDPR-sensitive workloads, strong open-weights lineage, Codestral for code tasks |
| `groq_llm` | Lowest latency (500+ tok/s), large batch jobs on a budget |
| `openai_llm` | gpt-4o, structured outputs, broad ecosystem |
| `anthropic_llm` | Claude (long context, prompt caching) |
| `gemini_llm` | Free Gemini quota, multimodal |
| `perplexity_llm` | Web-grounded answers with citations |
| `openrouter_llm` | One key for 100+ models across all providers |
| `litellm_inference_asset` | Multi-vendor routing, fallback, comparison |

## Sister components

- `openai_llm`, `anthropic_llm`, `gemini_llm`, `groq_llm`, `openrouter_llm`, `perplexity_llm` — native peers.
- `litellm_inference_asset` — generic multi-vendor router.
- `litellm_structured_output` — JSON-mode wrapper; works with Mistral via `litellm` too.
