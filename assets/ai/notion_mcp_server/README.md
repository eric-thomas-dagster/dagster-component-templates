# NotionMcpServer

Live Notion search/fetch for a chat agent, via Notion's **hosted MCP server** — the same
OAuth-as-the-signed-in-person approach as
[`notion_mcp_documents`](../../ingestion/notion_mcp_documents/README.md) (see that component's
README for sign-in and the full rate-limiting story), but for live lookups from an agent instead
of a batch extraction asset.

## Sign in first

```
python -m dagster_community_components.resources.notion_mcp_login --oauth-dir ~/.notion_mcp
```

Same sign-in CLI, same `oauth_dir` — both components can point at the same directory.

## Why a local proxy instead of pointing `mcp_server_resource` at Notion directly

[`mcp_server_resource`](../../../resources/mcp_server_resource/README.md)'s `http` transport
sends a **static** `Authorization` header, read once at call time from an env var —
fine for a token that never expires, wrong here: Notion's access token lives ~8h and needs
refreshing through a stored, file-locked, auto-rotating refresh token. This component instead
ships a small **local stdio MCP server** (`python -m <this module>`, same shape as
[`report_tools_server`](../report_tools_server/README.md)) that, on every tool call, refreshes
the token if needed and proxies the call to Notion's real hosted server — the agent framework
never sees a token at all, just a normal stdio MCP server exposing `notion-search`/`notion-fetch`.

```yaml
type: dagster_community_components.NotionMcpServerComponent
attributes:
  resource_key: notion_mcp
  oauth_dir: /home/dagster/.notion_mcp
  max_requests_per_second: 2
```

Then, in any MCP-aware component (anthropic_agent / openai_agent / litellm_agent / gemini_agent /
agentic_pipeline) instead of an inline `server:` spec:

```yaml
server_resource_key: notion_mcp
```

## `allow`

Restrict to one tool, e.g. read-only search with no page-content fetch:

```yaml
allow:
  - notion-search
```

Default: both `notion-search` and `notion-fetch`. This server never exposes Notion's write tools
(`notion-create-pages`, `notion-update-page`, `notion-delete-pages`, …) — only the two named here
are proxied at all, regardless of `allow`.

## Rate limiting

Same mechanism as `notion_mcp_documents`: one `NotionMcpRateLimiter` per server process (shared
across every concurrent tool call the agent makes, not per call), and Notion's own text-based
rate-limit signal (never HTTP 429) is detected and retried internally, never surfaced to the
agent as page content.
