# Perplexity LLM

Native Perplexity (Sonar) web-grounded LLM inference via Perplexity's OpenAI-compatible API. Drop-in peer of `openai_llm` / `anthropic_llm` / `gemini_llm` / `groq_llm` / `mistral_llm`.

Perplexity's wire format follows the standard `choices[].message.content` / `usage` shape at `POST https://api.perplexity.ai/chat/completions`, so the stock `openai` Python client works unchanged with just a base URL + API key swap — **but** Perplexity's whole reason to exist versus every other native LLM component in this repo is that its "Sonar" model family is **web-grounded**: every answer comes back with real-time citations to the pages it searched. This component surfaces those citations instead of discarding them, as:

- an extra `citations_column` (default `perplexity_citations`) — a list of source URLs per row
- optionally a `<citations_column>_detail` column with the fuller `search_results` payload (title/url/date/snippet) when `include_search_results: true`
- materialization metadata: `total_citations` across the batch, and a sample of any `related_questions` Perplexity suggested

```yaml
type: dagster_component_templates.PerplexityLLMComponent
attributes:
  asset_name: company_research_briefs
  upstream_asset_key: target_companies
  api_key_env_var: PERPLEXITY_API_KEY
  text_model: sonar-pro
  system_prompt: "You are a market research analyst. Answer in 3 sentences, citing the most recent facts you can find."
  input_column: company_name
  output_column: research_brief
  citations_column: research_sources
  search_recency_filter: month
```

## Citations: verified response shape

Per Perplexity's own API reference (`docs.perplexity.ai/api-reference/chat-completions-post`), the chat completion response carries two Perplexity-specific fields that are **not** part of OpenAI's own schema:

- `citations` — a top-level array of source URL strings
- `search_results` — a top-level array of `{title, url, date, snippet, source}` objects

This component reads `resp.citations` / `resp.search_results` off the raw `openai` client response (its models permit unrecognized fields through, which is how these pass-through). As a defensive fallback — some third-party write-ups show citations nested at `choice.message.citations` instead — `_extract_citations()` checks both locations before giving up, so a row never crashes just because a particular account/model variant shapes the field differently; it just comes back with an empty citations list for that row.

## Perplexity-specific request parameters

| Field | Effect |
|---|---|
| `search_domain_filter` | Allowlist domains, or denylist with a `-` prefix (e.g. `-reddit.com`). Max 20 entries. |
| `search_recency_filter` | Restrict sources to `day` / `week` / `month` / `year`. |
| `return_related_questions` | Ask Perplexity to also suggest follow-up questions (surfaced in metadata, not per row). |

## Common Perplexity models

| Model | Strength |
|---|---|
| `sonar` (default) | Fast, cheap, web-grounded Q&A |
| `sonar-pro` | Deeper search, more citations per answer |
| `sonar-reasoning` / `sonar-reasoning-pro` | Chain-of-thought reasoning + search |
| `sonar-deep-research` | Exhaustive multi-step research reports |

Full list: https://docs.perplexity.ai/models/model-cards

## ⚠️ API migration in flight (verified via WebSearch, Oct 2026)

While verifying this component against primary docs, multiple independent sources (Perplexity's own changelog/blog, and third-party migration write-ups) consistently indicate Perplexity is **retiring the classic Sonar Chat Completions endpoint used here (`/chat/completions`) around September 27, 2026**, in favor of a new **Agent API** (`/v1/agent`, later folded into a "Router API") with a materially different request/response shape (`input`/`preset` instead of `messages`/`model`, `output_text` instead of `choices[].message.content`, citations as inline `[n]` markers mapped to a `search_results` output item rather than a flat `citations` array).

This component is built to the classic, still-documented, OpenAI-wire-compatible shape — matching this repo's `groq_llm`/`mistral_llm`/`openai_llm` convention and the task this was built against — because sources conflicted on whether the old endpoint hard-fails post-cutover or is gateway-translated transparently ("no action required" per one source). **If calls against `https://api.perplexity.ai/chat/completions` start failing in production, that migration is almost certainly why** — this would need a follow-up port to whatever endpoint/shape Perplexity's Agent or Router API has settled into by then.

## When to pick Perplexity vs other native LLM components

| Provider | Best for |
|---|---|
| **`perplexity_llm`** | Answers that need real-time web grounding + citations (news, current events, fact-checking) |
| `groq_llm` | Lowest latency, large batch jobs on a budget |
| `mistral_llm` | EU-hosted workloads, open-weights lineage, Codestral for code |
| `openai_llm` | gpt-4o, structured outputs, broad ecosystem |
| `anthropic_llm` | Claude (long context, prompt caching) |
| `gemini_llm` | Free Gemini quota, multimodal |
| `openrouter_llm` | One key for 100+ models across all providers |
| `litellm_inference_asset` | Multi-vendor routing, fallback, comparison |
| `rag_grounding_check` | Grounding/faithfulness checks against *your own* retrieved context, not the open web |

## Sister components

- `openai_llm`, `anthropic_llm`, `gemini_llm`, `groq_llm`, `mistral_llm`, `openrouter_llm` — native peers.
- `litellm_inference_asset` — generic multi-vendor router.
- `rag_grounding_check` — faithfulness/hallucination checks for RAG pipelines over your own corpus (complementary, not overlapping: that component checks groundedness against retrieved docs you supply, this one grounds against the live web).
