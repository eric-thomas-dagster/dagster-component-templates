# ChromadbAssetComponent

Take documents from an upstream DataFrame asset, generate embeddings via the OpenAI Embeddings API, and upsert them into a [ChromaDB](https://www.trychroma.com) collection — all as an observable Dagster asset.

## Use case

In a RAG or semantic-search pipeline:

1. Source text lives in an upstream asset (e.g. a table loaded from PostgreSQL, MySQL, SQLite, etc.) that yields a DataFrame.
2. `ChromadbAssetComponent` reads that DataFrame, calls OpenAI to embed it, and upserts documents into a ChromaDB collection.
3. Downstream retrieval assets or applications query the collection for nearest-neighbour similarity.

## Prerequisites

```bash
pip install chromadb openai sqlalchemy
```

ChromaDB must be running and reachable (or use Chroma Cloud with `chroma_api_key_env_var`).

## Example YAML
```yaml
type: dagster_component_templates.ChromadbAssetComponent
attributes:
  asset_name: product_chroma_collection
  chroma_host: localhost
  chroma_port: 8000
  collection_name: products
  upstream_asset_key: products
  id_column: product_id
  text_column: description
  metadata_columns:
    - name
    - category
    - price
  embedding_model: text-embedding-3-small
  openai_api_key_env_var: OPENAI_API_KEY
  batch_size: 100
  group_name: vector_store
  deps:
    - raw/products
```

## Chroma Cloud

For Chroma Cloud, provide the cloud endpoint as `chroma_host` and set `chroma_api_key_env_var`:

```yaml
chroma_host: api.trychroma.com
chroma_port: 443
chroma_api_key_env_var: CHROMA_API_KEY
```

## Metadata Filtering

Storing extra columns as metadata enables filtered similarity search:

```yaml
metadata_columns:
  - category
  - brand
  - price_tier
```

In your retrieval application:

```python
collection.query(
    query_embeddings=[my_vector],
    n_results=10,
    where={"category": "electronics"},
)
```

Metadata values are cast to `str` if they are not a native ChromaDB type (`str`, `int`, `float`, `bool`).

### Reading from a database instead of an upstream asset

Instead of `upstream_asset_key`, set `source` to run a SQL query and feed its rows straight into this component -- no intermediate asset required. Set exactly one of `upstream_asset_key` or `source` (setting both or neither raises a `ValueError` at load time).

`source` is `{kind: warehouse_query, sql: <query>, resource_key: <registered resource> OR database_url_env_var: <env var>}`. `resource_key` names a Dagster resource exposing `.get_engine()`, `.get_connection()` or `.get_client()` (Postgres, Snowflake, DuckDB, BigQuery, Redshift, ...); `database_url_env_var` names an env var holding a SQLAlchemy URL.

```yaml
type: dagster_component_templates.ChromadbAssetComponent
attributes:
  asset_name: product_chroma_collection
  collection_name: products
  id_column: id
  text_column: body
  source:
    kind: warehouse_query
    database_url_env_var: WAREHOUSE_URL
    sql: "SELECT id, body FROM support.tickets WHERE created_at > current_date - 7"
```

Results stay a DataFrame (this adds no database write-back); compose with a sink component to persist them.

## Partitioning

When `partition_type` is set, each run reads only the upstream rows that fall in its partition (by `partition_date_column` / `partition_static_column`); unpartitioned runs read everything.
