# GeoIP Database Updater Component

Downloads and refreshes local MaxMind GeoLite2/GeoIP2 `.mmdb` database files on a schedule, skipping the download when the build hasn't changed.

## Purpose

The `GeoIpDatabaseUpdaterComponent` maintains one or more MaxMind `.mmdb` database files in a local directory. On every materialization it checks each configured edition's current build against MaxMind's metadata endpoint (by MD5), downloads and atomically replaces the file only when the build has actually changed, and verifies the extracted file's hash against what the server advertised before accepting it. Pair this with a `CronScheduleComponent` targeting its asset for a recurring refresh — it does not schedule itself.

## Licensing — read this before using

MaxMind GeoLite2 databases require a **free MaxMind account and EULA acceptance** (required for every download since 2019-12-30); GeoIP2 databases (the "ASN"/"City"/"Country"/"ISP" paid tier) require a **paid MaxMind subscription**. This component:

- Does **not** bundle, mirror, or redistribute any MaxMind database.
- Does **not** create a MaxMind account for you, or download anything until you supply `account_id_env_var`/`license_key_env_var` pointing at your own credentials.
- Only downloads editions you ask for, and only succeeds if your account is entitled to them.

You are responsible for holding a valid MaxMind account/license for every `editions` entry you configure.

## How the skip-if-unchanged check works

1. `GET {host}/geoip/updates/metadata?edition_id=...` (HTTP Basic Auth with `account_id`/`license_key`) returns the edition's current build date and MD5.
2. The local `.mmdb` file (if any) is hashed with MD5. If it matches the server's MD5, nothing is downloaded this tick.
3. If it differs (or the file doesn't exist yet), `GET {host}/geoip/databases/{edition_id}/download?date=...&suffix=tar.gz` streams the archive, the single `.mmdb` member is extracted while hashing it, and the extracted hash is checked against the server's advertised MD5 before the file is atomically renamed into place. A mismatch raises instead of writing a possibly-corrupt file.

This mirrors the protocol MaxMind's own `geoipupdate` tool (and its Python reimplementation, `pygeoipupdate`) use — both were read directly to verify this exact endpoint/auth/response shape, but neither is a dependency of this component: this is an independent, synchronous implementation using only `requests`, so it doesn't pull in `pygeoipupdate`'s async stack or its Python ≥3.11 requirement (stricter than this registry's ≥3.10 support).

## Recommended schedule

MaxMind typically rebuilds GeoLite2 databases Tuesdays and Fridays. Pair this component with `CronScheduleComponent`:

```yaml
# this component
type: dagster_community_components.GeoIpDatabaseUpdaterComponent
attributes:
  asset_name: geoip_databases
  editions: [GeoLite2-City, GeoLite2-ASN]
  database_directory: /var/lib/geoip
```

```yaml
# a separate defs.yaml pairing a schedule to it
type: dagster_community_components.CronScheduleComponent
attributes:
  schedule_name: refresh_geoip_databases
  cron_schedule: "0 6 * * 2,5"
  asset_keys: [geoip_databases]
```

## Using the result

Point `GeoIpLookupComponent`'s `database_path`/`asn_database_path` at `{database_directory}/{edition_id}.mmdb` for the editions this component maintains.

## Notes

- `editions` entries must be MaxMind's exact edition IDs (`GeoLite2-City`, `GeoLite2-Country`, `GeoLite2-ASN`, or the paid `GeoIP2-*` equivalents) — invalid characters are rejected before any request is made.
- A 401 from MaxMind raises a clear "check your credentials" error rather than a raw HTTP exception.
- `database_directory` is created if missing; files are written atomically (temp file + `os.replace`) so a crash mid-download never leaves a half-written `.mmdb` in place.
