# GeoIP Lookup Component

Enrich a DataFrame with geolocation data (city, country, lat/lng, postal code, subdivision, ASN) looked up from an IP address column.

## Purpose

The `GeoIpLookupComponent` iterates over an IP address column in a DataFrame and resolves each address to geolocation fields, either from a local MaxMind `.mmdb` database file (`lookup_mode: database`, the default — fast, no per-row network call) or MaxMind's hosted GeoIP2 web service (`lookup_mode: web_service` — no local file to maintain, but one network call per row). Both IPv4 and IPv6 addresses are supported natively by the MaxMind format and web service; no separate configuration is needed for IPv6.

## Licensing — read this before using `database` mode

MaxMind GeoLite2/GeoIP2 `.mmdb` files require a MaxMind account and license (free for GeoLite2 since account/EULA acceptance became mandatory on 2019-12-30; paid for GeoIP2). **This component does not bundle, redistribute, or auto-download that database.** In `database` mode you must:

1. Already hold a MaxMind account/license entitling you to the edition(s) you point `database_path`/`asn_database_path` at.
2. Have a plan for keeping that file refreshed — either `GeoIpDatabaseUpdaterComponent` in this same registry, MaxMind's own `geoipupdate` tool, or your own process.

If you'd rather not manage a local file at all, set `lookup_mode: web_service` — MaxMind holds and serves the data per request instead, using the same `account_id_env_var`/`license_key_env_var` credentials. Web-service mode does not support ASN enrichment (MaxMind's hosted service has no ASN endpoint); use `database` mode with `asn_database_path` for that.

## Lookup behavior — explicitly defined, not a silent crash or silent wrong answer

Every row resolves to exactly one of three statuses (visible via the optional `match_status_column`, and always counted in the asset's `rows_matched` / `rows_unmatched_not_found` / `rows_unmatched_invalid` metadata):

| Status | When | Output columns |
|---|---|---|
| `matched` | A real database/service entry was found | populated |
| `not_found` | A syntactically valid IP with no entry in the database — this is where private/reserved/unallocated ranges (RFC 1918, loopback, link-local, etc.) land, since MaxMind's databases don't carry entries for them | `null` |
| `invalid` | The string in `ip_column` isn't a parseable IPv4/IPv6 address | `null`, logged as a warning |

## ASN is a separate MaxMind database from City/Country

MaxMind ships ASN (`GeoLite2-ASN` / `GeoIP2-ASN`) as its own edition, independent of the City/Country database. Set `asn_database_path` to a *second* `.mmdb` file to populate `asn_column`/`asn_org_column` — pointing `database_path` at a City file does not give you ASN data.

## Use Cases

- **Web log enrichment**: add city/country/ASN to raw access logs for analytics or fraud signals
- **Fraud/abuse heuristics**: flag traffic by subdivision, ASN, or ASN organization
- **Content localization**: route or tag records by resolved country/subdivision
- **Network analytics**: attribute traffic to the originating network (ASN)

## Configuration

### Local database (recommended default)

```yaml
type: dagster_community_components.GeoIpLookupComponent
attributes:
  asset_name: enriched_web_logs
  upstream_asset_key: web_logs
  ip_column: client_ip
  database_path: /var/lib/geoip/GeoLite2-City.mmdb
  asn_database_path: /var/lib/geoip/GeoLite2-ASN.mmdb
  asn_column: geoip_asn
  asn_org_column: geoip_asn_org
```

### MaxMind web service (no local file to maintain)

```yaml
type: dagster_community_components.GeoIpLookupComponent
attributes:
  asset_name: enriched_web_logs
  upstream_asset_key: web_logs
  ip_column: client_ip
  lookup_mode: web_service
  account_id_env_var: MAXMIND_ACCOUNT_ID
  license_key_env_var: MAXMIND_LICENSE_KEY
  batch_delay: 0.05
```

## Notes

- `database` mode opens the `.mmdb` file(s) once per asset run and closes them when done — no per-row file handle churn.
- `web_service` mode makes one HTTPS call per row; use `batch_delay` to stay under MaxMind's rate limits for large batches.
- Both modes raise a clear error up front if required credentials/paths are missing, rather than failing on the first row.
