# gradient_boosting_model

Fit a gradient boosting model for classification or regression using scikit-learn's `GradientBoostingClassifier` or `GradientBoostingRegressor`. Evaluation metrics are logged to Dagster asset metadata. Output can be predictions appended to the original DataFrame or a ranked feature importance table.

## Ingestion

Two ways to get the rows in, set exactly one:

- **`upstream_asset_key`**: the usual Dagster way -- point at any asset producing a DataFrame with `feature_columns`/`target_column`.
- **`source: {kind: warehouse_query, resource_key: ..., sql: ...}`**: pull rows directly via SQL, no upstream asset required. Works out of the box with `duckdb_resource` and any resource exposing `.get_engine()`/`.get_connection()`, or a bare SQLAlchemy connection string via `database_url_env_var` when no Dagster resource is registered.

## `execution_mode: sql` -- train (or predict) server-side

Same 3-dialect asymmetry as `logistic_regression_model`:

- **`bigquery`**: real train-and-predict-in-SQL, and a genuine algorithmic match for BOTH task types -- `CREATE MODEL ... OPTIONS(model_type='BOOSTED_TREE_CLASSIFIER'|'BOOSTED_TREE_REGRESSOR')` (BigQuery's boosted-tree model is gradient boosting, via XGBoost under the hood) + `ML.PREDICT`.
- **`snowflake`**: `CREATE SNOWFLAKE.ML.CLASSIFICATION` -- **classification only**, no regression function exists in Snowflake ML. `task_type: regression` + `sql_dialect: snowflake` raises a clear error rather than silently producing something wrong; use `sql_dialect: bigquery` for regression instead.
- **`databricks`**: **predict-only.** No `CREATE MODEL` statement exists on Databricks at all. `model_name` must be an already-served Model Serving endpoint; the generated SQL calls `ai_query(endpoint, named_struct(...))` against it and trains nothing.

`execution_mode: sql` only supports `output_mode: predictions` -- there's no server-side equivalent to the sklearn `feature_importances_` output.

```yaml
type: dagster_component_templates.GradientBoostingModelComponent
attributes:
  asset_name: churn_gbm_sql
  source:
    kind: warehouse_query
    resource_key: bigquery_resource
    sql: "SELECT * FROM raw.customers"
  execution_mode: sql
  sql_dialect: bigquery
  output_table: analytics.churn_gbm_predictions
  model_name: analytics.churn_gbm_model
  target_column: churned
  feature_columns: [days_since_last_order, total_orders, avg_order_value]
  task_type: classification
```

## Output Modes

- **`predictions`**: Returns the original DataFrame with a `predicted` column appended.
- **`feature_importance`**: Returns a DataFrame with `feature` and `importance` columns sorted descending.

## Example YAML

```yaml
component_type: gradient_boosting_model
description: Predict customer churn using gradient boosting classification.

asset_name: churn_gbm_predictions
upstream_asset_key: customer_features_enriched
target_column: churned
feature_columns:
  - days_since_last_order
  - total_orders
task_type: classification
n_estimators: 200
learning_rate: 0.05
output_mode: predictions
group_name: churn_models
```
