# logistic_regression_model

Fit a logistic regression classifier and append predicted class labels and/or per-class probability columns to the output DataFrame. Accuracy and a full classification report are logged to Dagster asset metadata from the held-out test split.

## Ingestion

Two ways to get the rows in, set exactly one:

- **`upstream_asset_key`**: the usual Dagster way -- point at any asset producing a DataFrame with `feature_columns`/`target_column`.
- **`source: {kind: warehouse_query, resource_key: ..., sql: ...}`**: pull rows directly via SQL, no upstream asset required. Works out of the box with `duckdb_resource` and any resource exposing `.get_engine()`/`.get_connection()`, or a bare SQLAlchemy connection string via `database_url_env_var` when no Dagster resource is registered.

## `execution_mode: sql` -- train (or predict) server-side

Unlike `anomaly_detection`'s portable-statistics SQL mode, fitting a classifier genuinely needs a warehouse-native ML surface, and the three supported dialects differ in a way worth knowing rather than papering over:

- **`bigquery`**: real train-and-predict-in-SQL. `CREATE MODEL ... OPTIONS(model_type='LOGISTIC_REG')` trains, `ML.PREDICT` reads it back.
- **`snowflake`**: also real train-and-predict, via `CREATE SNOWFLAKE.ML.CLASSIFICATION` (same task, not literally logistic regression internally) and `model!PREDICT(...)`. Its `INPUT_DATA => SYSTEM$REFERENCE(...)` requires an actual table/view name, not an inline subquery, so this component creates a view from `source.sql` first.
- **`databricks`**: **predict-only.** There is no `CREATE MODEL` statement on Databricks at all -- training only happens via AutoML or notebooks in Python. `model_name` must be the name of an **already-registered/served** Model Serving endpoint; the generated SQL calls `ai_query(endpoint, named_struct(...))` against it, and trains nothing.

```yaml
type: dagster_component_templates.LogisticRegressionModelComponent
attributes:
  asset_name: churn_predictions_sql
  source:
    kind: warehouse_query
    resource_key: bigquery_resource
    sql: "SELECT * FROM raw.customers"
  execution_mode: sql
  sql_dialect: bigquery
  output_table: analytics.churn_predictions
  model_name: analytics.churn_model
  target_column: churned
  feature_columns: [tenure_months, monthly_spend, support_tickets]
```

Requires `source`, `sql_dialect`, `output_table`, `model_name`, and `feature_columns`.

## Output Columns

- `predicted_class` — predicted label (when `output_predictions: true`)
- `predicted_proba_<label>` — probability per class (when `output_probabilities: true`)

## Example YAML

```yaml
component_type: logistic_regression_model
description: Classify customer churn risk from behavioral features.

asset_name: churn_predictions
upstream_asset_key: customer_features_clean
target_column: churned
feature_columns:
  - days_since_last_login
  - total_orders
  - avg_order_value
  - support_tickets_30d
output_predictions: true
output_probabilities: true
normalize: true
group_name: churn_models
```

- `accuracy` — Classification accuracy on test split
- `classification_report` — Full precision/recall/F1 report
