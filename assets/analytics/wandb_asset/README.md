# Weights & Biases Asset Component

Logs metrics from an upstream asset's DataFrame or uploads file/directory artifacts to [Weights & Biases](https://wandb.ai), creating a tracked W&B run for every Dagster materialization.

---

## What it does

Supports two modes, selected by the `mode` field:

| Mode | Description |
|------|-------------|
| `log_metrics` | Reads rows from the upstream asset's DataFrame (`upstream_asset_key`) and logs each row as a step in a W&B run using `run.log({...})`. |
| `log_artifact` | Uploads a local file or directory as a W&B artifact using `wandb.Artifact` and `run.log_artifact(...)`. |

---

## Required packages

| Package | Minimum version | Purpose |
|---------|----------------|---------|
| `dagster` | 1.8.0 | Orchestration framework |
| `wandb` | 0.17.0 | W&B Python SDK |

Install with:

```bash
pip install wandb>=0.17.0
```

You will also need the appropriate SQLAlchemy dialect driver for your source database (e.g. `psycopg2` for PostgreSQL, `pymysql` for MySQL).

## Example YAML

### Log metrics from a training table

```yaml
type: dagster_component_templates.WandbAssetComponent
attributes:
  asset_name: model_training_run
  project: churn-prediction
  entity: my-team
  mode: log_metrics
  wandb_api_key_env_var: WANDB_API_KEY
  upstream_asset_key: model_training_results
  metrics_columns:
    - train_loss
    - val_loss
    - accuracy
  step_column: epoch
  tags:
    - production
    - v2
  group_name: ml_tracking
  deps:
    - marts/training_data
```

### Upload a model checkpoint

```yaml
type: dagster_component_templates.WandbAssetComponent
attributes:
  asset_name: model_checkpoint_upload
  project: churn-prediction
  entity: my-team
  mode: log_artifact
  wandb_api_key_env_var: WANDB_API_KEY
  artifact_path: /tmp/checkpoints/epoch_50
  artifact_name: churn_model_epoch50
  artifact_type: model
  tags:
    - checkpoint
  group_name: ml_tracking
```

## Materialization metadata

Each run emits the following metadata visible in the Dagster UI:

| Key | Description |
|-----|-------------|
| `run_id` | W&B run ID |
| `project` | W&B project name |
| `run_url` | Direct link to the W&B run page |
| `mode` | The mode used (`log_metrics` or `log_artifact`) |

### Reading from a database instead of an upstream asset

Instead of `upstream_asset_key`, set `source` to run a SQL query and feed its rows straight into this component -- no intermediate asset required. Set exactly one of `upstream_asset_key` or `source` (setting both or neither raises a `ValueError` at load time).

`source` is `{kind: warehouse_query, sql: <query>, resource_key: <registered resource> OR database_url_env_var: <env var>}`. `resource_key` names a Dagster resource exposing `.get_engine()`, `.get_connection()` or `.get_client()` (Postgres, Snowflake, DuckDB, BigQuery, Redshift, ...); `database_url_env_var` names an env var holding a SQLAlchemy URL.

`source` is only valid in `mode: log_metrics` (the DataFrame-input mode); `log_artifact` takes no DataFrame input.

```yaml
type: dagster_component_templates.WandbAssetComponent
attributes:
  asset_name: model_training_run
  mode: log_metrics
  project: churn-prediction
  wandb_api_key_env_var: WANDB_API_KEY
  step_column: epoch
  metrics_columns: [train_loss, val_loss]
  source:
    kind: warehouse_query
    database_url_env_var: WAREHOUSE_URL
    sql: "SELECT id, body FROM support.tickets WHERE created_at > current_date - 7"
```

Results stay a DataFrame (this adds no database write-back); compose with a sink component to persist them.

## Partitioning

When `partition_type` is set, each run reads only the upstream rows that fall in its partition (by `partition_date_column` / `partition_static_column`); unpartitioned runs read everything.
