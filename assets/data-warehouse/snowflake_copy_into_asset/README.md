# Snowflake Copy Into Asset

Bulk-loads files from a Snowflake stage into a table via `COPY INTO <table> FROM <stage> ...` —
mirrors Airflow's `CopyFromExternalStageToSnowflakeOperator`.

Sibling to [`snowflake_sql_asset`](https://dagster-component-ui.vercel.app/c/snowflake_sql_asset)
(arbitrary SQL) and [`snowflake_stored_procedure_call_asset`](https://dagster-component-ui.vercel.app/c/snowflake_stored_procedure_call_asset)
(named proc call): this one is specifically for the "load staged files into a table" case, with
the real COPY INTO grammar (`FILES`/`PATTERN`/`FILE_FORMAT`/copy options) as typed fields instead
of a hand-written SQL string.

## Example

```yaml
type: dagster_community_components.SnowflakeCopyIntoAssetComponent
attributes:
  asset_key: snowflake/loads/orders
  database: DAGSTER_DEMO
  schema: RAW
  table: ORDERS
  stage: orders_stage
  stage_path: "2026/01/"
  pattern: ".*\\.csv"
  file_format_options:
    TYPE: CSV
    FIELD_DELIMITER: ","
    SKIP_HEADER: 1
  on_error: CONTINUE
  purge: true
  account_env_var: SNOWFLAKE_ACCOUNT
  user_env_var: SNOWFLAKE_USER
  password_env_var: SNOWFLAKE_PASSWORD
```

### Using a named file format object

```yaml
attributes:
  file_format_name: MY_CSV_FORMAT
```

### Explicit file list instead of a pattern

```yaml
attributes:
  files:
    - "orders_2026_01_01.csv"
    - "orders_2026_01_02.csv"
```

## Auth options

Same as `snowflake_sql_asset` / `snowflake_stored_procedure_call_asset` — password / PAT /
keypair via `*_env_var` fields, or set `resource_key` to a registered `SnowflakeResourceComponent`
(`resources/snowflake_resource`) and skip the inline fields entirely.
