# Snowflake SQL Asset

Runs one or more SQL statements against Snowflake as a Dagster asset — mirrors Airflow's
`SnowflakeOperator` / `SQLExecuteQueryOperator`.

## Relationship to `dagster.TemplatedSqlComponent`

Core Dagster already ships `dagster.TemplatedSqlComponent` (built on the `@preview`
`SqlComponent`), which can render a Jinja-templated SQL string and run it once against a
`SnowflakeResource` via `connect_and_execute()`. That covers the simple case well, and if all
you need is "one rendered statement, no parameters, no session overrides," reach for that first.

`connect_and_execute`'s real implementation is exactly:

```python
def connect_and_execute(self, sql: str) -> None:
    with self.get_connection() as conn:
        conn.cursor().execute(sql)
```

— a single SQL string, no `num_statements`, no bind parameters, no per-call session overrides.
`snowflake_sql_asset` fills in specifically what that doesn't cover:

- **Multiple statements** in one call, via Snowflake's own `cursor.execute(sql, num_statements=0)`
  auto-detection (the real, documented mechanism for running every `;`-separated statement in a
  block — not naive string splitting, which breaks on semicolons inside quoted literals or
  comments), or as an explicit `sql_statements` list.
- **Bind parameters** (`parameters:`), applied to every statement.
- **Per-run session overrides** (`session_warehouse` / `session_database` / `session_schema` /
  `session_role`), issued as `USE ...` statements before the main SQL — distinct from the
  connection-level `warehouse_env_var` / `role_env_var` used when first connecting.
- **Rowcount metadata** per statement, surfaced on the materialization.

## Example

```yaml
type: dagster_community_components.SnowflakeSqlAssetComponent
attributes:
  asset_key: snowflake/transforms/customer_rollup
  sql_statements:
    - "CREATE OR REPLACE TEMP TABLE _staging AS SELECT * FROM RAW.CUSTOMERS WHERE updated_at > CURRENT_DATE - 1"
    - "MERGE INTO ANALYTICS.CUSTOMER_ROLLUP t USING _staging s ON t.id = s.id WHEN MATCHED THEN UPDATE SET t.name = s.name WHEN NOT MATCHED THEN INSERT (id, name) VALUES (s.id, s.name)"
  session_warehouse: TRANSFORM_WH
  session_database: ANALYTICS
  account_env_var: SNOWFLAKE_ACCOUNT
  user_env_var: SNOWFLAKE_USER
  password_env_var: SNOWFLAKE_PASSWORD
```

### Single multi-statement block

```yaml
attributes:
  sql: |
    CREATE OR REPLACE TEMP TABLE _staging AS SELECT * FROM RAW.ORDERS;
    DELETE FROM ANALYTICS.ORDERS WHERE id IN (SELECT id FROM _staging);
    INSERT INTO ANALYTICS.ORDERS SELECT * FROM _staging;
```

### Bind parameters

```yaml
attributes:
  sql: "DELETE FROM ANALYTICS.EVENTS WHERE event_date < %(cutoff)s"
  parameters:
    cutoff: "2026-01-01"
```

## Auth options

Same `*_env_var` fields (password / PAT / keypair) as `snowflake_stored_procedure_call_asset` and
`snowflake_task_execute_asset`.

Alternatively, set `resource_key` to the key of a registered `SnowflakeResourceComponent`
(`resources/snowflake_resource`) and skip the inline `*_env_var` fields entirely.

## Requirements

snowflake-connector-python>=3.0.0
