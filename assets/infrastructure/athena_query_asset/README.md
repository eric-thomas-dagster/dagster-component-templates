# Athena Query Asset

Run a SQL query against Amazon Athena as a Dagster asset -- the Airflow `AthenaOperator` equivalent.

Starts the query via `start_query_execution`, polls `get_query_execution` until it reaches `SUCCEEDED`/`FAILED`/`CANCELLED`, and raises with the real `StateChangeReason` on anything but success. `query` is rendered through Jinja2 first, so `{{ partition_key }}`/`{{ partition_start }}`/`{{ partition_end }}`/`{{ partition_date }}` are available for a partitioned asset -- a plain query with no `{{ }}` syntax is unaffected.

`output_location` is optional only when `workgroup` has its own configured result location (Athena workgroups can enforce this); otherwise AWS rejects the query with no result location at all.

## Example YAML

```yaml
type: dagster_community_components.AthenaQueryAssetComponent
attributes:
  asset_name: daily_sales_rollup
  query: |
    SELECT sale_date, SUM(amount) AS total_amount
    FROM sales
    WHERE sale_date = date '{{ partition_date }}'
    GROUP BY sale_date
  database: analytics
  output_location: s3://my-bucket/athena-results/
  region_name: us-east-1
  partition_type: daily
  partition_start: '2024-01-01'
  group_name: analytics
  kinds: [aws, athena]
```

## Authentication

Uses the standard boto3 credential chain (env vars, shared config/credentials file, instance/task role). Set `aws_profile` to use a named profile instead of the default.

## Requirements

```
boto3
jinja2
```
