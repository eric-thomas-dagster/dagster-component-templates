# Dataproc Cluster Asset

Ensures a Google Cloud Dataproc cluster is present or absent -- the `DataprocCreateClusterOperator`/`DataprocDeleteClusterOperator` equivalent from Airflow's Dataproc provider.

A Dataproc cluster is long-lived infrastructure, not a batch job that completes -- materializing this asset means "ensure the cluster is in `desired_state`" (idempotent: a no-op if it's already there), mirroring this repo's `managed_flink_application_asset` convention for long-running infra. It reads the current cluster state via `get_cluster`, calls `create_cluster`/`delete_cluster` if needed, then waits for the long-running operation to complete.

## Example YAML

```yaml
type: dagster_community_components.DataprocClusterAssetComponent
attributes:
  asset_name: etl_dataproc_cluster
  project_id: my-gcp-project
  region: us-central1
  cluster_name: etl-cluster
  desired_state: present
  master_machine_type: n2-standard-4
  worker_machine_type: n2-standard-4
  num_workers: 2
  idle_delete_ttl_seconds: 3600
  group_name: infrastructure
  kinds: [gcp, dataproc]
```

## Cluster configuration

`master_machine_type`/`worker_machine_type`/`num_workers`/`master_boot_disk_size_gb`/`worker_boot_disk_size_gb` cover the common single-master/N-worker shape. `zone` and `service_account` are optional GCE placement/identity overrides; `network_tags` applies GCE firewall tags. `image_version` pins a Dataproc image (e.g. `'2.2-debian12'`); omit it to track Dataproc's current default. `software_properties` sets cluster-wide Spark/Hadoop config (e.g. `{'spark:spark.executor.memory': '4g'}`). `idle_delete_ttl_seconds` auto-deletes an idle cluster -- useful for ephemeral, job-scoped clusters paired with `dataproc_job_asset`.

This component accepts a scoped, commonly-used subset of Dataproc's full `ClusterConfig` shape, not a full passthrough -- it does not cover autoscaling policies, secondary/preemptible worker pools, or custom VPC/subnet wiring.

## Authentication

Uses Application Default Credentials (ADC) by default -- Workload Identity, `GOOGLE_APPLICATION_CREDENTIALS`, or `gcloud auth application-default login`. Set `gcp_credentials_env_var` to an env var containing a service account JSON string to use explicit credentials instead.
