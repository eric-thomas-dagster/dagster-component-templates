# DockerContainerAsset

Wraps `dagster-docker` to run a container per materialization, wait for completion, and stream logs into the Dagster run log. Lighter-weight than k8s for local-dev or single-host pipelines.

Wraps the official `dagster-docker` package.

By default this delegates entirely to `dagster_docker.execute_docker_container`. Setting
`container_name`, `docker_base_url`, any `tls_*` field, or `retrieve_output` switches to this
component's own direct container-creation path instead -- `execute_docker_container` has no hook
for a custom container name (it always derives one from a hash of the run id and op name) or a
non-default/TLS Docker daemon connection (it always uses `docker.client.from_env()`), and
`retrieve_output` needs a container handle after the run to fetch logs, which the delegate path
never exposes. `force_pull`/`auto_remove`/`mounts`/`ports` work in either path.

## Example YAML
```yaml
type: dagster_community_components.DockerContainerAssetComponent
attributes:
  asset_name: nightly_export
  image: my-registry/exporter:1.4.0
  command: ["python", "export.py", "--full"]
  env_vars:
    TARGET_BUCKET: s3://my-exports
  network: bridge
  group_name: docker
  deps:
    - raw/orders
```
