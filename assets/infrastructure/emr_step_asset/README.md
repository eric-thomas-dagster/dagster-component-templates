# EMR Step

Add a step to an AWS EMR cluster and poll it to completion as a Dagster asset -- the Airflow `EmrAddStepsOperator` + `EmrStepSensor` equivalent in one asset.

Set `cluster_id` for an existing cluster, or `cluster_name` to resolve one by name (must match exactly one active cluster -- `STARTING`/`BOOTSTRAPPING`/`RUNNING`/`WAITING`). `jar` defaults to EMR's bundled `command-runner.jar`, the standard way to run an arbitrary shell command -- including `spark-submit` -- as a step without a custom jar; `args` then starts with the command itself, e.g. `["spark-submit", "--deploy-mode", "cluster", "s3://bucket/job.py"]`.

By default the asset polls the step to a terminal state (`COMPLETED` / `CANCELLED` / `FAILED` / `INTERRUPTED`) and raises with the step's real `FailureDetails` (`Reason`, `Message`, `LogFile`) on failure. Set `wait_for_completion: false` to fire the step and materialize immediately with just the step id -- useful when another sensor/asset tracks completion separately. Set `fail_on_step_failure: false` to materialize anyway with the terminal state in metadata instead of raising.

## Example YAML

```yaml
type: dagster_community_components.EmrStepAssetComponent
attributes:
  asset_name: run_daily_spark_job
  region_name: us-east-1
  cluster_name: analytics-emr-cluster
  jar: command-runner.jar
  args:
    - spark-submit
    - --deploy-mode
    - cluster
    - s3://my-bucket/jobs/daily_aggregation.py
  action_on_failure: CONTINUE
  timeout_seconds: 7200
  group_name: spark
  kinds: [aws, emr]
```

## Authentication

Uses the standard boto3 credential chain (env vars, shared config/credentials file, instance/task role). Set `aws_profile` to use a named profile instead of the default.

## Requirements

boto3
