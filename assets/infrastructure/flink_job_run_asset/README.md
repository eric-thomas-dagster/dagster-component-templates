# Flink Job Run

Submits (and optionally waits on) a job on a **self-hosted** Apache Flink cluster -- standalone, Kubernetes, or a YARN session -- via the real Flink JobManager REST API every such deployment exposes.

This is distinct from [`managed_flink_application_asset`](../managed_flink_application_asset/README.md), which talks to AWS's managed runtime (`kinesisanalyticsv2`) instead -- a different control plane entirely, since a self-managed cluster has no AWS API to call. Use this component when Flink itself is self-hosted; use the other when it's AWS Managed Service for Apache Flink.

## `wait_mode`

Controls what "materializing" this asset means:
- `until_finished` (default) -- for a **batch** job: poll until `FINISHED` / `CANCELED` / `FAILED`.
- `until_running` -- for a **streaming** job meant to run forever: poll only until it reaches `RUNNING`, then return; the job keeps running in the cluster after the asset materializes.
- `fire_and_forget` -- submit and return immediately, no polling at all.

## Example YAML

```yaml
type: dagster_community_components.FlinkJobRunAssetComponent
attributes:
  asset_name: clickstream_enrichment_job
  jobmanager_url: http://flink-jobmanager:8081
  jar_path: /opt/flink/jobs/clickstream-enrichment.jar
  entry_class: com.acme.ClickstreamEnrichmentJob
  program_args: ['--kafka-topic', 'clickstream.raw']
  wait_mode: until_running
  group_name: streaming
```

## Jar handling

Set exactly one of:
- `jar_path` -- a local jar file this component uploads first (`POST /jars/upload`), then runs using the server-assigned jar id from that response (not the local path).
- `jar_id` -- a jar already uploaded to the cluster (the filename a prior `POST /jars/upload` returned), to skip re-uploading on every run.

## Authentication

Flink's JobManager REST API has no built-in auth of its own -- if yours sits behind an authenticating reverse proxy or ingress, set `request_headers` (e.g. `{"Authorization": "Bearer ..."}`).
