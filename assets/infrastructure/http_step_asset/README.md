# HTTP Step

One synchronous HTTP call as a Dagster asset -- the Airflow `SimpleHttpOperator` equivalent.

A single request, a status-code (and optional response-field) success check, materialize with response metadata. Distinct from `integrations/http_external_asset` (a real trigger-a-job-then-poll-a-separate-status-endpoint-until-terminal asset builder, for async external systems with no dedicated vendor component) -- this component is explicitly the simpler, synchronous sibling: no polling loop, one request in, one result out.

By default any 2xx status is success. Set `success_status_codes` to restrict to specific codes. Set `response_json_path` + `response_json_success_value` to additionally require a specific value at a dotted path in the JSON response (e.g. `{"status": "ok"}` with `response_json_path: status` and `response_json_success_value: "ok"`). A failed check raises `dg.Failure` with the response status/body in the exception message and metadata.

```yaml
type: dagster_community_components.HttpStepAssetComponent
attributes:
  asset_name: notify_pipeline_complete
  url: https://api.example.com/v1/notifications
  method: POST
  json_body:
    message: "nightly pipeline complete"
  auth_type: bearer
  auth_token_env_var: NOTIFY_API_TOKEN
  response_json_path: status
  response_json_success_value: "ok"
  group_name: infrastructure
  kinds: [python, http]
```

## Authentication

`auth_type: none` (default) / `basic` (env-var username + password) / `bearer` (env-var token). Matches `assets/transforms/per_row_http_fetcher`'s auth fields for registry-wide consistency, minus `oauth2_client_credentials` -- a single synchronous step has no recurring token-refresh loop to amortize an extra auth round trip against; point `auth_token_env_var` at a pre-fetched bearer token instead.
