# Managed Flink Application

Ensures an AWS Managed Service for Apache Flink application (the managed runtime for Apache Flink; `kinesisanalyticsv2` in boto3) is running or stopped.

A Managed Flink application is a long-running stream processor, not a batch job that completes -- materializing this asset means "ensure the application is in `desired_state`" (idempotent: a no-op if it's already there), not "wait for it to finish." It reads the current `ApplicationStatus` via `describe_application`, calls `start_application`/`stop_application` if needed, then polls until the application settles into `RUNNING` or `READY`.

## Restoring from a snapshot

`application_restore_type` controls how a (re)start resumes state:
- `RESTORE_FROM_LATEST_SNAPSHOT` -- resume from the application's most recent snapshot.
- `SKIP_RESTORE_FROM_SNAPSHOT` -- start fresh, ignoring any snapshot.
- `RESTORE_FROM_CUSTOM_SNAPSHOT` -- requires `snapshot_name`, restore from a specific named snapshot.

`allow_non_restored_state` lets the runtime skip snapshot state that can't be mapped to an updated program (e.g. after a code change that removes an operator) rather than failing the restart outright.

## Authentication

Uses the standard boto3 credential chain (env vars, shared config/credentials file, instance/task role). Set `aws_profile` to use a named profile instead of the default.
