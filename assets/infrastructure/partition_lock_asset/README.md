# `PartitionLockAssetComponent` + `@partition_lock` decorator

Cross-run partition-scoped mutex via the Dagster event log. Prevent two concurrent runs from materializing the same `partition_key` of the same asset — without Redis, Zookeeper, or a side database.

## What it does

- On entry, scans recent `ASSET_OBSERVATION` events for `partition_lock_acquired=<partition_key>` newer than `ttl_seconds`.
- If found → conflict, resolved per `on_conflict`:
  - `wait` (default) — sleep-poll every `poll_seconds` up to `max_wait_seconds`.
  - `skip` — return `MaterializeResult(partition_lock_skipped=true)`; emit `partition_lock_skipped` observation.
  - `fail` — raise `dg.Failure`.
- On acquire → emit `partition_lock_acquired=<partition_key>` observation.
- On success or failure → emit `partition_lock_released=<partition_key>` observation.

## Why this belongs in Dagster

- **Lock state lives in the event log** — restart-safe, worker-safe, no side infra to run.
- **TTL auto-expires stuck holders** — a crashed run doesn't wedge the partition forever.
- **Companion sensor pattern** — a monitor finds `partition_lock_acquired` observations older than TTL that never got `partition_lock_released` (crashed holder detection).

## Race condition disclosure

This is a **probabilistic mutex**, not a distributed atomic. Two runs starting within ~200 ms could both observe an unlocked state and acquire. Acceptable for:

- Backfill dedupe (accidental concurrent partition triggers)
- Long-running exports that shouldn't overlap
- Warehouse writes that are idempotent within a partition

**Not adequate for**: money transfers, unique-key mint operations. Use a warehouse table lock or Postgres advisory lock inside the compute for those.

## Full YAML example

```yaml
type: dagster_community_components.PartitionLockAssetComponent
attributes:
  asset_name: daily_report

  compute:
    kind: python
    python: "my_project.reports:build_daily_partition"

  ttl_seconds: 1800          # lock auto-expires after 30 min
  on_conflict: wait          # wait (default) | skip | fail
  max_wait_seconds: 300      # 5 min budget when waiting
  poll_seconds: 5
```

## `@partition_lock` decorator

```python
import dagster as dg
from dagster_community_components import partition_lock

@dg.asset(partitions_def=daily_partitions)
@partition_lock(ttl_seconds=1800, on_conflict="wait", max_wait_seconds=300)
def daily_report(context):
    return build_report(context.partition_key)
```

## Composes with

- **`@smart_retry`** — retries inside a held lock.
- **`@throttle`** — orthogonal: throttle = inter-run gap; partition_lock = per-partition concurrency=1.
- **`@sla`, `@timeout`** — measure/kill the lock holder before TTL expires.
- **`@lifecycle`** — WAP inside the lock — safe atomic swap on a partition.

## Sensor pattern — detect crashed holders

```python
@dg.sensor
def stuck_lock_monitor(context):
    from dagster import EventRecordsFilter, DagsterEventType
    records = context.instance.get_event_records(
        event_records_filter=EventRecordsFilter(event_type=DagsterEventType.ASSET_OBSERVATION),
        limit=500, ascending=False,
    )
    acquired = {}
    for r in records:
        tags = r.asset_observation.tags
        pk_a = tags.get("partition_lock_acquired")
        pk_r = tags.get("partition_lock_released")
        if pk_a and pk_a not in acquired and pk_a not in {v for v in acquired.values()}:
            acquired[pk_a] = r.timestamp
        if pk_r in acquired:
            del acquired[pk_r]
    # `acquired` is now partition_keys with unmatched acquire → check age vs. TTL
    ...
```

## What's not in v1 (roadmap)

- **Strong mutex** — optional Postgres advisory lock integration for atomic acquire.
- **Explicit release on skip** — currently skip doesn't release (there was nothing to release); consider emitting a released event anyway for symmetry.
- **Per-partition TTLs** — different TTL for hourly vs. daily partitions of the same asset.
