# Redshift Data API Asset

Run a SQL query against Amazon Redshift (provisioned cluster or Serverless) via the AWS Redshift Data API as a Dagster asset -- the Airflow `RedshiftDataOperator` equivalent.

Calls `execute_statement`, polls `describe_statement` until the statement reaches `FINISHED`/`FAILED`/`ABORTED`, and raises with the real `Error` message on anything but success. `sql` is rendered through Jinja2 first, so `{{ partition_key }}`/`{{ partition_start }}`/`{{ partition_end }}`/`{{ partition_date }}` are available for a partitioned asset.

Connection: set EITHER `cluster_identifier` (a provisioned cluster -- pair with `db_user` for temporary IAM credentials, or `secret_arn_env_var` for Secrets Manager auth) OR `workgroup_name` (Redshift Serverless -- `secret_arn_env_var` optional there, since Serverless can authenticate via the caller's own IAM identity).

This does **not** fetch result rows into asset metadata (avoids pulling potentially large/sensitive query results through Dagster) -- only `result_rows`/`result_size` counts from `describe_statement` are reported.

## Example YAML

```yaml
type: dagster_community_components.RedshiftDataApiAssetComponent
attributes:
  asset_name: refresh_sales_summary
  sql: |
    CALL refresh_sales_summary('{{ partition_date }}');
  database: analytics
  workgroup_name: my-serverless-workgroup
  region_name: us-east-1
  partition_type: daily
  partition_start: '2024-01-01'
  group_name: analytics
  kinds: [aws, redshift]
```

## Authentication

Uses the standard boto3 credential chain (env vars, shared config/credentials file, instance/task role). Set `aws_profile` to use a named profile instead of the default.

## Requirements

```
boto3
jinja2
```
