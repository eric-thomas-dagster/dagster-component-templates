# S3CopyObjectAsset

Copy an S3 object to another location as a Dagster asset — mirrors Airflow's `S3CopyObjectOperator`.

```yaml
type: dagster_community_components.S3CopyObjectAssetComponent
attributes:
  source_s3_url: "s3://my-bucket/inbox/report.csv"
  dest_s3_url: "s3://my-bucket/archive/report.csv"
  acl: private
```

Both source and destination accept either a single `s3://bucket/key` URL, or `source_bucket`+`source_key` / `dest_bucket`+`dest_key` separately — set exactly one form per side.

`acl` defaults to `"private"`. Set `resource_key` to source credentials from a registered `aws_s3_resource` component instead of a bare `boto3.client("s3", region_name=...)`.

## Concurrency, retries, and timeouts

- `pool: <name>` — Dagster's native named concurrency pool (Airflow's `pool`), sharing a fixed number of slots across every asset/op using the same pool name. The slot count is configured at the deployment level (`dagster.yaml`'s `concurrency: pools:`, or the Dagster+ UI).
- `retry_policy_max_retries`/`retry_policy_delay_seconds`/`retry_policy_backoff` — a `RetryPolicy` for transient S3/network errors.
- `timeout_seconds` — bounds how long this step waits, via a background-thread wrapper. The underlying boto3 call may continue running past the deadline (Python threads can't be forcibly killed); this bounds the step's wait, not the call itself.
