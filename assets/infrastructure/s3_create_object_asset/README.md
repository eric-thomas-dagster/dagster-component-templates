# S3CreateObjectAsset

Write a literal string/bytes value to an S3 object as a Dagster asset — mirrors Airflow's
`S3CreateObjectOperator`.

```yaml
type: dagster_community_components.S3CreateObjectAssetComponent
attributes:
  asset_name: write_manifest
  data: '{"status": "ready"}'
  dest_s3_url: "s3://my-bucket/manifests/status.json"
  content_type: application/json
```

## `replace` — existence check before writing

Verified against the real boto3 `put_object` signature before building anything: `put_object`
itself always overwrites with no existence check (S3 PUT is unconditional). `replace: false`
(default, matching `S3CreateObjectOperator`'s own default) is enforced the same way
`s3_upload_file_asset` already does it: a `head_object` existence check runs first, and the
asset fails clearly if the destination key already exists. Set `replace: true` to always
write, overwriting any existing object.

## `data` vs `data_asset_key`

```yaml
data: "literal string"          # encoded as UTF-8 before upload
```
```yaml
data_asset_key: upstream_asset  # the upstream's materialized value (str or bytes) IS the body
```

## Concurrency, retries, and timeouts

- `pool: <name>` — Dagster's native named concurrency pool (Airflow's `pool`), sharing a fixed number of slots across every asset/op using the same pool name. The slot count is configured at the deployment level (`dagster.yaml`'s `concurrency: pools:`, or the Dagster+ UI).
- `retry_policy_max_retries`/`retry_policy_delay_seconds`/`retry_policy_backoff` — a `RetryPolicy` for transient S3/network errors.
- `timeout_seconds` — bounds how long this step waits, via a background-thread wrapper. The underlying boto3 call may continue running past the deadline (Python threads can't be forcibly killed); this bounds the step's wait, not the call itself.
