# S3DeleteObjectsAsset

Delete a list of S3 objects as a Dagster asset — mirrors Airflow's `S3DeleteObjectsOperator`.

```yaml
type: dagster_community_components.S3DeleteObjectsAssetComponent
attributes:
  bucket: my-bucket
  keys_asset_key: inbox_file_keys   # or keys: [a.txt, b.txt] for a static list
```

Set exactly one of `keys` (a static list) or `keys_asset_key` (an upstream asset whose materialized value is a list of keys — e.g. the output of `s3_list_keys_asset`). Deletes are chunked at 1000 keys per `DeleteObjects` call (the real S3 API limit). Any `Errors` in any chunk's response fails the asset clearly, with the error list in metadata.

Set `resource_key` to source credentials from a registered `aws_s3_resource` component instead of a bare `boto3.client("s3", region_name=...)`.

## Concurrency, retries, and timeouts

- `pool: <name>` — Dagster's native named concurrency pool (Airflow's `pool`), sharing a fixed number of slots across every asset/op using the same pool name. The slot count is configured at the deployment level (`dagster.yaml`'s `concurrency: pools:`, or the Dagster+ UI).
- `retry_policy_max_retries`/`retry_policy_delay_seconds`/`retry_policy_backoff` — a `RetryPolicy` for transient S3/network errors.
- `timeout_seconds` — bounds how long this step waits, via a background-thread wrapper. The underlying boto3 call(s) may continue running past the deadline (Python threads can't be forcibly killed); this bounds the step's wait, not the call itself.
