# S3UploadFileAsset

Upload a local file to S3 as a Dagster asset — mirrors Airflow's `LocalFilesystemToS3Operator` / `S3Hook.load_file`.

```yaml
type: dagster_community_components.S3UploadFileAssetComponent
attributes:
  local_path: ./output/report.csv
  dest_s3_url: "s3://my-bucket/reports/report.csv"
  replace: true
```

`replace: false` (the default, matching `S3Hook.load_file`'s own documented contract) checks whether the destination already exists via `head_object` (a 404 means "doesn't exist yet") and **fails clearly** if it does, before ever touching `upload_file`. `replace: true` always uploads, overwriting any existing object.

Destination accepts either a single `s3://bucket/key` URL (`dest_s3_url`), or `bucket`+`key` separately. `extra_args` is passed straight through to boto3's `upload_file(ExtraArgs=...)` (e.g. `{"ACL": "private", "ContentType": "text/csv"}`).

Set `resource_key` to source credentials from a registered `aws_s3_resource` component instead of a bare `boto3.client("s3", region_name=...)`.

## Concurrency, retries, and timeouts

- `pool: <name>` — Dagster's native named concurrency pool (Airflow's `pool`), sharing a fixed number of slots across every asset/op using the same pool name. The slot count is configured at the deployment level (`dagster.yaml`'s `concurrency: pools:`, or the Dagster+ UI).
- `retry_policy_max_retries`/`retry_policy_delay_seconds`/`retry_policy_backoff` — a `RetryPolicy` for transient S3/network errors.
- `timeout_seconds` — bounds how long this step waits, via a background-thread wrapper. The underlying boto3 call may continue running past the deadline (Python threads can't be forcibly killed); this bounds the step's wait, not the call itself.
