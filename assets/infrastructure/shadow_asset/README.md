# `ShadowAssetComponent` + `@shadow` decorator

Dual-run old + new implementations, diff outputs, ship the migration when they converge. Production always uses the primary; the shadow reports.

## What it does

- **Primary** compute produces the canonical asset value — production unchanged.
- **Shadow** compute runs after primary with the same inputs.
- **Diff** is emitted as `AssetObservation` per run, tagged `shadow_match=true|false`.
- Shadow exceptions are trapped (emitted as `shadow_error` observation) — production never breaks because of the shadow.
- `enforce_match=true` upgrades a mismatch to `dg.Failure` (opt-in for release gates).

## Why this belongs in Dagster

- **Every run is an event log entry** — `shadow_match`, `shadow_diff_rows`, `shadow_extra_cols`, `shadow_missing_cols`. A sensor can escalate after N consecutive mismatches.
- **Composes with `@dry_run`** — shadow a candidate migration end-to-end without ever risking a bad materialization.
- **Fits the migration playbook** — ship shadow → verify convergence → flip primary → drop shadow. Every stage tracked in the event log.

## Diff strategy

Ordered fallback:

| Type | Comparison |
|---|---|
| Both `None` | match |
| `pandas.DataFrame` | shape + column set + first-500-row equality |
| `list` / `tuple` | element equality |
| `dict` | key-value equality |
| Anything else | `primary == shadow` |

Diff details land as typed metadata on the `AssetObservation` so sensors and BI can query drift over time.

## Full YAML example

```yaml
type: dagster_community_components.ShadowAssetComponent
attributes:
  asset_name: order_totals

  compute:
    kind: python
    python: "my_project.reports:old_order_totals"

  shadow_compute:
    kind: python
    python: "my_project.reports:new_order_totals"

  enforce_match: false          # false (default) = observe; true = fail-on-mismatch
```

## `@shadow` decorator

```python
import dagster as dg
from dagster_community_components import shadow

def new_order_totals(context, upstream):
    return upstream.groupby("customer_id")["amount"].sum().reset_index()

@dg.asset
@shadow(new_order_totals)  # observe-only
def order_totals(context, upstream):
    return old_order_totals(context, upstream)
```

## Sensor pattern — alert on repeat mismatches

```python

    from dagster import EventRecordsFilter, DagsterEventType
    records = context.instance.get_event_records(
        event_records_filter=EventRecordsFilter(event_type=DagsterEventType.ASSET_OBSERVATION),
        limit=100, ascending=False,
    )
    for asset_name in ["order_totals", "customer_ltv"]:
        mismatches = [
            r for r in records
            if r.asset_observation.asset_key.to_user_string() == asset_name
```

## Composes with

- **`@dry_run`** — shadow-instrument a dry run to validate a candidate end-to-end.
- **`@lifecycle`** — shadow at the audit stage; primary publishes, shadow observes.
- **`@profile`** — profile both primary and shadow; diff the profiles for coarse drift.
- **`@smart_retry`** — retry the shadow independently of the primary.

## What's not in v1 (roadmap)

- **Parallel execution** — shadow currently runs after primary. Worker-pool parallelism is on deck.
- **Fuzzy match** — tolerance for float rounding differences.
- **Full row diff export** — write mismatched rows to a side asset for triage.
