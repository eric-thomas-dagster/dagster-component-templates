# Spark Submit

Run `spark-submit` as a Dagster asset -- the Airflow `SparkSubmitOperator` equivalent, for a Spark cluster reached by a local `spark-submit` install (standalone master URL, YARN, Kubernetes master URL, or `local[*]`).

Builds the real `spark-submit` command line from the component's fields (`--master`, `--deploy-mode`, `--class`, one `--conf key=value` per `conf` entry, `--packages`/`--jars`/`--py-files` as comma-joined lists) then the application path and its args. Streams stdout/stderr through the parent process (so the Dagster ComputeLogManager captures them) and raises on a non-zero exit code with the captured stderr, unless that code is listed in `success_exit_codes`.

Distinct from `spark_livy_batch_asset` (submits over Apache Livy's REST API -- no local `spark-submit` binary needed) and `spark_k8s_operator_asset` (submits via the Kubernetes Spark Operator CRD).

## Example YAML

```yaml
type: dagster_community_components.SparkSubmitAssetComponent
attributes:
  asset_name: run_daily_aggregation
  application: s3://my-bucket/jobs/daily_aggregation.py
  master: yarn
  deploy_mode: cluster
  conf:
    spark.executor.memoryOverhead: 512m
  executor_memory: 4g
  num_executors: 10
  application_args:
    - --date
    - '2024-01-01'
  group_name: spark
  kinds: [spark]
```

## Requirements

Requires a `spark-submit` binary on `PATH` (or `spark_submit_binary` pointed at one). No extra Python dependencies.
