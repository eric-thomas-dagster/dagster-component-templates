# WaitUntilAsset

Hold a single Dagster step open until a condition becomes true — Airflow's sensor-mode
operators (`PythonSensor`, `BashSensor`, `FileSensor`, `TimeSensor`, `TimeDeltaSensor`), which
poll *inside* one task rather than starting a separate run.

This is a different shape from `python_sensor`/`*_monitor`/`event_automation`: those react
from *outside* a run and start a *new* one. This component *is* the step itself, blocking the
run it's already part of, until its condition is met (or `timeout_seconds` elapses).

```yaml
type: dagster_community_components.WaitUntilAssetComponent
attributes:
  asset_name: wait_for_upstream_file
  condition: file_exists
  file_pattern: "/data/inbox/orders_*.csv"
  poll_seconds: 30
  timeout_seconds: 1800
```

## Conditions

| `condition` | Checks | Required field(s) |
|---|---|---|
| `callable` | `callable_path()` (no args) returns truthy | `callable_path` |
| `shell_exit_zero` | a shell command exits 0 | `command` (+ optional `retry_exit_code`) |
| `file_exists` | a glob pattern matches at least one path | `file_pattern` |
| `time_of_day` | today's wall-clock time (in `timezone`) has passed `time_of_day` | `time_of_day` |
| `delay` | `delay_seconds` have passed since the run's reference time | `delay_seconds` |
| `sftp_file_exists` | `sftp_path` exists on an SFTP server (checked via `stat`, not a glob) | `sftp_host_env_var`, `sftp_username_env_var`, `sftp_path`, + `sftp_password_env_var` or `sftp_private_key_env_var` |
| `s3_key_exists` | `s3_key` exists in `s3_bucket` (checked via `head_object`) | `s3_bucket`, `s3_key` |
| `gcs_object_exists` | `gcs_blob_name` exists in `gcs_bucket` | `gcs_bucket`, `gcs_blob_name` |
| `http_ok` | a `GET` to `http_url` returns a 2xx status (anything else, including a connection error, is "not yet met") | `http_url` |

## `sftp_file_exists` / `s3_key_exists` / `gcs_object_exists` / `http_ok`

Same auth conventions as this package's own ingestion components, not a new pattern:
`sftp_file_exists` mirrors `sftp_to_database_asset`'s `host_env_var`/`username_env_var`/
`password_env_var`/`private_key_env_var` (paramiko); `s3_key_exists` uses boto3's default
credential/region chain, same as `s3_to_database_asset`; `gcs_object_exists` mirrors
`gcs_to_database_asset`'s `credentials_env_var` (unset falls back to application-default
credentials); `http_ok` mirrors `per_row_http_fetcher`'s `auth_type` (`none`/`basic`/`bearer`
only here — no `oauth2_client_credentials`, since a poll check has no use for a short-lived
token refresh loop). `sftp_file_exists` checks an exact path via SFTP `stat`, not a glob —
SFTP has no native wildcard listing the way local `file_exists` does.

## `retry_exit_code` — a designated "not ready yet" exit code

Airflow's `BashSensor` distinguishes "keep polling" from "fail now" by a specific exit code.
Without `retry_exit_code` set, ANY non-zero exit fails the run immediately (no polling). With
it set, that one specific code keeps polling; every other non-zero code still fails immediately:

```yaml
condition: shell_exit_zero
command: check_export_ready.sh
retry_exit_code: 75   # EX_TEMPFAIL-style convention -- "not ready", not "broken"
```

## `delay`'s reference time

Priority 1: this run's `logical_date` tag (set by `cron_schedule`'s/`interval_schedule`'s
`add_logical_date_tag`/`add_interval_tags` — the same convention `python_callable_asset` and
`conditional_asset` use for their own date resolution). Priority 2: the time this step itself
started executing.

## `on_timeout`

`fail` (default): raises and fails the run. `skip`: materializes successfully with
`timed_out: true` / `met: false` metadata — Dagster has no native per-asset "skipped" status
for a single-asset op, same convention as `shell_command_asset`'s `skip_on_exit_code`.

## Requirements

```
dagster
paramiko>=3.0.0
boto3>=1.26.0
google-cloud-storage>=2.0.0
requests
```

`paramiko` is only needed for `condition='sftp_file_exists'`, `boto3` only for
`'s3_key_exists'`, `google-cloud-storage` only for `'gcs_object_exists'`, and `requests`
only for `'http_ok'` — the other conditions (`callable`, `shell_exit_zero`, `file_exists`,
`time_of_day`, `delay`) need none of them.
