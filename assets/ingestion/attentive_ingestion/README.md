# Attentive Ingestion

Ingest Attentive SMS/email marketing segment, webhook, and catalog-upload data using dlt's generic REST API source.

Uses dlt's generic REST API source (`dlt.sources.rest_api.rest_api_source`).

By default, runs an in-memory DuckDB pipeline and returns a pandas DataFrame. Set `destination` to persist directly to any dlt-supported destination. See `../DESTINATIONS.md`.

> **Verified against Attentive's primary docs** (docs.attentive.com, including the machine-readable reference index at docs.attentive.com/llms.txt):
> - **Auth**: `Authorization: Bearer <API_KEY>` (a private-application API key created in the Integrations setup page).
> - **Base URL**: `https://api.attentivemobile.com`.
> - **Shape deviation from the rest of this batch**: Attentive's public API is overwhelmingly WRITE-oriented (events, user-attribute upserts, subscribe/unsubscribe) or single-identifier LOOKUP-oriented (`GET /v1/subscriptions?phone=...`/`?email=...` returns one subscriber's eligibility). It does **not** expose a generic, paginated "list all customers/events/campaigns" bulk endpoint the way the other five vendors in this batch do -- confirmed by walking the full reference index: there is no list-campaigns or list-events endpoint at all, and "list subscribers" doesn't exist either (only single-identifier eligibility lookup). The only genuinely bulk-listable, paginated GET resources in the real API are:
>   - **`segments`** -> `GET /v2/segments` -- note the **different version prefix** (v2, not v1), confirmed on its own reference page, with real cursor pagination (`cursor`, `limit`, default 20, max 1000) and filters (`name`, `externalId`, `updatedSince`).
>   - **`webhooks`** -> `GET /v1/webhooks` -- lists configured webhook subscriptions (event-type routing config, not historical event data itself).
>   - **`product_catalog_uploads`** -> `GET /v1/product-catalog/uploads` -- lists recent product-catalog ingestion-job statuses.
> This connector exposes exactly these three; it does not attempt to force a "subscribers" or "events" bulk resource that the real API does not support.

> **Partition honesty note:** if you set `partition_type`, it controls Dagster's materialization/backfill schedule only. This connector's compute function does not use the partition key to filter the API request, so every partition run re-fetches the same full resource set rather than a bounded window.
