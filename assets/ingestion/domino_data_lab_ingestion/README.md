# Domino Data Lab Ingestion

Ingest Domino Data Lab (dominodatalab.com / docs.domino.ai) user, project, and compute-environment metadata using dlt's generic REST API source.

Uses dlt's generic REST API source (`dlt.sources.rest_api.rest_api_source`).

By default, runs an in-memory DuckDB pipeline and returns a pandas DataFrame. Set `destination` to persist directly to any dlt-supported destination. See `../DESTINATIONS.md`.

> **Self-hosted / per-deployment, like Metabase:** Domino Data Lab has no single global API base URL -- it's deployed per customer (self-hosted, or as "Domino Cloud" at a per-customer subdomain). There is no default; `deployment_url` is **required**, following the same convention as this repo's `metabase_ingestion` component (`instance_url`). The API base is built at run-time as `self.deployment_url.rstrip("/")`.

> **Verified against Domino's own currently-published OpenAPI spec** (fetched and parsed directly as JSON from `https://docs.domino.ai/api-specs/6.3/public-api.json`, 587 operations), cross-checked against the `dominodatalab/python-domino` official SDK's source:
> - **Server / base URL convention**: the OpenAPI spec's own `servers` block literally states `https://mycluster.domino.tech` with the note *"Replace 'mycluster.domino.tech' with your Domino cluster hostname. For Domino Cloud customers, that is `your-subdomain`.domino.tech ... For self-hosted deployments, it is the hostname you reach the Domino UI at."* -- directly confirming the self-hosted/per-deployment shape.
> - **Auth**: `X-Domino-Api-Key` header. Confirmed directly from the spec's `components.securitySchemes` (`DominoApiKey`: `{"type": "apiKey", "in": "header", "name": "X-Domino-Api-Key"}`), listed as the primary security scheme on every operation this connector uses. Generated per-user in Domino's UI under Account Settings > API Key. (A separate SCIM 2.0 API with its own bearer token exists for provisioning automation -- out of scope here.)
> - **`users`** -> `GET /api/users/v1/users` -- "Get all users visible to the current user." Response envelope `{"users": [...], "metadata": {...}}`.
> - **`projects`** -> `GET /api/projects/beta/projects` -- "Get projects that a user can see." Response envelope `{"projects": [...], "metadata": {...}}`. Domino marks this "beta" but it's the current documented way to list all visible projects.
> - **`environments`** -> `GET /api/environments/beta/environments` -- "Get environments that a user can see." Response envelope `{"environments": [...], "metadata": {...}}`.
> - All three are offset/limit paginated, defaulting server-side to `limit=10`. This connector requests `limit=100` and pulls a **single page per run** (no multi-page loop), matching this repo's other simple REST connectors (e.g. `reclaim_ingestion`).
>
> **Correction to this component's original research pass:** the seed assumption was a single uniform `https://<deployment>/v4/...` base URL for everything, based on the confirmed-real (and still-working) legacy `GET /v4/users` route. That route does exist, but Domino's current, officially-documented public API surface instead exposes `/api/<service>/<version>/<resource>`-style routes (e.g. `/api/users/v1/users` rather than `/v4/users`) -- and digging into the legacy SDK's own route-builders showed its internal "environments_list"/"models_list" helpers aren't even consistently global: `environments_list()` hits an undocumented `/v1/environments` alias, and `models_list()` is project-scoped (`/v1/projects/{owner}/{project}/models`), not a cross-project list. This component targets the three genuinely-global, OpenAPI-documented list endpoints above rather than forcing everything under one `/v4` prefix.

## Configuration

| Field | Required | Description |
|---|---|---|
| `asset_name` | required | Name of the asset that will hold the data |
| `deployment_url` | required | Base URL of your Domino Data Lab deployment, e.g. `https://domino.mycompany.com` (self-hosted, varies per customer). No default -- see above. |
| `api_key` | required | Domino API key (X-Domino-Api-Key header), generated per-user in Account Settings > API Key. |
| `resources` | optional | Comma-separated list of resources to extract: users, projects, environments. Default: `users,projects,environments` |
