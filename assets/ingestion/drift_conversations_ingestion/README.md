# Drift Conversations Ingestion

Fetch Drift conversations via `GET /conversations/list` and (optionally) each conversation's
messages via `GET /conversations/{id}/messages`, materializing the result as a pandas DataFrame.

Uses:
- `GET /conversations/list` — `page_token`-paginated list of conversations
- `GET /conversations/{id}/messages` — per-conversation message history (when `include_messages: true`)

## Installation

```bash
pip install requests pandas
```

Also requires a `DriftResourceComponent` on the same code location for authentication (see
`resources/drift_resource`).

## Configuration

```yaml
type: dagster_component_templates.DriftConversationsIngestionComponent
attributes:
  asset_name: drift_conversations
  resource_name: drift_resource
  from_date_time: "2026-06-01T00:00:00Z"
  to_date_time: "2026-07-01T00:00:00Z"
  include_messages: true
  limit: 200
```

## Output Schema

The DataFrame contains every field Drift's `/conversations/list` returns (`id`, `status`,
`contactId`, `inboxId`, `createdAt`, `updatedAt`, ...) plus, when `include_messages: true`:

- `messages_raw` — the raw structured list of message objects per conversation
- `transcript` — a flattened `AUTHOR: text` newline-joined string suitable for LLM prompts

## Drift API notes

- Pagination uses the response's `pagination.next` field, passed back as `page_token` on the next
  request (matching Drift's own `drift-python` client library). Requests loop until no `next`
  token is returned, the page comes back empty, or `limit` is reached.
- **`/conversations/list` has no documented date-range filter** — only `statusId` is supported
  server-side. `from_date_time` / `to_date_time` are therefore applied as a **client-side filter**
  on each conversation's `createdAt` (epoch milliseconds) after fetching.
- Message fetching is capped at 20 pages per conversation as a safety bound against pathologically
  long conversations; 50 messages are returned per page.
- Auth is `Authorization: Bearer <token>` against `https://driftapi.com`.
