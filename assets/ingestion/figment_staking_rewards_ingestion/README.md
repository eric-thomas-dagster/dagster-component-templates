# Figment Staking Rewards Ingestion

Pull granular and/or aggregated staking rewards/balances per validator/delegator from [Figment's](https://figment.io) institutional staking **Rewards API**, across networks, and materialize the result as a pandas DataFrame.

Figment's Rewards API is **read-only reporting** — there is no reverse-ETL/write-side Figment component in this repo, since staking operations (delegate, create validator, exit validator) are separate deliberate actions, not a warehouse sync.

## Installation

```bash
pip install requests pandas
```

Also requires a `FigmentResourceComponent` on the same code location for authentication (see `resources/figment_resource`).

## Configuration

```yaml
type: dagster_community_components.FigmentStakingRewardsIngestionComponent
attributes:
  asset_name: figment_eth_staking_rewards
  resource_key: figment_resource
  network: ethereum
  time_rollup: daily
  start: "2026-06-01T00:00:00Z"
  end: "2026-07-01T00:00:00Z"
  include_aggregate_summary: true
```

```yaml
type: dagster_community_components.FigmentStakingRewardsIngestionComponent
attributes:
  asset_name: figment_sol_staking_rewards
  resource_key: figment_resource
  network: solana
  accounts: ["<stake-or-system-account-address>"]  # max 50 per request
```

## Figment API notes (verified via docs.figment.io, 2026-10)

- **Ethereum**: `POST https://api.figment.io/ethereum/rewards` returns gross rewards earned by validators created via FigApp or the Create Validators endpoint. Granularity is set with `time_rollup` (`epoch` = most granular, `daily`, `all_time` = aggregated); filter by date with `start`/`end` (both bounds inclusive), by validator with `pubkeys`, or by address with `withdrawal_addresses`. Rewards appear roughly 3 hours after the network distributes them on-chain.
- **Solana**: `POST https://api.figment.io/solana/rewards` returns rewards (net of on-chain validator commission) for any wallet staking with any validator. The required body field is `accounts` (stake-account or system-account addresses) — **max 50 accounts per request**, enforced here at config time.
- Both endpoints, and every other Figment endpoint, share the same `https://api.figment.io` host and `x-api-key` auth.
- The exact response envelope isn't uniformly documented across every network; this component defensively looks for a list under `data` / `rewards` / `results`, falling back to treating the whole response as a single aggregate row.
- `extra_query_params` is the escape hatch for any network/field this component doesn't model explicitly (Figment supports many more networks than ETH/SOL under the same `/{network}/rewards` shape).

## Pairs with

- **`figment_resource`** — static `x-api-key` auth (required).

## Partitioning

Set `partition_type` (with `partition_start` for time partitions) to partition this asset. On a partitioned run the tokens `{partition_key}`, `{partition_date}`, `{partition_start}` and `{partition_end}` (and `{partition_<dimension>}` for multi-partitions) are substituted into `start`, `end`, so each partition reads its own slice. Unpartitioned runs use the value as written.
