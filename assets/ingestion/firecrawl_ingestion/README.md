# Firecrawl Ingestion

Scrape or crawl websites into clean markdown via [Firecrawl](https://firecrawl.dev), ready to feed into `document_chunker` for a RAG pipeline.

> **Note:** Firecrawl has no official dlt-maintained verified source, and (unlike most REST APIs in this repo) its two relevant endpoints don't share one shape dlt's generic `rest_api_source` auto-pagination can drive: `/v2/scrape` is a synchronous single-URL call, while `/v2/crawl` is asynchronous (POST starts a job, returns an `id`; you then poll `GET /v2/crawl/{id}` until `status == 'completed'`, following `next` to page through large result sets). This connector is hand-written with a plain `@dlt.resource` generator wrapping the already-fetched rows -- the same approach used for Dropbox/Linear/monday.com elsewhere in this repo -- so destination flexibility, hash_columns, on_schema_change, exclude_columns, and max_rows_per_resource all still work identically to every other ingestion component.

Firecrawl has no multi-table concept: one run produces a flat set of scraped pages, so there is no `asset_shape`/multi_asset option here.

By default, runs an in-memory DuckDB pipeline and returns a pandas DataFrame. Set `destination` to persist directly to any dlt-supported destination. See `../DESTINATIONS.md`.

## Configuration

| Field | Required | Description |
|---|---|---|
| `asset_name` | required | Name of the asset that will hold the data |
| `api_key_env_var` | optional (default `FIRECRAWL_API_KEY`) | Env var holding your Firecrawl API key. |
| `urls` | optional | Comma-separated list of specific URLs to scrape. Required unless `crawl_url` is set. |
| `crawl_url` | optional | Root URL to crawl. Required unless `urls` is set. |
| `crawl_limit` | optional (default `100`) | Max pages to crawl when `crawl_url` is set. |
| `crawl_max_depth` | optional | Max link-following depth from `crawl_url`. |
| `output_format` | optional (default `markdown`) | Comma-separated Firecrawl content formats, e.g. `markdown` or `markdown,html` -- one output column per format. |
| `only_main_content` | optional (default `true`) | Strip boilerplate (nav/ads/footers) from scraped content. |
| `strip_boilerplate` | optional (default `true`) | On top of `only_main_content`, drop lines that repeat across most of this run's pages. |
| `poll_interval_seconds` | optional (default `5`) | Seconds between status checks for a `crawl_url` job. |
| `poll_timeout_seconds` | optional (default `600`) | Max seconds to wait for a `crawl_url` job to complete. |

At least one of `urls` / `crawl_url` is required -- enforced at config-resolution time, not just at runtime.

## Output shape

One row per scraped page: `url`, `title`, `scraped_at` (ISO timestamp), plus one column per requested `output_format` (just `markdown` by default). Point `document_chunker`'s `upstream_asset_key` at this asset, `source_column` at `markdown`, and (optionally) `metadata_columns` at `url,title,scraped_at`.

## Re-running without duplicating pages

`write_disposition` (default `"replace"`) controls what a rerun does to the destination table: `"replace"` (default) makes each run's scrape fully replace the table -- the right default, since dlt's own default (`"append"`) has no notion of a previous scrape's pages going stale and keeps adding another full copy of every page on top of the last. `"merge"` upserts keyed on `doc_id` (the page URL) instead, keeping pages from a prior run this run didn't re-scrape. `"append"` is the old behavior, kept as an explicit opt-in for a deliberate historical log of every scrape.

As a safety net independent of `write_disposition`, the returned DataFrame is always deduplicated by `doc_id`, keeping the row with the latest `updated_at` -- this catches stale rows regardless of mode. Run metadata reports `write_disposition`, `load_id`, `pages_scraped`, `rows_returned` (the deduplicated row count), and `duplicate_rows_removed`.

## Example
```yaml
type: dagster_community_components.FirecrawlIngestionComponent
attributes:
  asset_name: firecrawl_docs
  crawl_url: "https://docs.example.com"
  crawl_limit: 200
```

To scrape specific pages instead of crawling a whole site:
```yaml
type: dagster_community_components.FirecrawlIngestionComponent
attributes:
  asset_name: firecrawl_pages
  urls: "https://example.com/page-1,https://example.com/page-2"
```
