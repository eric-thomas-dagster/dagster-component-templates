# Freshsales (Freshworks CRM) Ingestion

Ingest Freshsales (the CRM/sales product in the Freshworks suite) contact, lead, deal, and sales-account data using dlt's generic REST API source.

Uses dlt's generic REST API source (`dlt.sources.rest_api.rest_api_source`).

By default, runs an in-memory DuckDB pipeline and returns a pandas DataFrame. Set `destination` to persist directly to any dlt-supported destination. See `../DESTINATIONS.md`.

> **Naming note -- Freshworks vs. Freshdesk vs. Freshsales vs. Freshservice:** "Freshworks" is the parent company; Freshdesk (support ticketing), Freshservice (IT service management), and Freshsales (CRM/sales) are separate product lines, each with its own API and subdomain. This repo already ships `freshdesk_ingestion` (built on dlt's verified `freshdesk` source package) and `freshservice_ingestion`. Before building this component, both siblings were checked (`grep -ril freshworks assets/` / `grep -ril freshdesk assets/`) to confirm Freshsales -- the CRM/sales-intelligence product -- was the one genuinely missing, rather than duplicating existing coverage.

> **Verified against developer.freshsales.io and cross-checked against third-party integration guides** (Freshworks' docs have moved around under the brand unification, so this was corroborated across multiple independent sources):
> - **Base URL**: `https://<domain>.myfreshworks.com/crm/sales/api`, where `<domain>` is your Freshworks tenant subdomain. Older tenants may still resolve at `https://<domain>.freshsales.io/api` (the pre-unification domain) -- this connector targets the current `myfreshworks.com` form.
> - **Auth**: `Authorization: Token token=<api_key>`. This is neither a bearer token nor HTTP Basic auth -- the literal string `Token token=` is part of the header value, and the full string is sent as-is. The API key is generated per-user under Settings -> API Settings in the Freshsales UI.
> - **`contacts`** -> `GET /contacts` (`data_selector: "contacts"`).
> - **`leads`** -> `GET /leads` (`data_selector: "leads"`).
> - **`deals`** -> `GET /deals` (`data_selector: "deals"`).
> - **`sales_accounts`** -> `GET /sales_accounts` (`data_selector: "sales_accounts"`), company/account records.
> - Freshsales' default page size is 25 records. This connector does not configure a custom dlt paginator (consistent with this repo's other generic-REST connectors) -- see the pagination caveat below.

> **Pagination honesty note:** this connector relies on dlt's default REST client behavior rather than a hand-configured page-number paginator. For resources with more than one page of results, you may need to extend `_build_resources_config` in `component.py` with an explicit `paginator` block (dlt supports `page_number` paginators keyed off Freshsales' `page` query param) to fetch beyond the first page. This mirrors the same honesty note already present on this repo's other no-dlt-verified-source connectors (e.g. `chargify_ingestion`, `reclaim_ingestion`).

> **Partition honesty note:** if you set `partition_type`, it controls Dagster's materialization/backfill schedule only. This connector's compute function does not use the partition key to filter the API request, so every partition run re-fetches the same full resource set rather than a bounded window.

## Configuration

| Field | Required | Description |
|---|---|---|
| `asset_name` | required | Name of the asset that will hold the data |
| `domain` | required | Freshworks subdomain (for `<domain>.myfreshworks.com`). |
| `api_key` | required | Freshsales API key, sent as `Authorization: Token token=<api_key>` (generated under Settings -> API Settings). |
| `resources` | optional | Comma-separated list of resources to extract: contacts, leads, deals, sales_accounts. Default: `contacts,leads,deals,sales_accounts` |

