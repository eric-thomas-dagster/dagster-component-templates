# Google Drive Documents

Extract RAG-ready document rows from **every file** in a Google Drive folder, any type, via a service account.

This repo already has two narrower Google Drive components:

- [`google_docs_extractor`](../google_docs_extractor/README.md) — native Google Docs ONLY.
- [`google_drive_ingestion`](../google_drive_ingestion/README.md) — lists any file type and optionally downloads it, but explicitly skips native Google formats (Docs/Sheets/Slides) and only extracts a subset of binary formats into a raw file-listing shape (not the document-source contract).

`google_drive_documents` fills the gap: point it at a folder and get back one row per file — PDFs, Google Sheets, Google Slides, Google Docs, uploaded `.docx`/`.pptx`/`.xlsx`/images/etc — all shaped as the same document-source contract every RAG ingestion component in this repo produces (`doc_id`/`content`/`title`/`url`/`source_type`/`updated_at`/`content_hash`), ready for `document_chunker` downstream.

## How each file type is handled

| File type | Mechanism | Export/extraction |
|---|---|---|
| Google Doc | `files().export(mimeType='text/plain')` | plain text |
| Google Slides | `files().export(mimeType='text/plain')` | plain text |
| Google Sheet | `files().export(mimeType='text/csv')` | CSV (Drive API exports the **first sheet only** for multi-sheet Spreadsheets — a documented Drive API limitation) |
| PDF | `files().get_media()` | pdfplumber |
| `.docx` | `files().get_media()` | python-docx |
| `.html`/`.htm` | `files().get_media()` | BeautifulSoup |
| `.pptx`/`.xlsx`/`.xls`/`.epub`/audio | `files().get_media()` | [markitdown](https://github.com/microsoft/markitdown) |
| everything else | `files().get_media()` | decoded as plain text (fails/skipped if not valid text) |

Drive API's `files().export` has a documented ~10MB cap on exported content; uploaded files are capped separately by `download_max_bytes` (default 10MB) before download.


## Setup gotchas

1. **The folder (or each file) must be shared with the SA email.** Share the Drive folder → paste the SA email (`client_email` in your JSON) → Viewer. Shared-with-SA files inside it inherit access.
2. **Drive API has to be enabled** on the SA's GCP project. If not, the first call returns `403 SERVICE_DISABLED` with the activation URL.
3. **Non-recursive by default.** Set `recursive: true` to walk subfolders too.

## Output schema

| Column | Type | Notes |
|---|---|---|
| `doc_id` | str | Drive file ID |
| `content` | str | Extracted text (export for native formats, extracted text for everything else) |
| `title` | str | File name minus extension |
| `url` | str | `webViewLink` from the Drive listing |
| `source_type` | str | Always `"google_drive"` |
| `updated_at` | str | `modifiedTime` from the Drive listing |
| `content_hash` | str | sha256 of `content` |

A file that fails to export/download/extract, or extracts to empty content, is **dropped** (not emitted as a null-content row) and recorded in the `skipped_files_detail` materialization metadata.

## Example

```yaml
type: dagster_community_components.GoogleDriveDocumentsComponent
attributes:
  asset_name: drive_documents
  credentials_path: ${GOOGLE_APPLICATION_CREDENTIALS}
  drive_folder_id: "1AbCdEfGhIjKlMnOpQrStUvWxYz0123456"
  recursive: false
  description: RAG-ready document rows from every file in a Drive folder
  group_name: documents
```

Drop a `document_chunker` (or any `transform_*`/`llm_*` component) downstream for embeddings / RAG / summarization.
