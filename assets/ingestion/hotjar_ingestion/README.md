# Hotjar Ingestion

Ingest Hotjar (hotjar.com) on-site survey and survey-response data using dlt's generic REST API source.

Uses dlt's generic REST API source (`dlt.sources.rest_api.rest_api_source`).

By default, runs an in-memory DuckDB pipeline and returns a pandas DataFrame. Set `destination` to persist directly to any dlt-supported destination. See `../DESTINATIONS.md`.

> **Verified against Hotjar's real REST API** (`api.hotjar.io/v1`), via Hotjar's help-center API reference and corroborated with a real third-party open-source client (`github.com/yasin749/hotjar-mcp-server`, `src/services/hotjar/hotjar.service.ts` + `src/config/config.ts`), which implements this exact flow against the live API:
> - **Base URL**: `https://api.hotjar.io/v1`.
> - **Auth**: OAuth2 **client_credentials** -- a genuine two-step flow that does NOT fit dlt's built-in simple auth types (bearer / api_key / http_basic) directly:
>   1. Generate a `client_id` + `client_secret` pair in the Hotjar app (Organization Settings -> API).
>   2. `POST https://api.hotjar.io/v1/oauth/token`, `Content-Type: application/x-www-form-urlencoded`, body `grant_type=client_credentials&client_id=...&client_secret=...`. Response: `{"access_token": "...", "expires_in": <seconds>}`.
>   3. `Authorization: Bearer <access_token>` on subsequent calls.
>
>   This component mints the token itself with `requests` (`_mint_hotjar_token`) before building the `rest_api_source` config, then feeds the minted token through as a plain bearer token (`{"type": "bearer", "token": <minted_token>}`). The token is minted fresh on every asset run.
> - Hotjar's API is scoped **per-site**: every path is rooted at `/sites/{site_id}/...`. `site_id` is a required field (find it in the Hotjar app URL at `insights.hotjar.com/sites/{site_id}/surveys/list`).
> - **`surveys`** -> `GET /sites/{site_id}/surveys` -- lists the site's surveys. Cursor-paginated (`limit`/`cursor` params; response shape `{"results": [...], "next_cursor": "..."}`).
> - **`survey_details`** -> `GET /sites/{site_id}/surveys/{survey_id}` -- full metadata (including question definitions) for one survey. A **dependent** resource: issues one request per survey returned by `surveys`, via dlt's `resolve` mechanism.
> - **`survey_responses`** -> `GET /sites/{site_id}/surveys/{survey_id}/responses` -- individual responses to one survey. Also dependent on `surveys` (same `resolve` mechanism), and also cursor-paginated.
> - Requesting `survey_details` or `survey_responses` implicitly also includes `surveys` in the built resource set (dlt needs the parent resource present to resolve against), even if you didn't list it explicitly.

> **Real API limitation (confirmed, not a guess):** Hotjar's heatmap and session-recording data has **no programmatic export path** in the current public API -- only on-site Survey data is exposed for pull-based ingestion (account-side user-deletion/lookup also exists in the API, but that's a destructive write operation, out of scope for a pull-based connector). This component therefore only ingests Survey data; it cannot pull heatmaps or recordings, despite those being Hotjar's most visually prominent product surfaces.

> **Partition honesty note:** if you set `partition_type`, it controls Dagster's materialization/backfill schedule only. This connector's compute function does not use the partition key to filter the API request, so every partition run re-fetches the same full resource set rather than a bounded window.

## Configuration

| Field | Required | Description |
|---|---|---|
| `asset_name` | required | Name of the asset that will hold the data |
| `site_id` | required | Hotjar site ID. Find it in the Hotjar app URL at `insights.hotjar.com/sites/{site_id}/surveys/list`. |
| `client_id` | required | Hotjar API client ID (OAuth2 client_credentials), generated under Organization Settings -> API. |
| `client_secret` | required | Hotjar API client secret, generated alongside `client_id`. |
| `resources` | optional | Comma-separated list of resources to extract: `surveys`, `survey_details`, `survey_responses`. Default: `surveys,survey_responses` |
| `api_limit` | optional | Page size for cursor-paginated list endpoints. Default: `100` |

## Example
```yaml
type: dagster_component_templates.HotjarIngestionComponent
attributes:
  asset_name: hotjar_ingestion
  site_id: "${HOTJAR_SITE_ID}"
  client_id: "${HOTJAR_CLIENT_ID}"
  client_secret: "${HOTJAR_CLIENT_SECRET}"
  resources: "surveys,survey_responses"
```
