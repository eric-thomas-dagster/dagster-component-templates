# Jina Reader Ingestion

Fetch clean markdown for a list of URLs using [Jina AI's Reader API](https://jina.ai/reader/) (`r.jina.ai`) -- a free/low-cost alternative to Firecrawl for turning web pages into clean text for a RAG pipeline.

> **Note:** Verified against Jina's own docs (https://jina.ai/reader/, https://docs.jina.ai/reader, https://github.com/jina-ai/reader). `GET https://r.jina.ai/<target-url>` with `Accept: application/json` returns structured content at `response["data"]["content"]`; auth (`Authorization: Bearer $JINA_API_KEY`) is optional (20 requests/minute without a key vs. 500+ with a free key). This connector is hand-written with a plain `@dlt.resource` generator wrapping the already-fetched rows -- the same approach used for Firecrawl/Dropbox/monday.com elsewhere in this repo -- so destination flexibility, hash_columns, on_schema_change, exclude_columns, and max_rows_per_resource all still work identically to every other ingestion component.

Jina Reader has no multi-table concept: one run produces a flat set of fetched pages, one row per URL, so there is no `asset_shape`/multi_asset option here.

By default, runs an in-memory DuckDB pipeline and returns a pandas DataFrame. Set `destination` to persist directly to any dlt-supported destination. See `../DESTINATIONS.md`.

## Configuration

| Field | Required | Description |
|---|---|---|
| `asset_name` | required | Name of the asset that will hold the data |
| `urls` | required | Comma-separated list of URLs to fetch via Jina Reader. |
| `api_key_env_var` | optional (default `JINA_API_KEY`) | Env var holding your Jina API key. Auth is optional -- leave unset (or point at an unset env var) to fetch anonymously at a lower rate limit. |
| `target_selector` | optional | CSS selector (`X-Target-Selector`) -- return content within the matched element only. |
| `wait_for_selector` | optional | CSS selector (`X-Wait-For-Selector`) -- wait for this element to render before extracting (JS-rendered pages). |
| `request_timeout_seconds` | optional | `X-Timeout` header, integer seconds (Jina caps this at 180). |
| `with_generated_alt` | optional (default `false`) | `X-With-Generated-Alt` header -- caption images lacking alt text. |

## Output shape

One row per requested URL: `url`, `title`, `text` (the page's clean markdown -- named `text` rather than `markdown` so it lines up with `document_chunker`'s default `source_column='text'` with zero extra config), `fetched_at` (ISO timestamp), `error` (`None` on success; the exception message on a per-URL fetch failure). A failure fetching one URL never fails the whole run -- it's recorded as a row with `error` set and `text`/`title` null. Point `document_chunker`'s `upstream_asset_key` at this asset and `metadata_columns` at `url,title,fetched_at` to carry them through chunking.

## Re-running without duplicating pages

`write_disposition` (default `"replace"`) controls what a rerun does to the destination table: `"replace"` (default) makes each run's fetch fully replace the table. This component previously hard-coded dlt's own `"append"` default, which has no notion of a previous run's pages going stale -- every re-run kept adding another full copy of every page on top of the last (row_count doubled on every rerun of the same URLs). `"merge"` upserts keyed on `doc_id` (the page URL) instead, keeping pages from a prior run this run didn't re-fetch. `"append"` is the old behavior, kept as an explicit opt-in for a deliberate historical log of every fetch.

As a safety net independent of `write_disposition`, the returned DataFrame is always deduplicated by `doc_id`, keeping the row with the latest `updated_at` -- this catches stale rows regardless of mode. Run metadata reports `write_disposition`, `load_id`, `rows_returned` (the deduplicated row count), and `duplicate_rows_removed`.

## Example
```yaml
type: dagster_community_components.JinaReaderIngestionComponent
attributes:
  asset_name: jina_reader_ingestion
  urls: "https://docs.dagster.io,https://jina.ai/reader"
```

With an API key for a higher rate limit:
```yaml
type: dagster_community_components.JinaReaderIngestionComponent
attributes:
  asset_name: jina_reader_docs
  urls: "https://example.com/page-1,https://example.com/page-2"
  api_key_env_var: JINA_API_KEY
```
