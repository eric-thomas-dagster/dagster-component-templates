# Kustomer Conversations Ingestion

Fetch Kustomer conversations via the Search API and materialize the result as a pandas DataFrame.

Uses:
- `POST /v1/customers/search` with `"queryContext": "conversation"` — Kustomer's best-documented
  way to bulk list/filter Conversations. Paginated via integer `page` / `pageSize` (not a cursor).

## Installation

```bash
pip install requests pandas
```

Also requires a `KustomerResourceComponent` on the same code location for authentication (see
`resources/kustomer_resource`).

## Output Schema

Kustomer's REST responses are JSON:API-ish: `data` is an array of `{id, type, attributes,
relationships}` objects rather than flat records. This component flattens each object's
`attributes` into a DataFrame row and adds back `id` and `type` as columns, so the DataFrame reads
like a normal flat table of conversation fields (`conversation_created_at`,
`conversation_status`, etc. -- exact field names depend on your Kustomer instance's data model).

## Kustomer API notes

- There is no single well-documented `GET /v1/conversations` "list everything" endpoint with a
  documented date-range filter. The best-documented bulk mechanism is the **Search API**
  (`POST /v1/customers/search`), which returns Conversations instead of Customers when
  `"queryContext": "conversation"` is set and every filter field is prefixed with
  `conversation_` (e.g. `conversation_created_at` instead of `createdAt`).
- Pagination is **integer `page` / `pageSize`**, not a cursor — this component increments `page`
  and stops when a page comes back empty, `limit` is reached, or the `max_pages` safety cap (100
  by default) is hit. Kustomer's Search API has a documented hard cap of ~10,000 total results
  (100 pages × 100 per page); raise `max_pages` only if you also raise `page_size`.
- Auth is `Authorization: Bearer <api_key>` against your org-scoped base URL
  (`https://<org_subdomain>.api.kustomerapp.com`).
- Kustomer's docs for this endpoint are JS-rendered and were not fully crawlable during research;
  the request/response shape here follows the documented `conversation_*`-prefixed filter
  convention and the general JSON:API response shape used across Kustomer's REST API. Validate the
  exact filter operator names (`gte`/`lt` used here) against your account before relying on this
  in production, and promote this component's `validation.level` once confirmed against a live org.
