# Lattice Ingestion

Ingest Lattice performance-management, OKR/goal, and engagement data using dlt's generic REST API source.

Uses dlt's generic REST API source (`dlt.sources.rest_api.rest_api_source`).

By default, runs an in-memory DuckDB pipeline and returns a pandas DataFrame. Set `destination` to persist directly to any dlt-supported destination. See `../DESTINATIONS.md`.

> **PII note:** HR data. `users`, `updates`, and `reviews` all carry employee-identifying data (name, email, manager, performance-review content, check-in/feedback text) -- handle destinations and retention accordingly.

> **Pagination honesty note:** Lattice's list endpoints are cursor-paginated (`{"object": "list", "hasMore": bool, "endingCursor": ..., "data": [...]}`, next page via `startingAfter=<endingCursor>`). This connector relies on dlt's default paginator auto-detection rather than configuring an explicit paginator -- check your actual response if a resource under-paginates.

> **Scope note:** this targets Lattice's performance/engagement "Talent API" (`v1`) -- `users`, `goals`, `updates`, `reviews`. A separate `v2` "HRIS API" covers core-HR data and is not covered by this component.

## Configuration

| Field | Required | Description |
|---|---|---|
| `asset_name` | required | Name of the asset that will hold the data |
| `api_key` | required | Lattice API key (Bearer token), generated at Admin > Platform > API keys in the Lattice admin UI. Shown in full only once at creation -- store it securely, there is no way to re-reveal it afterward. |
| `resources` | optional | Comma-separated list of resources to extract: users, goals, updates, reviews. Default: `users,goals,updates,reviews` |
