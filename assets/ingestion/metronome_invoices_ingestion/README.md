# Metronome Invoices Ingestion

Fetch Metronome customers and their invoices via the Metronome billing API and materialize the result as a pandas DataFrame (one row per invoice) -- the pull-side sibling of `metronome_usage_event_send`, for finance reporting on the invoices usage events eventually produce.

Uses:
- `GET /v1/customers` -- paginated list of customers (used when `customer_ids` is unset)
- `GET /v1/customers/{customer_id}/invoices` -- paginated list of a customer's invoices, with `status` / `starting_on` / `ending_before` filters

## Installation

```bash
pip install requests pandas
```

Also requires a `MetronomeResourceComponent` on the same code location for authentication (see `resources/metronome_resource`).

## Configuration

```yaml
type: dagster_community_components.MetronomeInvoicesIngestionComponent
attributes:
  asset_name: metronome_invoices
  resource_key: metronome_resource
  invoice_status: FINALIZED
  starting_on: "2026-01-01T00:00:00.000Z"
  ending_before: "2026-07-01T00:00:00.000Z"
```

## Output schema

One row per invoice, with Metronome's header-level invoice fields (`id`, `status`, `total`, `subtotal`, `issued_at`, `start_timestamp`, `end_timestamp`, `contract_id`, `customer_id`, ...) plus a nested `line_items` column (list of per-line dicts: `name`, `type`, `quantity`, `unit_price`, `total`, `product_id`, ...). Explode `line_items` downstream if you need line-item-level granularity.

## Metronome API notes

- Both `/customers` and `/customers/{id}/invoices` share the same pagination envelope: `{"data": [...], "next_page": "<cursor-or-null>"}`. This component follows `next_page` until it's null/absent.
- When `customer_ids` is unset, every customer in the account is listed first (optionally capped via `max_customers`), then invoices are fetched per customer -- a large account means a large number of requests; set `customer_ids` explicitly to scope a run.
- Auth: `MetronomeResource`'s static Bearer API key (see `resources/metronome_resource`).

## Pairs with

- **`metronome_resource`** -- static Bearer API key auth (required).
- **`metronome_usage_event_send`** -- the reverse-ETL sibling that sends the usage events these invoices are generated from.

## Partitioning

Set `partition_type` (with `partition_start` for time partitions) to partition this asset. On a partitioned run the tokens `{partition_key}`, `{partition_date}`, `{partition_start}` and `{partition_end}` (and `{partition_<dimension>}` for multi-partitions) are substituted into `starting_on`, `ending_before`, so each partition reads its own slice. Unpartitioned runs use the value as written.
