# Monday.com Board Items Ingestion

Fetch Items from a monday.com board via its GraphQL API and materialize the result as a pandas DataFrame.

Uses:
- `boards(ids: [$boardId]) { items_page(limit: ...) { cursor items { ... } } }` — first page
- `next_items_page(cursor: $cursor, limit: ...)` — a **separate top-level field**, not a repeat of the `boards` query, for every subsequent page

> **Note on scope:** this repo also has a pre-existing `monday_ingestion` component (a dlt-pipeline-based connector supporting boards/items/users generically, with an inline API token field). This component is a distinct, narrower variant that pairs with `resources/monday_resource` (the paired-Resource-component architecture used by `facebook_ads_resource`/`marketo_resource`/etc) and focuses specifically on board Items. If you already use `monday_ingestion`, you likely don't need both — this one exists for projects standardizing on the resource-component pattern.

## Installation

```bash
pip install requests pandas
```

Also requires a `MondayResourceComponent` on the same code location for authentication (see `resources/monday_resource`).

## Output Schema

One row per Item:

- `id`, `name`, `state`, `created_at`, `updated_at`, `group_id`, `group_title`
- Per board column: `column_<id>` (the human-readable `text` value) and `column_<id>_raw` (the raw JSON-encoded `value`, needed for structured column types like people/dates/dropdowns where `text` loses detail)

## monday.com API notes

- Single GraphQL endpoint (`POST https://api.monday.com/v2`), not path-based REST — see `resources/monday_resource` for the request shape and the required `API-Version` header.
- Pagination is cursor-based, but **the cursor field changes between the first and subsequent requests**: the first page comes from `boards(ids: [...]) { items_page { cursor, items } }`; every page after that comes from the independent top-level `next_items_page(cursor: ..., limit: ...)` field — NOT another `boards` query. This component handles that switch internally.
- Each cursor is valid for 60 minutes from the *initial* request, not from the last page fetched — don't let a backfill of many boards run long enough to let an in-flight cursor expire.
- `items_page`/`next_items_page` return at most 500 items per call; `page_size` is capped accordingly.
