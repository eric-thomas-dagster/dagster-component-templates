# mParticle Ingestion

Ingest mParticle CDP audience and calculated-attribute data using dlt's generic REST API source.

Uses dlt's generic REST API source (`dlt.sources.rest_api.rest_api_source`).

By default, runs an in-memory DuckDB pipeline and returns a pandas DataFrame. Set `destination` to persist directly to any dlt-supported destination. See `../DESTINATIONS.md`.

> **Verified against mParticle's primary docs** (docs.mparticle.com):
> - **Auth**: OAuth 2.0 Client Credentials (confirmed on the Platform API Overview page). `POST https://sso.auth.mparticle.com/oauth/token` with a JSON body of `client_id`, `client_secret`, `audience: "https://api.mparticle.com"`, `grant_type: "client_credentials"` returns an `access_token` used as `Authorization: Bearer <access_token>`. This is a meaningfully different auth shape than a static API key -- this connector mints the token via an inline pre-auth POST inside the asset body (the same pattern already used by `quickbooks_ingestion`'s refresh-token exchange in this repo), then feeds the resulting bearer token into the dlt rest_api_source config.
> - **Base host**: `https://api.mparticle.com` -- with a real, confirmed quirk: different "Platform API" resource groups live under **different version prefixes on the same host**, not one unified prefix. The Audiences pages document `GET /v1/audiences` and `GET /v1/workspace/{workspaceId}/audiences`, both requiring an `accountId` query param. The Calculated Attributes page explicitly states its resource group "is only accessible at `https://api.mparticle.com/platform/v2`, and does not require the `?accountId` query string parameter" -- a different prefix, no accountId. This connector gives each resource its own full relative path rather than forcing one shared prefix, matching what the real API does.
> - **`audiences`** -> `GET /v1/audiences?accountId={account_id}` -- all audiences visible to the account.
> - **`workspace_audiences`** -> `GET /v1/workspace/{workspace_id}/audiences?accountId={account_id}` -- audiences scoped to one workspace. Only emitted if `workspace_id` is set.
> - **`calculated_attributes`** -> `GET /platform/v2/workspaces/{workspace_id}/calculatedattributes` -- calculated-attribute definitions for a workspace. Only emitted if `workspace_id` is set (no accountId param, per the real docs quirk above).

> **Partition honesty note:** if you set `partition_type`, it controls Dagster's materialization/backfill schedule only. This connector's compute function does not use the partition key to filter the API request, so every partition run re-fetches the same full resource set rather than a bounded window.

## Configuration

| Field | Required | Description |
|---|---|---|
| `asset_name` | required | Name of the asset that will hold the data |
| `account_id` | required | mParticle numeric account ID (accountId query param). |
| `client_id` | required | mParticle API Credential client ID. |
| `client_secret` | required | mParticle API Credential client secret. |
| `workspace_id` | optional | mParticle workspace ID. Required for workspace_audiences / calculated_attributes. |
| `resources` | optional | Comma-separated list: audiences, workspace_audiences, calculated_attributes. Default: `audiences` |

```yaml
  account_id: "123456"
  client_id: "${MPARTICLE_CLIENT_ID}"
  client_secret: "${MPARTICLE_CLIENT_SECRET}"
  resources: "audiences"
```
