# Orb Ingestion

Ingest Orb (withorb.com) customer, subscription, and invoice data using dlt's generic REST API source.

Orb (https://www.withorb.com) is a usage-based billing / metering platform. It has no official dlt-maintained verified-source package, so this connector uses the same config-driven REST connector pattern as the ad-platform ingestions and the `chargify_ingestion` sibling in this repo (`dlt.sources.rest_api.rest_api_source`).

By default, runs an in-memory DuckDB pipeline and returns a pandas DataFrame. Set `destination` to persist directly to any dlt-supported destination. See `../DESTINATIONS.md`.

> **API reference (verified against docs.withorb.com, 2026-10):** base URL `https://api.withorb.com/v1`; auth is HTTP bearer (`Authorization: Bearer <api_key>`); endpoints are `GET /customers`, `GET /subscriptions`, `GET /invoices`. Responses follow Orb's standardized pagination envelope (`{"data": [...], "pagination_metadata": {"has_more", "next_cursor"}}`) -- paginated via the `cursor` query param populated from `pagination_metadata.next_cursor`.

> **Scope note:** usage-event ingestion (`POST /events/ingest`) is a write/metering endpoint used to *send* usage data into Orb, not a pull resource -- intentionally out of scope for this ingestion component.

> **Partition honesty note:** if you set `partition_type`, it controls Dagster's materialization/backfill schedule only. This connector's compute function does not use the partition key to filter the API request, so every partition run re-fetches the same full resource set rather than a bounded window.

| Field | Required | Description |
|---|---|---|
| `asset_name` | required | Name of the asset that will hold the data |
| `api_key` | required | Orb API key, sent as an HTTP bearer token (Authorization: Bearer \<api_key\>). |
| `resources` | optional | Comma-separated list of resources to extract: customers, subscriptions, invoices. Default: `customers,subscriptions` |
