# Pardot (Salesforce Account Engagement) Ingestion

Ingest Salesforce Account Engagement (Pardot) prospect, campaign, list, and visitor data using dlt's generic REST API source.

Uses dlt's generic REST API source (`dlt.sources.rest_api.rest_api_source`).

By default, runs an in-memory DuckDB pipeline and returns a pandas DataFrame. Set `destination` to persist directly to any dlt-supported destination. See `../DESTINATIONS.md`.

> **Note on scope**: Pardot ("Account Engagement") is a Salesforce product, but it runs its OWN distinct API, separate from core Salesforce's REST/Bulk API, with a different auth header requirement. This connector is intentionally NOT built on this repo's existing `salesforce_resource`/`salesforce_record_upsert` components -- those authenticate against core Salesforce and know nothing about Pardot's Business Unit Id requirement.

> **Verified against multiple sources that agree on the same shape** (Salesforce's own developer blog on Pardot OAuth setup, plus third-party connector docs from Jitterbit and Cloud Elements):
> - **Auth**: OAuth 2.0 via a Salesforce Connected App -- legacy username/password auth (the old Pardot API key) is no longer accepted. This connector uses the standard `refresh_token` grant (the same pattern already used by `quickbooks_ingestion` in this repo): an inline pre-auth POST to `https://login.salesforce.com/services/oauth2/token` (or `https://test.salesforce.com/services/oauth2/token` for a sandbox org -- set `use_sandbox=true`) returns an `access_token` used as `Authorization: Bearer <access_token>`.
> - **Every** Pardot v5 request additionally requires a `Pardot-Business-Unit-Id: <business_unit_id>` header (an 18-character Salesforce ID beginning with "0Uv"). Omitting it returns a 400 even with a valid access token.
> - **Base URL**: `https://pi.pardot.com/api/v5/` (production) or `https://pi.demo.pardot.com/api/v5/` (sandbox).
> - **`prospects`** -> `GET objects/prospects`
> - **`campaigns`** -> `GET objects/campaigns`
> - **`lists`** -> `GET objects/lists`
> - **`visitors`** -> `GET objects/visitors`
> All four are real v5 JSON REST object-list endpoints (the modern replacement for the deprecated v3/v4 query-parameter API, which this connector does NOT use).

> **Partition honesty note:** if you set `partition_type`, it controls Dagster's materialization/backfill schedule only. This connector's compute function does not use the partition key to filter the API request, so every partition run re-fetches the same full resource set rather than a bounded window.

## Configuration

| Field | Required | Description |
|---|---|---|
| `asset_name` | required | Name of the asset that will hold the data |
| `business_unit_id` | required | Pardot/Account Engagement Business Unit ID. |
| `client_id` | required | Salesforce Connected App Consumer Key. |
| `client_secret` | required | Salesforce Connected App Consumer Secret. |
| `refresh_token` | required | OAuth2 refresh token. |
| `use_sandbox` | optional | Use test.salesforce.com / pi.demo.pardot.com. Default: `false` |
| `resources` | optional | Comma-separated list: prospects, campaigns, lists, visitors. Default: `prospects,campaigns` |

## Example
```yaml
type: dagster_component_templates.PardotIngestionComponent
attributes:
  asset_name: pardot_ingestion
  business_unit_id: "0Uv000000000001AAA"
  client_id: "${PARDOT_CLIENT_ID}"
  client_secret: "${PARDOT_CLIENT_SECRET}"
  refresh_token: "${PARDOT_REFRESH_TOKEN}"
  resources: "prospects,campaigns"
```
