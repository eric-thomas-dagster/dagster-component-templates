# Reclaim.ai Ingestion

Ingest Reclaim.ai (reclaim.ai) AI-scheduling task, calendar event, and Smart Habit data using dlt's generic REST API source.

Uses dlt's generic REST API source (`dlt.sources.rest_api.rest_api_source`).

By default, runs an in-memory DuckDB pipeline and returns a pandas DataFrame. Set `destination` to persist directly to any dlt-supported destination. See `../DESTINATIONS.md`.

> **Verified against the Reclaim.ai OpenAPI spec** (`api.app.reclaim.ai/swagger/reclaim-api-0.1.yml`), cross-checked against the live host and third-party reverse-engineering docs:
> - **Base URL**: `https://api.app.reclaim.ai`. Confirmed three ways: (1) the OpenAPI spec itself is served from this host, (2) an unauthenticated `GET /api/tasks` against this host redirects into a login flow rather than 404ing -- i.e. the route is live and auth-gated, not nonexistent, (3) independent community documentation (the `reclaim-sdk` package, third-party API research writeups) states the same base URL, bearer auth, and a 100 requests/minute rate limit.
> - **Auth**: `Authorization: Bearer <token>` (OpenAPI `Authorization` security scheme).
> - **`tasks`** -> `GET /api/tasks`. The spec marks a `user` query param "required", but it's typed as the full authenticated-principal `User` object -- a generated-OpenAPI artifact of the framework injecting the Bearer-authenticated principal as a method parameter (the pattern is characteristic of Dropwizard/Jersey-style auto-generated specs: `@Auth User user`), not something a client passes explicitly. This connector does not send a `user` param; community reverse-engineering docs document `GET /api/tasks` the same way (no client-supplied `user`).
> - **`events`** -> `GET /api/events/v2`, the modern path (preferred here over the legacy `GET /api/events`, which still exists in the spec). Unlike `/api/events`, `/api/events/v2` requires BOTH `start` and `end` (ISO date) -- there is no "everything" mode. If `event_start_date`/`event_end_date` aren't set, this connector defaults to a 30-day window starting today (UTC).
> - **`habits`** (Smart Series) -> expands to TWO dlt resources: `habits_daily` (`GET /api/assist/habits/daily`) and `habit_templates` (`GET /api/assist/habits/templates`). Both are parameter-free for a basic listing.
> - Reclaim's calendar-connection endpoints (`GET /api/calendars/personal`, `GET /api/calendars/sync`) were verified to exist but are intentionally **not** exposed as a `resources` option here -- they return calendar *connection* metadata, not event/task/habit data, and are out of scope for this connector's resource set.

> **Partition honesty note:** if you set `partition_type`, it controls Dagster's materialization/backfill schedule only. This connector's compute function does not use the partition key to filter the API request, so every partition run re-fetches the same full resource set rather than a bounded window.

## Configuration

| Field | Required | Description |
|---|---|---|
| `asset_name` | required | Name of the asset that will hold the data |
| `api_token` | required | Reclaim.ai API token (Bearer), generated at app.reclaim.ai/settings/developer. |
| `resources` | optional | Comma-separated list of resources to extract: tasks, events, habits. Default: `tasks,events,habits` |
| `event_start_date` | optional | Start date (ISO 'YYYY-MM-DD') for the `events` resource's required `start` param. Defaults to today (UTC). |
| `event_end_date` | optional | End date (ISO 'YYYY-MM-DD') for the `events` resource's required `end` param. Defaults to 30 days from today (UTC). |
