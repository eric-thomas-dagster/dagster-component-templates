# Sage Intacct AR Invoices Ingestion

Fetch Sage Intacct AR Invoice records (the `ARINVOICE` object) via Intacct's legacy XML Web Services `readByQuery` function and materialize the result as a pandas DataFrame.

Uses:
- `readByQuery` — initial page of `ARINVOICE` records matching a query where-clause
- `readMore` (with the `resultId` Intacct returns) — walks subsequent pages until `numremaining == 0`

## Installation

```bash
pip install requests pandas
```

Also requires a `SageIntacctResourceComponent` on the same code location for authentication (see `resources/sage_intacct_resource`).


## Output Schema

The DataFrame contains one row per `ARINVOICE` record with the configured `fields` as columns. By default:

`RECORDNO, INVOICENO, CUSTOMERID, CUSTOMERNAME, WHENCREATED, WHENDUE, WHENPOSTED, TOTALENTERED, TOTALDUE, CURRENCY, STATE, DESCRIPTION`

All values come back as strings (Intacct's XML gateway does not type-annotate response fields) — cast numeric/date columns downstream as needed.

## Sage Intacct API notes

- This hits Intacct's **legacy XML gateway** (`POST https://api.intacct.com/ia/xml/xmlgw.phtml`), not a JSON REST API. See `resources/sage_intacct_resource` for the full request/response envelope shape and the two-layer credential model.
- Query clauses are a single SQL-like where-clause string ANDed from `date_field >= from_date`, `date_field <= to_date`, and `extra_query`, e.g. `"WHENCREATED >= '06/01/2026' AND WHENCREATED <= '07/01/2026' AND (STATE = 'Open')"`.
- Pagination: `readByQuery` returns a `resultId` + `numremaining` on its `<data>` element; this component loops `readMore` with that `resultId` until `numremaining` reaches `0` or `limit` is hit.
- Intacct query date literals are `MM/DD/YYYY`, not ISO-8601 — `from_date`/`to_date` config accepts ISO-8601 and this component converts internally.
