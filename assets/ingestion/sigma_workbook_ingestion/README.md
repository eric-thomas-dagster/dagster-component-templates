# Sigma Workbook Ingestion

Ingest a catalog of Sigma workbooks + their elements via `GET /v2/workbooks` and `GET /v2/workbooks/{workbookId}/elements`, and materialize the result as a pandas DataFrame — one row per (workbook, element) pair.

Uses the `sigma_resource` component for authentication (see `resources/sigma_resource`).

## Installation

```bash
pip install requests pandas
```

Also requires a `SigmaResourceComponent` on the same code location for authentication (see `resources/sigma_resource`).

```yaml
  asset_name: sigma_workbook_catalog

```

## Output schema

One row per (workbook, element):

| Column | Source |
|---|---|
| `workbook_id`, `workbook_name`, `workbook_path`, `workbook_url` | `GET /v2/workbooks` entry |
| `owner_id`, `created_by`, `updated_by`, `created_at`, `updated_at`, `latest_version`, `is_archived` | same — the closest API-exposed audit proxy (see below) |
| `element_id`, `element_name`, `element_type`, `element_columns`, `visualization_type` | `GET /v2/workbooks/{id}/elements` entry |
| `is_input_table` | derived: `element_type == "input-table"` |

If `include_elements: false`, every `element_*` / `is_input_table` field is `null` and you get exactly one row per workbook.

## Finding Input Tables

Set `input_tables_only: true` to get a lean catalog of just the Input Table elements across your org — e.g. to drive a target-discovery step feeding `sigma_input_table_upsert`. This mirrors Sigma's own documented recipe, ["Workbooks: List all Input Tables"](https://help.sigmacomputing.com/recipes/workbooks-list-all-input-tables-javascript), which performs the identical `elements[].type === 'input-table'` filter across every workbook/page.

## Usage/audit data — what's real vs. what isn't

Sigma's REST API does **not** expose per-row audit history (who changed which cell, when) — that's a UI-only feature: ["View input table audit history"](https://help.sigmacomputing.com/docs/view-input-table-audit-history). This component does **not** fabricate that data. The closest API-exposed proxy is workbook-level `created_by` / `updated_by` / `created_at` / `updated_at` / `latest_version`, which are included on every row. If you need real row-level audit trail, that currently requires the Sigma UI (Input Table → row history panel), not this component.

## Partitioning note

Sigma's `List workbooks` endpoint documents no time-range filter parameter. A time-based `partition_type` here therefore only controls **scheduling cadence** — every run still performs a full catalog pass across all workbooks, it does not scope the API call to a time window. Prefer `static` or `dynamic` partition types if you actually want to scope *which* workbooks get cataloged (e.g. by folder/workspace, via a custom sensor that seeds dynamic partitions).

## Pagination

Both `GET /v2/workbooks` and `GET /v2/workbooks/{id}/elements` share the same `entries` / `nextPage` / `total` response shape (confirmed against Sigma's own reference docs) — this component walks `nextPage` until it's null/absent or the relevant limit (`workbook_limit`, or a fixed per-workbook element cap of 10,000) is reached.
