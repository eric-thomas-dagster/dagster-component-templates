# Totango Accounts Ingestion

Fetch Totango Account records via the Totango Search API and materialize the result as a pandas DataFrame.

Uses:
- `POST /api/v1/search/accounts` — paginated account search with configurable `terms`/`fields`

## Installation

```bash
pip install requests pandas
```

Also requires a `TotangoResourceComponent` on the same code location for authentication (see `resources/totango_resource`).

## Configuration

```yaml
type: dagster_component_templates.TotangoAccountsIngestionComponent
attributes:
  asset_name: totango_accounts
  resource_name: totango_resource
  fields: ["name", "display_name", "health", "last_activity_time", "status"]
  count: 1000
  limit: 5000
```

## Output Schema

The DataFrame contains the account fields requested via `fields`, plus Totango's always-returned `name` (account id) and `display_name` (account name).

## Totango API notes

- **Auth header is non-standard**: `Authorization: app-token <token>` (not `Bearer`/Basic). See `resources/totango_resource`.
- **Two regional hosts**: `api.totango.com` (US) vs `api-eu1.totango.com` (EU) — configured on the resource, not per-ingestion.
- **Field names (especially health scores) are org-specific custom attributes** configured per Totango tenant via SuccessBLOCs — confirm your org's actual field names before relying on the default `fields` list.
- **Response is deeply nested**: results live at `response.accounts.hits`, not a top-level `accounts`/`results` key.
- **`offset` is a page number, not a record offset** (page 0 = first page of `count` records) — this component increments `offset` by 1 per page, not by `count`.
- Totango enforces a global rate limit of 100 calls/minute per token.
