# Vitally Accounts Ingestion

Fetch Vitally Accounts (health/NPS data) via Vitally's REST API and materialize the result as a pandas DataFrame.

Uses:
- `GET /resources/accounts` — cursor-paginated list of Accounts

## Installation

```bash
pip install requests pandas
```

Also requires a `VitallyResourceComponent` on the same code location for authentication (see `resources/vitally_resource`).

## Output Schema

The DataFrame contains every field Vitally's `/resources/accounts` returns (account id, name, health score, NPS, traits, etc. — exact shape varies by account configuration).

## Vitally API notes

- **Auth is HTTP Basic** with the API key as username and an empty password — not a Bearer token. See `resources/vitally_resource`.
- **Pagination is cursor-based**: `limit` (max 100) + `from` (opaque cursor echoed back as `next`); loop until `next` is empty or a short page is returned.
- **No server-side date-range filter on Accounts.** Unlike Gong/Gainsight, Vitally's Accounts endpoint has no "modified between X and Y" query parameter — only a `sortBy` ordering hint. This component still exposes the standard `partition_type`/`partition_start`/etc. fields for structural consistency with every other ingestion component in this repo, but a time-based partition only tags each run's metadata; it does **not** narrow the fetched accounts. Every run fetches the full account list (subject to `status`/`limit`). If you need true incremental sync, diff on the `updatedAt` field downstream.
