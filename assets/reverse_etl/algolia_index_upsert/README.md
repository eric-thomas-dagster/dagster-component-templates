# `AlgoliaIndexUpsertComponent`

Reverse-ETL / search-index activation: sync an upstream DataFrame into an
**Algolia index** so warehouse-sourced data (product catalogs, content,
docs) powers site search. Uses Algolia's native batch endpoint:

```
POST https://{app_id}-dsn.algolia.net/1/indexes/{index_name}/batch
{"requests": [{"action": "updateObject"|"deleteObject", "body": {...}}]}
```

Every Algolia record needs an `objectID`. This component takes `id_field`
(an upstream column) and uses its value as that `objectID` -- all other
upstream columns become document fields.

## Operations

| Operation | Algolia action | Behavior |
|---|---|---|
| `upsert` (default) | `updateObject` | Create-or-replace in one call -- no search-then-write. |
| `delete` | `deleteObject` | Remove the record (only `objectID` needed in the body). |

Both go through the same `/batch` endpoint, chunked at 1,000 operations
per HTTP call (matching Algolia's own helper libraries' default chunk size).

## When to use

- Sync a dbt/warehouse product or content catalog mart into Algolia for
  site search ("search-activation" reverse ETL).
- Keep an Algolia index in lockstep with a source-of-truth table (nightly
  or CDC-driven full/partial refresh).
- Suppress/remove records from search (e.g. discontinued products) via
  `operation: delete`.

## Prerequisite: Admin API Key

`AlgoliaResourceComponent`'s `api_key_env_var` must point to an **Admin
API Key** (Dashboard -> Settings -> API Keys) -- the Search-only key
cannot write.

## Pairs with

- `algolia_resource` -- App ID + Admin API Key auth (required)

## Configuration

```yaml
type: dagster_component_templates.AlgoliaIndexUpsertComponent
attributes:
  asset_name: algolia_product_catalog_sync
  upstream_asset_key: dbt_marts_product_catalog
  resource_key: algolia_resource

  index_name: products
  id_field: product_id
  operation: upsert

  batch_size: 50000
  group_name: reverse_etl
```

## Partitioning

When `partition_type` is set, a run sends only the rows in its partition: `partition_date_column` selects the rows whose date falls in a time partition's window (a backfill run covers its whole range) and `partition_static_column` selects the rows for a static/dynamic partition key. Unpartitioned runs send every row.
