# `ClickUpTaskUpsertComponent`

Reverse-ETL: mirror an upstream DataFrame into ClickUp tasks in a target List, create-or-update.

ClickUp has no native "upsert" endpoint for tasks, and (unlike Salesforce's `External ID` fields) no universal field every workspace exposes for an external key. This component uses the same **key-marker** pattern this repo already uses for `github_issue_upsert`: the upstream key is written into the task's `description` as `<!-- dagster-key: <value> -->`, and existing tasks in the target List are paginated and matched against that marker on every run.

Matches → updated (name, description, status, priority, assignees, tags). Misses → created.

## Pairs with

- **`clickup_resource`** — API token connection (personal token or OAuth2 access token, sent raw — no `Bearer ` prefix — matching ClickUp's documented convention and this repo's `clickup_ingestion`).

## Behavior + gotchas

- **Status names must already exist** — ClickUp statuses are per-List/Space configuration; passing a status name not configured on the target List returns an API error for that row (caught, recorded in `first_errors`, does not fail the whole run).
- **Pagination** — existing tasks are listed via `GET /list/{list_id}/task?include_closed=true`, page by page (100/page), stopping at the first short page. A hard cap of 1000 pages guards against runaway pagination on a misconfigured/huge List.
- **`include_closed=true`** — closed/completed tasks are still matched against (so a completed task gets updated, not duplicated), but this component has no equivalent of `github_issue_upsert`'s `close_missing` — removing a row from the upstream DataFrame does not close the corresponding task.
