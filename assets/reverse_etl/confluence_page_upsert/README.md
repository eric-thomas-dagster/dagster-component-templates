# `ConfluencePageUpsertComponent`

Reverse-ETL sink: batch-upsert rows from an upstream DataFrame into **Confluence Cloud pages**, one row per page, matched on `(space_id, title)`. Confluence has no native page-upsert endpoint, so this is a search-then-write pattern: `GET /pages?space-id=..&title=..` to find an existing page, then `PUT` (update) or `POST` (create).

This is the "Shopify / Salesforce shape" -- loop over every upstream row and batch-upsert many pages in one run -- rather than the `notion_page_sync` shape (sync exactly one already-known `page_id` from row 0). Confluence pages are matched by title within a space rather than a pre-known page id, so a realistic sink needs to handle many rows per run.

## Why a separate `confluence_resource`, not `jira_resource`

Confluence and Jira are both Atlassian Cloud products with the same auth mechanics (email + API token, HTTP Basic) and the same site host. This component's resource dependency, `confluence_resource`, is still a fully separate, self-contained component from `jira_resource` -- `JiraResource`'s convenience methods are scoped entirely to Jira's issue endpoints (`/rest/api/3/issue/...`), while Confluence pages live under a different API surface (`/wiki/api/v2/pages`) with different write semantics. See `resources/confluence_resource/README.md` for the full rationale.

## Gotchas

- **Version numbers on update are exact, not best-effort.** Confluence's v2 `PUT /pages/{id}` requires `version.number` to be exactly the page's current version + 1 (optimistic-concurrency protection). This is handled for you inside `ConfluenceResource.upsert_page_by_title` -- it re-fetches the page to read the current version before every update -- but it's worth knowing this is why updates cost 2 API calls (GET then PUT), not 1.
- **Page bodies are "storage format"** (Confluence's XHTML-based wiki markup), not Markdown. By default (`wrap_body_as_html: true`) this component treats `body_column` as plain text and wraps it in escaped `<p>` paragraphs -- safe, but no rich formatting. Set `wrap_body_as_html: false` and supply pre-built storage-format XHTML in `body_column` for tables, macros, or layouts.
- **Title lookups are a single API call**, not a client-side scan: `GET /wiki/api/v2/pages` supports `space-id` + `title` as direct query parameters.
- **Blank titles are skipped, not errored** -- a row with no title can't be matched or created, so it's counted under `rows_skipped_blank_title` rather than failing the whole run.

## Pairs with

- **`confluence_resource`** -- connection + auth + workhorse HTTP (required).
