# `DefaultWorkflowTriggerComponent`

Reverse-ETL sink: fire one [Default](https://default.com) API trigger per row of an upstream DataFrame. Default's API trigger "runs the workflow connected to the API trigger with the submitted form responses" — this is the mechanism for kicking off lead-routing/scheduling/automation workflows from a warehouse-computed row (e.g. one newly-scored lead per row).

Default has no upsert concept for trigger firings — every run fires the workflow again per row. Re-running this on the same data re-fires it (the same caveat as Asana's "no upsert for tasks").

## Real request shape (confirmed, not assumed)

Default's fire-a-trigger endpoint (`POST /v1/triggers/{trigger_id}`) is **not** a flat column→value dict. Its body is:

- `email` (string, **required**) — "The lead being routed. Identity always comes from this field."
- `responses` (object, optional) — form field values keyed by field name.
- `context` (object, optional) — web attribution (utm params, gclid, etc.) — not exposed by this component today.

So this component requires a separate `email_column` for the identity field, in addition to `field_mapping` (upstream column → Default form-field name), which populates `responses`.

## When to use

- A dbt mart scores leads and you want each newly-qualified lead to fire a Default lead-routing workflow.
- A warehouse table of accounts should trigger a scheduling/outreach automation per row.

## Pairs with

- **`default_resource`** — Default API key (Bearer token) auth (required).

## Example

```yaml
type: dagster_component_templates.DefaultWorkflowTriggerComponent
attributes:
  asset_name: default_lead_routing_triggers
  upstream_asset_key: scored_leads
  resource_key: default_resource
  trigger_id: "3fa85f64-5717-4562-b3fc-2c963f66afa6"
  email_column: lead_email
  field_mapping:
    company_name: Company
    deal_size_usd: Deal Size
  group_name: default
```

## Partitioning

When `partition_type` is set, a run sends only the rows in its partition: `partition_date_column` selects the rows whose date falls in a time partition's window (a backfill run covers its whole range) and `partition_static_column` selects the rows for a static/dynamic partition key. Unpartitioned runs send every row.
