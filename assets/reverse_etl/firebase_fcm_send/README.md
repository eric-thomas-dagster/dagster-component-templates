# `FirebaseFcmSendComponent`

## ⚠️ This component SENDS REAL PUSH NOTIFICATIONS — read before you materialize

Unlike the ad-audience reverse-ETL components in this repo (Meta/Google/TikTok/LinkedIn custom-audience upserts), there is **no "upload for later matching" indirection** here. Materializing this asset immediately sends a real push notification, via Firebase Cloud Messaging's live API, to every device token resolved from `recipient_column` — the moment the run executes.

**Before pointing this at a real warehouse segment:**
- Test against a small list of your own test-device tokens first — e.g. `source: {kind: inline, rows: [{fcm_device_token: "..."}]}` with 1-2 rows, or a low `batch_size` against a dev upstream asset.
- Double-check `recipient_column` actually holds the column you think it does — a typo here means real pushes go to the wrong devices.
- This component adds **no rate-limiting or throttling** beyond `batch_size` (a blast-radius cap, not a throughput control) — if you need pacing, that's your responsibility to configure/orchestrate.

Reverse-ETL message activation: send a personalized push notification to each row of an upstream DataFrame via `firebase_admin.messaging.send(message, app=...)` against the `firebase_resource`'s Firebase Admin `App`.

## Why a single `send()` per row, not a bulk call

A single `messaging.send()` per row (rather than `send_each`/a multicast call) is used deliberately: it keeps per-row failure isolation simple — one bad token raises on exactly that row, caught and counted, never aborting the run — and it sidesteps the Firebase Admin Python SDK's bulk-API churn. `send_all`/`send_multicast` were **removed entirely in Python SDK 7.0.0** (2025-07-17) in favor of `send_each`/`send_each_for_multicast`, but a plain per-row `send()` was never deprecated and needs no migration.

## Personalization

`message_template` (body) and `title_template` (title, optional) both support simple `{column_name}` substitution from any other column in the same row:

```yaml
title_template: "You left something behind!"
message_template: "{first_name}, your cart has {item_count} item(s) waiting."
```

A column referenced in a template but missing from the row renders as an empty string rather than failing that row. Omit `title_template` for a body-only notification.

## Per-row failure isolation

One recipient's send failing (unregistered/expired token, etc.) is caught and counted — it does **not** abort the run or the remaining rows. Metadata reports `messages_sent` / `messages_failed` / `rows_skipped_no_recipient` (blank/null recipient values), plus a `first_errors` sample when failures occur.

## When to use

- Send a cart-abandonment or re-engagement push to a warehouse-computed segment.
- Trigger a transactional-style push (order update, appointment reminder) from a dbt mart / Dagster asset.
- Any "send a message to each row" reverse-ETL case where the destination is FCM push rather than an ad platform's audience list.

## Pairs with

- **`firebase_resource`** — Firebase Admin SDK service-account auth (required).
