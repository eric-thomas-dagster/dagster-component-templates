# `FreshserviceTicketUpsertComponent`

Reverse-ETL sink: mirror an upstream DataFrame into **Freshservice tickets** via **search-then-write** — Freshservice (like ServiceNow and Freshdesk) has no single-call native upsert endpoint.

For each upstream row:
1. `GET /api/v2/tickets/filter?query="{key_field}:'{value}'"` — the [Filter Tickets API](https://api.freshservice.com/#filter_tickets), matching on the bare field name.
2. If found → `PUT /api/v2/tickets/{id}` (update).
3. If not found → `POST /api/v2/tickets` (create).

## Freshservice is NOT Freshdesk

Freshservice and Freshdesk are both Freshworks products but have different API shapes:

| | Freshdesk | Freshservice |
|---|---|---|
| Primary object | Contacts | Tickets |
| Match-by-external-id | `unique_external_id` contact filter param (built-in) | No such field on tickets — must go through a custom field + the Filter Tickets API |
| Custom field payload shape | N/A | Nested `custom_fields` object on create/update |
| Custom field filter shape | N/A | Bare field name (no `custom_fields.` prefix, no `cf_` prefix) |

This sink does **not** assume a `unique_external_id` ticket filter shortcut exists — it always goes through `key_field` + `fields_map`.

## `fields_map` prefix convention

`fields_map` maps **source column → Freshservice field**. The Freshservice field name determines where it lands in the request payload:

- **`"custom_fields.<name>"`** (e.g. `"custom_fields.unique_external_id"`) → goes into the nested `custom_fields` sub-object on create/update: `{"subject": "...", "custom_fields": {"unique_external_id": "ABC-123"}}`.
- **Unprefixed** (e.g. `"subject"`, `"description"`, `"email"`, `"priority"`, `"status"`) → a top-level ticket field.

`key_field` must be one of the values in `fields_map` (validated at component build time). If `key_field` carries the `custom_fields.` prefix, it is **stripped** before being used in the Filter Tickets API query — Freshservice's filter syntax addresses custom fields by their raw name directly, never the nested payload path. For example `key_field: custom_fields.unique_external_id` produces the query `unique_external_id:'ABC-123'`, not `custom_fields.unique_external_id:'ABC-123'`.

## When to use

- Sync computed/enriched data (incident correlation ID, SLA risk flag, customer tier) from a warehouse INTO Freshservice tickets so IT agents see it in-context.
- Push alerting-pipeline output into Freshservice as tickets, matched by a stable external correlation ID so re-runs update rather than duplicate.

## Prerequisites

1. **A stable key column** in your upstream data, mapped via `fields_map` to a Freshservice field (built-in or custom) that is also set as `key_field`.
2. If using a custom field as the key, it must already exist on the Freshservice ticket form.

## Pairs with

- **`freshservice_resource`** — HTTP Basic auth `(api_key, "X")` (required).
- **`freshservice_ingestion`** — the READ-side counterpart (dlt-based bulk pull of tickets/requesters/agents/assets).

Together they cover **both directions** of Freshservice data movement.

## Example

```yaml
type: dagster_component_templates.FreshserviceTicketUpsertComponent
attributes:
  asset_name: freshservice_tickets_from_alerts
  upstream_asset_key: alerts_to_tickets
  resource_key: freshservice_resource

  key_field: custom_fields.unique_external_id   # must be in fields_map values
  fields_map:
    alert_id: custom_fields.unique_external_id  # source col → Freshservice field
    title: subject
    details: description
    requester_email: email
    priority: priority
  batch_size: 500
```

## Behavior + gotchas

- **No native upsert** — Freshservice (like Freshdesk and ServiceNow) has no single-call upsert. This sink always does search-then-write.
- **Date custom fields can't be filtered** — the Filter Tickets API does not support querying date-type custom fields. Don't use a date field as `key_field`.
- **Blank vs missing** — `None` / `NaN` values are omitted from the request body (Freshservice keeps its current value); rows whose `key_field` value is null/blank are skipped and counted in `rows_skipped_no_key`.
- **In-run cache** — tickets created earlier in the same run are cached by key value so duplicate upstream rows (or eventual-consistency lag on Freshservice's filter index) don't double-post.
- **key_field must be in fields_map** — the sink validates at build time that `key_field` appears in `fields_map` values. Otherwise the upsert can't propagate the match key onto the ticket.
- **custom_fields prefix** — strip it mentally when thinking about the filter query: the payload uses `custom_fields.<name>`, the filter query uses bare `<name>`. This component does that translation for you.
