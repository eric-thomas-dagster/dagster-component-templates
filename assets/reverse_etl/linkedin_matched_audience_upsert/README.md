# `LinkedInMatchedAudienceUpsertComponent`

Reverse-ETL / audience activation: mirror an upstream DataFrame into an existing **LinkedIn Matched Audiences DMP Segment** via the native `POST /rest/dmpSegments/{id}/users` endpoint, batched via `X-RestLi-Method: BATCH_CREATE` (up to 5,000 elements per request).

This component only **uploads members** — it does not create segments. Create the segment once via LinkedIn Campaign Manager (Account Assets → Matched Audiences → Create Audience → Website/Contact list) or the Marketing API, then pass its ID as `segment_id`. LinkedIn recommends waiting a few seconds after creating a segment before uploading to it.

## Privacy: identifiers are hashed before they leave your infrastructure

LinkedIn never sees plaintext PII. **Email is the only supported identifier type** — LinkedIn's DMP Segment Users API documents `SHA256_EMAIL` / `SHA512_EMAIL` / `GOOGLE_AID` only; there is no phone identifier type, unlike Google Ads, Meta, and TikTok.

Normalization follows LinkedIn's documented email-hashing guideline exactly:
1. Convert to lowercase.
2. Remove **all** whitespace from the address (not just leading/trailing — LinkedIn's guideline is broader than the other three platforms' simple trim).
3. SHA-256, hex-encoded.

## `add` vs `remove`

- **`add`** (default) → LinkedIn `action: ADD` — activation: add matching users to the segment.
- **`remove`** → LinkedIn `action: REMOVE` — suppression: remove matching users, e.g. exclude customers who already converted.

## When to use

- Sync a dbt mart of high-LTV customers into a Matched Audiences segment for targeting B2B campaigns.
- Suppress churned or already-converted customers from retargeting (`operation: remove`).
- Push a warehouse-computed segment (e.g. "active trial users") into an existing LinkedIn contact-list audience.

## API versioning

LinkedIn's REST API requires a `Linkedin-Version` header (format `YYYYMM`) and periodically **sunsets old versions** (~12 months after release — e.g. version `202510` is slated for sunset in October 2026). This is exposed as `linkedin_api_version` rather than hardcoded, so bumping it is a config change, not a code change. Check [LinkedIn's API versioning docs](https://learn.microsoft.com/en-us/linkedin/marketing/versioning) periodically.

## Behavior + gotchas

- **Email only** — `fields_map` must map exactly one column to `email`; any other identifier type (including `phone`) raises at build time, since LinkedIn's API doesn't document one.
- **No API call when every row is skipped** — if no row has a valid email, the component returns early without calling the DMP Segment Users endpoint at all.
- **Whitespace removal is broader than the other three platforms** — LinkedIn's guideline strips all whitespace anywhere in the address, not just leading/trailing. Don't assume the same normalization function works across Google Ads/Meta/TikTok/LinkedIn.
- **Rate limits** — LinkedIn enforces 600 requests/minute per member for this endpoint; very frequent small syncs may get throttled (HTTP 429) without affecting the matched-audience processing SLA.
- **API version sunsets** — see "API versioning" above; a stale `linkedin_api_version` will eventually start failing as LinkedIn retires old versions.
