# `MagentoProductUpsertComponent`

Reverse-ETL sink: mirror an upstream DataFrame into **Magento/Adobe Commerce Products** via the REST API.

## The one real gotcha: `PUT` is update-ONLY, not an upsert

Magento's catalog product REST endpoint has **no native upsert**. `PUT /V1/products/:sku` is **update-only** -- if the SKU in the path doesn't already exist, Magento does not create it; the request errors instead. So this sink always does search-then-write per row:

1. `GET /V1/products/{sku}` -- look up existing product (`None` on 404).
2. If found -> `PUT /V1/products/{sku}` (partial update). The body's `sku` is forced to match the path `sku` -- sending a different SKU in the body than in the path is the single most common Magento REST API footgun.
3. If not found -> `POST /V1/products` with `{"product": {...}}` (new product). Create requires at minimum `sku`, `name`, `price`, and `attribute_set_id` (the resource fills `attribute_set_id` from its own configured default, id `4` on a stock install, if your `fields_map` doesn't supply one). In practice you also want `status` (1=enabled), `visibility` (4=Catalog, Search for a normal standalone product), and `type_id` (`"simple"`) -- omitting these silently creates a disabled/invisible/typeless product.

**SKU is Magento's natural per-store unique merge key** for reverse ETL -- every product has one, and (unlike Shopify's auto-generated `handle`) it's typically assigned explicitly by whatever system of record produced the catalog, making it a stable match key.

## When to use

- Sync a warehouse-side product catalog INTO Magento/Adobe Commerce (from a PIM, a dbt mart, or an authoritative source of truth).
- Push computed pricing (dynamic pricing, promo overrides) into Magento's `price` field as a scheduled job.
- Enable/disable products in bulk by mirroring a computed `status` column.

## Prerequisites

1. **A `MagentoResourceComponent`** registered under the same `resource_key`, configured with `instance_url` and `admin_token_env_var`.
2. The admin/integration token needs write access to the Catalog/Products resource (Admin > System > Integrations -- grant the integration the Catalog resource ACL).

## Pairs with

- **`magento_resource`** -- bearer-token auth + workhorse HTTP client (required).
- **`magento_ingestion`** -- the READ-side counterpart (dlt-based bulk pull).

## Example

```yaml
type: dagster_component_templates.MagentoProductUpsertComponent
attributes:
  asset_name: magento_products_mirror
  upstream_asset_key: catalog_products
  resource_key: magento

  fields_map:
    product_sku: sku              # upstream sku -> Magento sku
    product_name: name
    list_price: price
    is_active: status              # 1=enabled, 2=disabled
    visibility_code: visibility    # 1/2/3/4

  batch_size: 200
```

## Behavior + gotchas

- **SKU required** -- every upstream row must have a value in the column mapped to `sku`; rows with `None` / `NaN` / `""` are skipped and counted in `rows_skipped_no_sku` metadata.
- **Blank vs missing** -- `None` / `NaN` values are omitted from the request body (existing Magento value preserved on update). Non-null values overwrite.
- **Create fields** -- on a true create (SKU not found), the body needs at least `sku`/`name`/`price`/`attribute_set_id`. `attribute_set_id` falls back to the resource's configured default (`4` = "Default" attribute set on a stock install) if your `fields_map` doesn't map it explicitly; the others must come from `fields_map` or the create will fail (Magento 400s on missing required attributes).
- **Update-only PUT, always re-checked** -- this sink never blindly PUTs. It always GETs first (via the resource's `upsert_product_by_sku`) so a SKU that doesn't exist yet gets POSTed instead of erroring against the update-only endpoint.
- **Status / visibility codes** -- `status`: `1`=enabled, `2`=disabled. `visibility`: `1`=Not Visible Individually, `2`=Catalog, `3`=Search, `4`=Catalog, Search (the usual default for a standalone product).
- **Rate limits / transient errors** -- the resource retries on `429` (honoring `Retry-After`) and `5xx` with exponential backoff, up to `max_retries` (default 3).
- **No variant/configurable-product support** -- this sink targets simple products. Configurable products with child SKUs need custom compute using the resource directly.
