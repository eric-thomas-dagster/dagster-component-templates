# `MetaCustomAudienceUpsertComponent`

Reverse-ETL / audience activation: mirror an upstream DataFrame into an existing **Meta (Facebook/Instagram) Custom Audience** via the native `/{custom_audience_id}/users` endpoint (wrapped by the `facebook-business` SDK's `CustomAudience.add_users` / `.remove_users`).

Meta's API takes a `schema` (ordered list of identifier types, e.g. `["EMAIL", "PHONE"]`) and `data` (rows of hashed values positionally aligned with that schema). This component builds that schema once from the distinct identifier types in `fields_map`; a row missing one identifier type still contributes "" at that position (not an omitted column) — only a row missing *every* identifier is skipped entirely.

## Privacy: identifiers are hashed before they leave your infrastructure

Meta never sees plaintext PII. Supported identifier types — map an upstream column to one via `fields_map`:

| Type | Normalization before SHA-256 |
|---|---|
| `email` | trim, lowercase |
| `phone` | strip **everything but digits** — no leading `+`, unlike Google Ads' E.164 convention. Include the country code digits with no symbols, e.g. `"14155552671"` not `"+1 (415) 555-2671"` |

A row can supply more than one identifier across different columns — Meta matches on any identifier present, so supplying more improves match rate.

## `add` vs `remove`

- **`add`** (default) — activation: add matching users to the audience for targeting.
- **`remove`** — suppression: remove matching users, e.g. exclude customers who already converted from further retargeting.

## When to use

- Sync a dbt mart of high-LTV customers into a Custom Audience for lookalike/targeting campaigns.
- Suppress churned or already-converted customers from retargeting (`operation: remove`).
- Push a warehouse-computed segment into an existing remarketing audience.

## Prerequisite: the audience must already exist

This component only **uploads members** — it does not create audiences. Create the Custom Audience once via Meta Ads Manager (Audiences → Create Audience → Custom Audience → Customer list) or the Marketing API, then pass its ID as `custom_audience_id`.

## Pairs with

- **`facebook_ads_resource`** — App/token auth + Facebook Business SDK (required).
- **`facebook_ads_ingestion`** — the READ-side counterpart (campaign/performance data pull).

Together they cover both directions of Meta Ads data movement.

## Behavior + gotchas

- **Phone hashing differs from Google Ads** — Meta wants digits-only (no leading `+`); Google Ads wants E.164 (leading `+`). Using the wrong normalization for a given platform silently produces a hash that will never match — this component gets it right per-platform, but if you're hand-rolling hashes elsewhere, don't copy one platform's format to the other.
- **No API call when every row is skipped** — if no row has a valid identifier, the component returns early without calling the Custom Audience API at all.
- **Positional schema, not sparse columns** — a row missing one identifier type still needs `""` at that schema position, not an omitted value; this component handles that automatically, you don't need to pre-pad your DataFrame.
- **Chunking** — requests are capped at 10,000 rows each, automatically, regardless of `batch_size`.

## Partitioning

When `partition_type` is set, a run sends only the rows in its partition: `partition_date_column` selects the rows whose date falls in a time partition's window (a backfill run covers its whole range) and `partition_static_column` selects the rows for a static/dynamic partition key. Unpartitioned runs send every row.
