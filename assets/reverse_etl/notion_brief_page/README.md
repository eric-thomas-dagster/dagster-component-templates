# `NotionBriefPageComponent`

Create a brand-new, freeform, **multi-section Notion page** under a parent page from a structured dict of fields -- typically the output of an upstream LLM-extraction step. Every materialization creates a NEW page with real heading/paragraph/bulleted-list block content.

## When to use

- You have an upstream asset (e.g. an `agentic_pipeline` `extract` step) that produces a structured dict per run, and you want each run to create its own standalone Notion page -- a "brief," report, or writeup -- not update one fixed page's fields.

## Not this component

This repo has three Notion write components. Pick the one that matches what you're actually doing:

| Component | What it does | What it can't do |
|---|---|---|
| **`notion_brief_page`** (this one) | Creates a **brand-new page** under a parent page every run, with real multi-section block content (headings, paragraphs, bulleted lists) built from a structured dict. | No update-in-place; no database rows. |
| **`notion_page_sync`** | **Update-only** against one fixed, already-existing `page_id` -- patches properties and, at most, replaces the whole body with one markdown blob. | Can't create new pages; no structured multi-section content. |
| **`notion_database_upsert`** | **Flat tabular property-upsert** into a Notion database -- matches rows by key, updates or inserts. | No block/body content at all. |

## Pairs with

- **`notion_resource`** — connection (required).
- **`agentic_pipeline`'s `extract` op** — typical upstream. Its output asset's value is `{"text": ..., "extracted": {...fields...}, "model": ...}`; this component reads the `extracted` sub-key (configurable via `extracted_field`).
- **`context_receipt_store`** — optional provenance recording after a successful page creation.

## How sections work

- Pass `sections` explicitly: a list of `{heading, field, format}`, where `field` names a key in the extracted dict and `format` is `paragraph` (scalar or newline-joined list, under one `heading_2` + one `paragraph` block) or `bulleted_list` (the field's value must be a list; one `bulleted_list_item` block per element).
- Omit `sections` and the component auto-builds one section per remaining key in the extracted dict (bulleted list for list-valued fields, paragraph otherwise), logging which fields it found.
- `markdown_body_field` (default `markdown_body`) is a free-form escape hatch: if that key exists in the extracted dict, its value is appended as a final section via a crude paragraph-per-blank-line split (`\n\n`) -- not a full markdown parser.

## Example

```yaml
type: dagster_community_components.NotionBriefPageComponent
attributes:
  asset_name: prospect_brief_page
  upstream_asset_key: prospect_extract
  resource_key: notion_resource
  parent_page_id: "abc123def456"
  title_template: "Brief: {company_name}"
  sections:
    - heading: Summary
      field: summary
      format: paragraph
    - heading: Key Risks
      field: risks
      format: bulleted_list
  markdown_body_field: markdown_body
  icon_emoji: "📄"
  group_name: notion
```

## Configuration

| Field | Required | Description |
|---|---|---|
| `asset_name` | required | Output Dagster asset name. |
| `upstream_asset_key` | required | Upstream Dagster asset producing the LLM-extraction dict (single upstream only). |
| `extracted_field` | optional (default `extracted`) | Key of the upstream dict holding the structured fields dict. |
| `resource_key` | optional (default `notion_resource`) | Resource key registered by NotionResourceComponent. |
| `parent_page_id` | required | Notion page ID the new page is created under. |
| `title_template` | required | Title template, substituted via `str.replace("{field}", value)` -- not `.format`. |
| `sections` | optional | Explicit section list; omit to auto-build from the extracted dict's keys. |
| `markdown_body_field` | optional (default `markdown_body`) | Key holding free-form markdown appended as a final section. |
| `icon_emoji` | optional | Emoji for the new page's icon. |
| `receipts` | optional | `{resource_key, caller_id, policy_version}` -- records a context_receipt_store receipt after page creation. |
