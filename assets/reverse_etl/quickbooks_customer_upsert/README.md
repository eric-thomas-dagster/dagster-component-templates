# `QuickBooksCustomerUpsertComponent`

Reverse-ETL sink: mirror an upstream DataFrame into **QuickBooks Online Customer** records.

## There is no single-call upsert -- SyncToken makes this a two-step dance

QuickBooks uses **one endpoint for both create and update** — `POST /v3/company/<realmId>/customer` — but which one happens depends entirely on what's in the request body:

- **Create**: body has no `Id` / `SyncToken` → QBO assigns a new Id.
- **Update**: body **must** include the record's current `Id` **and** its current `SyncToken` — QBO's optimistic-concurrency version number. Every successful write increments it; sending a stale `SyncToken` gets the whole request rejected with a 400. `sparse: true` makes the update partial (only the fields you send change) rather than replacing list-type fields wholesale.

The only way to learn a record's current `SyncToken` is to **read it first**. So a real "upsert" from this component's perspective requires, per row:

1. **Query**: `GET /query?query=SELECT * FROM Customer WHERE <lookup_field> = '<value>'` — discovers whether a match exists, and if so, its `Id` + `SyncToken`.
2. **Write**: `POST /customer` — with `Id` + `SyncToken` + `sparse: true` set (update) if a match was found, or without them (create) if not.

**Two API calls per row, always** — there's no way to skip the query step.

## `lookup_field` and nested fields

`lookup_field` (default `DisplayName` — QBO enforces this field's uniqueness per company, making it the conventional match key) **must** be a top-level, non-dotted `fields_map` value, since it's substituted directly into a QBO query WHERE clause.

Other `fields_map` values can use **dotted keys** to build QBO's nested object fields, e.g. `PrimaryEmailAddr.Address` or `PrimaryPhone.FreeFormNumber` → `{"PrimaryEmailAddr": {"Address": ...}}`.

## When to use

- Sync a dbt Customers mart into QuickBooks for invoicing/billing.
- Push warehouse-computed customer attributes (segment, tier) into a QBO custom field.
- Keep QuickBooks Customer records in sync with a CRM or external system of record.

## Pairs with

- **`quickbooks_resource`** — OAuth2 refresh-token auth + `realm_id`-scoped HTTP (required).
- **`quickbooks_ingestion`** — the READ-side counterpart (dlt-based bulk pull); unrelated implementation per this repo's no-shared-logic rule.

## Example

```yaml
type: dagster_component_templates.QuickBooksCustomerUpsertComponent
attributes:
  asset_name: quickbooks_customers_mirror
  upstream_asset_key: dbt_marts_customers
  resource_key: quickbooks

  lookup_field: DisplayName
  fields_map:
    customer_name: DisplayName
    company_name: CompanyName
    email: PrimaryEmailAddr.Address
    phone: PrimaryPhone.FreeFormNumber

  batch_size: 5000
```

## Behavior + gotchas

- **Lookup value required** — rows with `None`/`NaN` in the column mapped to `lookup_field` are skipped and counted in `rows_skipped_no_key`.
- **Query-then-write race** — if the record is modified between the query and the write (e.g. by a human in the QBO UI), the write is rejected with a stale-`SyncToken` 400 and counted in `rows_errored`; it is NOT automatically retried with a re-query. Re-run the asset to pick up the latest state.
- **`sparse: true` always used on update** — only fields present in `fields_map` are changed; fields you don't map are left alone. Set `sparse: false` behavior isn't exposed by this component (sparse updates are the safer default for reverse-ETL use cases).
- **No bulk batching** — `api_requests` metadata is roughly `2 * rows_upserted` (one query + one write per successful row).
- **`DisplayName` quoting in the query** — single quotes in the lookup value are escaped before being embedded in the QBO query string; values containing other SQL-injection-relevant characters should still be sanitized upstream if untrusted.

## Partitioning

When `partition_type` is set, a run sends only the rows in its partition: `partition_date_column` selects the rows whose date falls in a time partition's window (a backfill run covers its whole range) and `partition_static_column` selects the rows for a static/dynamic partition key. Unpartitioned runs send every row.
