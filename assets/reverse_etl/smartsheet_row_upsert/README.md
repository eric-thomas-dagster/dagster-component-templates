# `SmartsheetRowUpsertComponent`

Reverse-ETL sink: mirror an upstream DataFrame into a **Smartsheet sheet**.

## Key behavior: no native upsert, client-side match, 500-row chunking

Unlike Airtable's `performUpsert` or Salesforce's composite upsert, **Smartsheet has no server-side column-match upsert endpoint at all**:

- `POST /2.0/sheets/{sheetId}/rows` always **adds** new rows.
- `PUT /2.0/sheets/{sheetId}/rows` always **updates** existing rows, and **requires each row's numeric `id`** — there is no way to tell the API "update the row where column X equals value Y".

So the matching has to happen client-side. The paired `smartsheet_resource` fetches the sheet **once** (`GET /2.0/sheets/{sheetId}`, which returns both `columns` and the current `rows`), builds a `title → columnId` map, and scans the fetched rows for a cell in `key_column` matching each incoming row's key value — found rows go to PUT, unmatched rows go to POST. This is a single sheet fetch total, not one GET per row, which would be wildly inefficient for anything but a handful of rows.

Both write endpoints cap out at **500 rows per API call**; `add_rows` / `update_rows` chunk automatically at that limit, mirroring the chunked-batch pattern this repo's Salesforce composite-upsert sink uses (just with 500 as the chunk size instead of 200).

## When to use

- Sync computed data (scores, statuses, assignments) from a warehouse INTO a Smartsheet sheet so non-technical teams can view/filter/sort it in Smartsheet's UI.

## Prerequisites

1. **Access token** (personal access token, or an OAuth2 app's token) with write access to the target sheet.
2. **`key_column` must be a Smartsheet column title** present in `fields_map`'s values — it's the Smartsheet-side column being matched on, not an upstream DataFrame column name.
3. Rows with a blank/null value in the upstream column(s) that map to `key_column` are **skipped** (logged, counted in `rows_skipped_blank_key`) — there's no safe way to match or create a row without a key value.

## Pairs with

- **`smartsheet_resource`** — bearer-token auth + sheet/row read-write methods, including the client-side upsert convenience (required).
- **`smartsheet_ingestion`** — the READ-side counterpart (dlt-based bulk pull of sheets/users/reports/rows).

## Example
```yaml
type: dagster_community_components.SmartsheetRowUpsertComponent
attributes:
  asset_name: smartsheet_tasks_mirror
  upstream_asset_key: tasks_seed
  resource_key: smartsheet
  sheet_id: "4583173393803140"
  key_column: "Task ID"
  fields_map:
    task_id: "Task ID"
    name: "Task Name"
    status: Status
  batch_size: 500
```

## Partitioning

When `partition_type` is set, a run sends only the rows in its partition: `partition_date_column` selects the rows whose date falls in a time partition's window (a backfill run covers its whole range) and `partition_static_column` selects the rows for a static/dynamic partition key. Unpartitioned runs send every row.
