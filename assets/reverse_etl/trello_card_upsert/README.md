# `TrelloCardUpsertComponent`

Reverse-ETL: mirror an upstream DataFrame into Trello cards in a target List, create-or-update.

Trello has no native "upsert" endpoint for cards, and no way to set a custom field at card-creation time (Trello's Custom Fields Power-Up can only set values on a card via a separate call *after* it already exists). This component uses the same **key-marker** pattern this repo already uses for `github_issue_upsert` / `clickup_task_upsert`: the upstream key is written into the card's `desc` as `<!-- dagster-key: <value> -->`, and existing cards in the target List are fetched (Trello's `/1/lists/{id}/cards` is not paginated — one call returns the whole list) and matched against that marker on every run.

Matches → updated (name, desc, due, idLabels, closed). Misses → created.

## Pairs with

- **`trello_resource`** — API key + token connection, passed as query-string parameters (Trello has no header-based auth scheme — required).

## Example

```yaml
attributes:
  asset_name: trello_incidents_mirror
  upstream_asset_key: incidents_seed
  resource_key: trello_resource

  list_id: "5f8a1b2c3d4e5f6a7b8c9d0e"
  key_column: incident_id
  name_column: name

  desc_column: description
  due_column: due_date
  id_labels_column: label_ids
  closed_column: is_resolved

  batch_size: 100
  group_name: trello
```

## Behavior + gotchas

- **`id_labels_column` takes label IDs, not names** — Trello labels are per-board, and resolving human-readable names to IDs would require a board-labels lookup this component doesn't do (kept deliberately simple, matching `trello_card_upsert`'s zero-extra-lookup design). Pass the board's label IDs directly (`GET /1/boards/{id}/labels` to find them).
- **No pagination on the match step** — `/1/lists/{list_id}/cards` returns the entire list in one call (Trello's own API doesn't paginate this endpoint); very large lists (thousands of cards) will be slower to scan but won't silently miss matches the way a paginated-and-stopped-early scan could.
- **Moving a card between lists is not supported** — only `idList` on *create* is set; updating an existing card never changes `idList`, so a card doesn't get re-filed if its upstream "list" mapping changes.

## Partitioning

When `partition_type` is set, a run sends only the rows in its partition: `partition_date_column` selects the rows whose date falls in a time partition's window (a backfill run covers its whole range) and `partition_static_column` selects the rows for a static/dynamic partition key. Unpartitioned runs send every row.
