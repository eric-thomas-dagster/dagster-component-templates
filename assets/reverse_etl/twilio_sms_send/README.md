# `TwilioSmsSendComponent`

## ⚠️ This component SENDS REAL TEXT MESSAGES — read before you materialize

Unlike the ad-audience reverse-ETL components in this repo (Meta/Google/TikTok/LinkedIn custom-audience upserts), there is **no "upload for later matching" indirection** here. Materializing this asset immediately sends a real SMS, via Twilio's live API, to every phone number resolved from `recipient_column` — the moment the run executes. Twilio **bills you per message segment** for every send, success or not.

**Before pointing this at a real warehouse segment:**
- Test against a small list of your own test numbers first — e.g. `source: {kind: inline, rows: [{phone: "+1..."}]}` with 1-2 rows, or a low `batch_size` against a dev upstream asset.
- Double-check `recipient_column` actually holds the column you think it does — a typo here means real messages go to the wrong people.
- This component adds **no rate-limiting or throttling** beyond `batch_size` (a blast-radius cap, not a throughput control) — if you need pacing, that's your responsibility to configure/orchestrate.

Reverse-ETL message activation: send a personalized SMS to each row of an upstream DataFrame via `client.messages.create(to=..., from_=..., body=...)` — the `dagster-twilio` package's `TwilioResource.get_client()` returns a real `twilio.rest.Client`.

## Personalization

`message_template` supports simple `{column_name}` substitution from any other column in the same row:

```yaml
message_template: "Hi {first_name}, your order {order_id} just shipped!"
```

A column referenced in the template but missing from the row renders as an empty string rather than failing that row.

## Per-row failure isolation

One recipient's send failing (invalid number, carrier rejection, etc.) is caught and counted — it does **not** abort the run or the remaining rows. Metadata reports `messages_sent` / `messages_failed` / `rows_skipped_no_recipient` (blank/null recipient values), plus a `first_errors` sample when failures occur.

## When to use

- Send a one-time SMS blast to a warehouse-computed segment (e.g. "customers with an order shipped today").
- Trigger a transactional-style SMS (shipping notification, appointment reminder) from a dbt mart / Dagster asset.
- Any "send a message to each row" reverse-ETL case where the destination is Twilio SMS rather than an ad platform's audience list.

## Prerequisite: a provisioned Twilio sending number or Messaging Service

`from_number` must be an E.164 phone number or Messaging Service SID already provisioned in your Twilio account — this component only sends, it does not provision numbers.

## Pairs with

- **`twilio_resource`** — Account SID / Auth Token auth via the `dagster-twilio` package (required).
