# `TypesenseIndexUpsertComponent`

Reverse-ETL / search-index activation: sync an upstream DataFrame into a
**Typesense collection** so warehouse-sourced data (product catalogs,
content, docs) powers site search. Uses Typesense's native Documents
Import endpoint:

```
POST {host}/collections/{collection_name}/documents/import?action=upsert
Content-Type: text/plain
{"id": "...", ...fields...}
{"id": "...", ...fields...}
...
```

Unlike Algolia (`objectID` in the batch body) or OpenSearch (`_id` in a
separate bulk metadata line), **Typesense requires the document ID to be
a string field named `id` inside the document body itself** -- there's no
out-of-band ID slot. This component takes `id_field` (an upstream
column), stringifies its value, and sets it as `id`; the original column
is excluded from the rest of the body to avoid a duplicate key.

## Operations

| Operation | Mechanism | Behavior |
|---|---|---|
| `upsert` (default) | `POST .../documents/import?action=upsert`, batched NDJSON | Create-or-replace per document. |
| `delete` | `DELETE .../documents/{id}`, **one call per row** | Typesense's bulk import endpoint has **no delete mode** -- this is the only way to remove documents by ID. |

Upsert batches are chunked at 1,000 documents per import call; delete
always loops per-document (no batching possible).

## When to use

- Sync a dbt/warehouse product or content catalog mart into Typesense
  for site search ("search-activation" reverse ETL).
- Keep a Typesense Cloud or self-hosted collection in lockstep with a
  source-of-truth table.
- Remove discontinued/stale records from search via `operation: delete`
  (accept the per-row request cost -- there's no bulk alternative).

## Pairs with

- `typesense_resource` -- host + API key auth (required)

## Configuration

```yaml
type: dagster_component_templates.TypesenseIndexUpsertComponent
attributes:
  asset_name: typesense_product_catalog_sync
  upstream_asset_key: dbt_marts_product_catalog
  resource_key: typesense_resource

  collection_name: products
  id_field: product_id
  operation: upsert

  batch_size: 50000
  group_name: reverse_etl
```

## Partitioning

When `partition_type` is set, a run sends only the rows in its partition: `partition_date_column` selects the rows whose date falls in a time partition's window (a backfill run covers its whole range) and `partition_static_column` selects the rows for a static/dynamic partition key. Unpartitioned runs send every row.
