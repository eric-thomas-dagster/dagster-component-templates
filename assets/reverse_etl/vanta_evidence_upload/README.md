# `VantaEvidenceUploadComponent`

Reverse-ETL sink: **upload one evidence file into Vanta** per row of an upstream DataFrame.

This is the WRITE-path sibling of `vanta_controls_ingestion` (read) and `vanta_evidence_response_agent` (LLM narrative drafting) — it pushes externally-produced evidence files INTO Vanta, it does not read control state or draft text.

## How it works

Vanta's "Manage Vanta" API documents evidence as a three-step sequence (confirmed against the [upload-a-document guide](https://developer.vanta.com/docs/guides/upload-a-document) and the [createdocument](https://developer.vanta.com/reference/createdocument) / [uploadfilefordocument](https://developer.vanta.com/reference/uploadfilefordocument) reference pages):

1. `POST /v1/documents` — create a document record to track new evidence.
2. `POST /v1/documents/{documentId}/uploads` — attach the evidence file (`multipart/form-data`, file in the `file` field). The upload stays in **draft** status until submitted.
3. `POST /v1/documents/{documentId}/submit` — submit for review (flips `uploadStatus` to `OK`, visible to auditors).

This component drives that sequence once per upstream row: each row becomes one document (or reuses an existing one via `document_id_column`), gets one file attached, and is optionally submitted (`auto_submit`).

A separate write path exists — creating a *custom evidence request* on an audit (`POST /audits/{auditId}/evidence/custom-evidence-requests`) — but that endpoint asks an auditor/operator to supply evidence later; it has no file-upload step, so it doesn't fit a "push this file into Vanta now" reverse-ETL use case and isn't implemented here.

## Auth / scopes

This component reuses the existing `vanta_resource` (`VantaResourceComponent`) — the same OAuth2 client-credentials resource that `vanta_controls_ingestion` and `vanta_evidence_response_agent` already use. No new auth handling was added.

That said, writing evidence requires more than those two read-only components need. Set the resource's `scope:` field to include write/upload scopes:

```yaml
type: dagster_community_components.VantaResourceComponent
attributes:
  resource_key: vanta_resource
  client_id_env_var: VANTA_CLIENT_ID
  client_secret_env_var: VANTA_CLIENT_SECRET
  scope: "vanta-api.all:read vanta-api.all:write vanta-api.documents:upload"
```

## When to use

- Push externally-generated compliance evidence (access review exports, pen-test reports, policy PDFs, log samples) into Vanta on a schedule, keyed off whatever upstream asset produces that evidence.
- Keep a Vanta document's evidence current without a human manually clicking "Upload" in the UI every renewal cycle.

## Not for

- Reading Vanta controls — use `vanta_controls_ingestion`.
- Drafting the narrative text that explains how a control is met — use `vanta_evidence_response_agent`.
- Asking an auditor to supply evidence later (custom evidence requests) — that's a different Vanta workflow, not implemented here.

## Pairs with

- **`vanta_resource`** — OAuth2 client-credentials auth (required; needs write/upload scopes, see above).
- **`vanta_controls_ingestion`** — the READ-side counterpart for control metadata.
- **`vanta_evidence_response_agent`** — drafts the narrative text that might accompany this evidence.

## File source

Supply exactly one of:

- `file_path_column` — upstream column holding a local filesystem path; the file is read from disk per row.
- `file_content_column` — upstream column holding inline content, **base64-encoded text by convention** (falls back to raw utf-8 bytes if a value isn't valid base64).

## Example
```yaml
type: dagster_component_templates.VantaEvidenceUploadComponent
attributes:
  asset_name: vanta_access_review_evidence
  upstream_asset_key: quarterly_access_review_exports
  resource_key: vanta_resource
  document_name_column: control_title
  evidence_description_column: evidence_summary
  file_path_column: evidence_file_path
  auto_submit: true
  group_name: reverse_etl
```
