# `WooCommerceProductUpsertComponent`

Reverse-ETL sink: mirror an upstream DataFrame into **WooCommerce Products** via the REST API v3. WooCommerce has no native upsert endpoint, so this sink does search-then-write per row:

1. `GET /products?sku=<sku>&per_page=1` — look up existing product.
2. If found → `PUT /products/{id}` (partial update, unchanged fields preserved).
3. If not found → `POST /products` (new product).

**SKU is WooCommerce's natural unique merge key** — it's the field store owners already treat as a stable external identifier (the numeric WooCommerce product `id` is assigned by WooCommerce itself and isn't portable across environments), which makes it the right match key for reverse-ETL.

## Authentication — HTTP Basic auth, not OAuth2

This sink authenticates through `woocommerce_resource`, which uses WooCommerce REST API v3's **HTTP Basic auth** scheme: the consumer key as the username, the consumer secret as the password, sent over HTTPS. This is a static, long-lived credential pair — not an OAuth2 client-credentials / refresh-token flow. See `woocommerce_resource`'s README for the full mechanic and gotchas.

## When to use

- Sync a warehouse-side product catalog INTO WooCommerce Products (from a PIM, a dbt mart, or an authoritative source of truth).
- Push computed pricing (dynamic pricing, promo overrides) into WooCommerce's `regular_price` / `sale_price` fields.
- Mirror inventory counts computed elsewhere into WooCommerce's `stock_quantity` field.

## Prerequisites

1. **A WooCommerce REST API key with Write permission** — WooCommerce Admin -> Settings -> Advanced -> REST API -> Add key.
2. **Consumer key + consumer secret** — copied into env vars at key-creation time (WooCommerce only shows the secret once).
3. A `woocommerce_resource` component registered under the same `resource_key` this sink references.

## Pairs with

- **`woocommerce_resource`** — consumer key/secret (HTTP Basic auth) + workhorse HTTP client (required).
- **`woocommerce_ingestion`** — the READ-side counterpart (dlt-based bulk pull).

## Example

```yaml
type: dagster_component_templates.WooCommerceProductUpsertComponent
attributes:
  asset_name: woocommerce_products_mirror
  upstream_asset_key: catalog_products
  resource_key: woocommerce

  fields_map:
    product_sku: sku              # upstream sku → WooCommerce sku (match key)
    product_name: name
    product_description: description
    price: regular_price
    stock_quantity: stock_quantity

  batch_size: 200
```

## Behavior + gotchas

- **SKU required** — every upstream row must have a value in the column mapped to `sku`; rows with `None` / `NaN` / `""` are skipped and counted in `rows_skipped_no_sku` metadata.
- **Blank vs missing** — `None` / `NaN` values are omitted from the request body (existing WooCommerce value preserved). Non-null values overwrite.
- **In-run cache** — if two upstream rows share the same SKU, the sink caches the product id created on the first occurrence and PATCHes it on the second (no double-post).
- **Rate limits** — the resource retries on `429` honoring `Retry-After`, and on `5xx`, up to `max_retries` (default 3) with exponential backoff.
- **Soft deletes** — out of scope for this sink (it only creates/updates); use the resource's `delete_product(force=True)` directly for hard deletes from custom asset code.
- **Bulk fast-path** — `woocommerce_resource.batch_products(...)` wraps `POST /products/batch` for callers that need higher throughput than this sink's default per-row path; this sink intentionally stays simple/per-row for consistency with every other sink in this repo.
