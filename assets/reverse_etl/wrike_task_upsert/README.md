# `WrikeTaskUpsertComponent`

Reverse-ETL: mirror an upstream DataFrame into Wrike tasks in a target Folder, create-or-update.

Wrike has no native "upsert" endpoint for tasks, and matching on a Wrike custom field would require a per-account custom field ID to already be set up (an extra manual step this component avoids). Instead it uses the same **key-marker** pattern this repo already uses for `github_issue_upsert` / `clickup_task_upsert` / `trello_card_upsert`: the upstream key is written into the task's `description` as `<!-- dagster-key: <value> -->`, and existing tasks in the target folder are listed and matched against that marker on every run.

Matches → updated (title, description, status, importance, due date). Misses → created.

Wrike wraps every API response — even single-record create/update calls — in `{"kind": ..., "data": [...]}`; this component unwraps that consistently.

## Pairs with

- **`wrike_resource`** — Bearer token connection (permanent access token from Apps & Integrations → API — required).

## Example

```yaml
type: dagster_component_templates.WrikeTaskUpsertComponent
attributes:
  asset_name: wrike_incidents_mirror
  upstream_asset_key: incidents_seed
  resource_key: wrike_resource

  folder_id: "IEAABBCC123456"
  key_column: incident_id
  title_column: name

  description_column: description
  status_column: status
  importance_column: severity
  due_date_column: due_date

  batch_size: 100
  group_name: wrike
```

## Behavior + gotchas

- **Status/importance are a closed vocabulary** — Wrike only accepts `Active`/`Completed`/`Deferred`/`Cancelled` for status and `High`/`Normal`/`Low` for importance. An unrecognized value is logged as a warning and that field is simply omitted from the write (not a hard failure for the row).
- **No pagination on the match step** — tasks are listed via one `GET /folders/{folder_id}/tasks` call (matching `wrike_ingestion`'s own single-fetch convention); very large folders may need a different approach.
- **No delete/archive support** — removing a row from the upstream DataFrame does not cancel or archive the corresponding Wrike task.
