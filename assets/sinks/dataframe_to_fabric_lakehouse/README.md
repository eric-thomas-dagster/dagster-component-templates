# DataFrame → Microsoft Fabric Lakehouse

Write a DataFrame to a Microsoft Fabric Lakehouse table as Delta on
OneLake. Tables auto-register in the Fabric SQL endpoint, so once written
they're queryable from Fabric Data Warehouse + Power BI + any T-SQL
client without additional setup.

## OneLake URL

The component constructs the abfss URL automatically:

```
abfss://<workspace_id>@onelake.dfs.fabric.microsoft.com/<lakehouse>.Lakehouse/Tables/<table>
```

You provide `workspace_id`, `lakehouse_name`, `table_name` — the rest is
derived.

## Auth

With service principal env vars set, writes authenticate with
`azure_tenant_id`/`azure_client_id`/`azure_client_secret`. Without them, the
default sends an **empty** `storage_options` dict to delta-rs, letting
`object_store`'s own default Azure credential resolution run (can include
managed identity in Azure compute) rather than forcing CLI-only auth. Set
`use_azure_cli: true` to force Azure CLI auth instead — local dev only
(needs an interactive `az login` session); it fails outright in CI or a
Dagster+ agent, so leave it `false` anywhere without an interactive session.

## Partitioning

When `partition_type` is set, each run processes only the upstream rows in its partition: `partition_date_column` selects the rows whose date falls in a time partition's window (a backfill run covers its whole range), and `partition_static_column` (with `partition_static_dim` for multi-partitions) selects the rows for a static/dynamic partition key. Unpartitioned runs process every row.
