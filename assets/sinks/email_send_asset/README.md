# Email Send Asset Component

Send one email as a Dagster asset materialization — a mid-chain notification step (the shape of RunMyJobs' `System_Mail_Send`: To, Subject, Text, JobFile), not a bulk per-row campaign tool. Use [`smtp_send_asset`](../smtp_send_asset/) for that instead (per-row/digest modes, templating, `max_send` caps).

Goes through an already-registered [`smtp_resource`](../../../resources/smtp_resource/) or [`sendgrid_resource`](../../../resources/sendgrid_resource/) — this is the first component in this repo that actually calls either resource's registered `send_email(...)`, rather than reimplementing SMTP from scratch the way `smtp_send_asset` and `email_approval_gate` both do.

## SMTP

```yaml
type: dagster_community_components.EmailSendAssetComponent
attributes:
  asset_key: notifications/nightly_close_complete
  provider: smtp
  resource_key: smtp_resource   # registered via SMTPResourceComponent
  to: [ops-team@example.com]
  subject: "Nightly close complete"
  body: "The nightly close chain finished successfully."
  deps: [sap/nightly_close]
```

`from_addr` defaults to the resource's own configured username when unset.

## SendGrid

```yaml
type: dagster_community_components.EmailSendAssetComponent
attributes:
  asset_key: notifications/report_ready
  provider: sendgrid
  resource_key: sendgrid   # registered via SendGridResourceComponent
  from_addr: reports@example.com   # required -- SendGrid has no default sender
  to: [finance@example.com]
  cc: [controller@example.com]
  subject: "Monthly report"
  body: "See attached."
  attachment_paths: ["/data/out/monthly_report.csv"]
```

SendGrid's `send_email` wraps its real `POST /v3/mail/send` transactional endpoint (not the Marketing contacts API `upsert_contacts_bulk` already uses) — not the same thing as `sendgrid_contact_upsert`, which manages bulk marketing contacts, not transactional sends.

## Attachments, HTML, Cc/Bcc

`attachment_paths` reads local files at materialization time, guessing MIME type from the extension. `html_body` sends a `multipart/alternative` message alongside the plain-text `body`. `bcc` recipients receive the message but are never added as a header, same as any real BCC.

## `run_window`, `pool`, `dry_run`

Same conventions as `sql_asset`/`task_chain_asset`: `run_window` skips cleanly outside a configured time window (e.g. don't page anyone at 2am), `pool` caps concurrent sends via Dagster's named concurrency pools, and `dry_run` logs what would be sent (recipients, subject, attachment paths) without looking up the resource or touching the network at all. To share one `run_window` value across several assets instead of repeating the same literal string in each component instance, see `task_chain_asset`'s README ("Sharing one `run_window` across several assets") for a `template_vars_module` example.
