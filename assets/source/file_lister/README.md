# File Lister

List files matching a glob pattern from any fsspec-supported location — `s3://`, `gs://`, `abfss://` / `abfs://` / `az://`, or a plain local path — into a DataFrame with one row per file. Built as the missing upstream for the document/image/audio extractor family (`ocr_extractor`, `document_ai_extractor`, `image_llm_extractor`, `audio_transcriber`, ...), which all consume an `upstream_asset_key` + a column of file paths but have no way to discover those paths from object storage themselves.

## How it works

By default (`download: true`), every matched file is downloaded to a local cache directory and `local_path` points at the cached copy — every existing extractor works immediately with zero changes, since they already open plain local paths. Set `download: false` to list metadata only (path/size/modified_at, no bytes moved) when you just need a file inventory, or a downstream component already fsspec-opens `path` directly.

```yaml
type: dagster_component_templates.FileListerComponent
attributes:
  asset_name: incoming_invoices
  path: s3://my-bucket/invoices/**/*.pdf
  download: true
```

Wire it into an extractor by pointing `upstream_asset_key` at this asset and `image_column` (or the extractor's equivalent) at `local_path`:

```yaml
type: dagster_component_templates.OcrExtractorComponent
attributes:
  asset_name: invoice_text
  upstream_asset_key: incoming_invoices
  image_column: local_path
```

## Output columns

| Column | Description |
|---|---|
| `path` | Fully-qualified source URI (`s3://...`, `gs://...`, or the local path) |
| `local_path` | Local cached copy's path when `download: true`; same as `path` when `download: false` |
| `filename` | Basename of the file |
| `size` | File size in bytes, when the backend reports it |
| `modified_at` | Last-modified timestamp, when the backend reports it (format varies by backend) |

## Auth

Uses fsspec's ambient credential discovery — same as `file_ingestion`. For S3 that's the standard boto3 credential chain (env vars, `~/.aws/credentials`, instance role); for GCS, application default credentials; for ADLS, `DefaultAzureCredential`'s chain. No separate resource/connection config on this component.

## Requirements

`fsspec` is a hard dependency. Install the matching protocol package for whichever location(s) you point `path` at: `s3fs` for `s3://`, `gcsfs` for `gs://`, `adlfs` for `abfss://` / `abfs://` / `az://`. Local paths need nothing extra.

## Validation

`validation.level: code` — this component compiles and was verified end-to-end against a real local Dagster materialization (list + download + metadata-only modes), but has not yet been run against a real S3/GCS/ADLS account. Live-test against your actual cloud storage before trusting it in production, and flip `validation.level` to `live` in the manifest once confirmed.
