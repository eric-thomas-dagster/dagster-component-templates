# Pulsar Topic Stats

Fetches an [Apache Pulsar](https://pulsar.apache.org/) topic's live stats via the broker's real Admin REST API (`GET /admin/v2/{persistent|non-persistent}/{tenant}/{namespace}/{topic}/stats`) and materializes one row per subscription -- the operational signal people actually want from a Pulsar topic ("is any consumer falling behind") -- as a pandas DataFrame asset.

This is distinct from `pulsar_to_database_asset`, which consumes message *payloads* from a topic via a stateful pulsar-client consumer. This component reads topic/subscriber *health* metrics only (backlog size, message rates, consumer counts) through a plain, stateless HTTP+JSON call to the broker's admin port -- no pulsar-client dependency, no open subscription.

If the topic currently has no subscriptions, a single topic-level summary row is still returned (rather than an empty DataFrame) so the asset always has something to materialize.

Plain HTTP+JSON API -- no native Pulsar client required.

## Example YAML

```yaml
type: dagster_component_templates.PulsarTopicStatsQueryComponent
attributes:
  asset_name: orders_topic_health
  admin_url: "{{ env.PULSAR_ADMIN_URL }}"
  tenant: public
  namespace: default
  topic: orders
  auth_token_env_var: PULSAR_AUTH_TOKEN
  group_name: observability
  kinds: [pulsar]
```

## Output shape

One row per subscription, each carrying `subscription_name`, `msgBacklog`, `backlogSize`, `msgRateOut`, `unackedMessages`, `consumer_count`, plus the topic-level fields (`topic_msgRateIn`, `topic_msgRateOut`, `topic_storageSize`, `topic_backlogSize`, ...) repeated on every row. If the topic has no subscriptions, one row with `scope="topic"` and `subscription_name=None` is returned instead.
