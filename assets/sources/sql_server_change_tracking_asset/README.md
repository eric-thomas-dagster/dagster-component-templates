# SQL Server Change Tracking

Reads changed rows from a SQL Server table with [Change Tracking](https://learn.microsoft.com/en-us/sql/relational-databases/track-changes/about-change-tracking-sql-server) enabled, using SQL Server's own `CHANGETABLE(CHANGES ...)` function -- the real native CDC-lite mechanism SQL Server has shipped since 2008, not a generic timestamp-column polling diff.

**Prerequisite**: Change Tracking must already be enabled on the SQL Server side (`ALTER DATABASE ... SET CHANGE_TRACKING = ON` + `ALTER TABLE <schema>.<table> ENABLE CHANGE_TRACKING`). This component only reads -- it never enables tracking itself.

## How the cursor is tracked

No external state store needed: this asset reads its own previous materialization's metadata (`ct_version`) to know where it left off, the same pattern `openlineage_export_job` uses for column-lineage lookups. First materialization (no prior run) does a full table load instead of `CHANGETABLE`, with the current `CHANGE_TRACKING_CURRENT_VERSION()` as the new baseline.

## A real correctness nuance this handles for you

SQL Server only retains change history back to `CHANGE_TRACKING_MIN_VALID_VERSION(table)` (bounded by the table's `CHANGE_RETENTION` setting -- 2 days by default). If the stored cursor is older than that because history was cleaned up since the last run, `CHANGETABLE` would either error or silently miss changes. This checks `CHANGE_TRACKING_MIN_VALID_VERSION` explicitly before querying, and falls back to a full reload with a warning log rather than returning wrong data.

## Why `columns` is required (no `SELECT *`)

`CHANGETABLE`'s own result only carries the primary key columns plus change metadata (`SYS_CHANGE_OPERATION`, `SYS_CHANGE_VERSION`) -- it does not carry the row's other column values. Getting those requires an explicit `LEFT JOIN` back to the base table (a plain `SELECT *` can't express that join), so `columns` names every column to read, including the primary key.

## Output shape

Each row carries `sys_change_operation`: `I` (insert), `U` (update), or `D` (delete -- for a deleted row, every non-key column is `NULL`, since the row no longer exists in the base table to join against). A full load (first run, or a stale-cursor fallback) tags every row `I`.
