# External S3 Asset

Declares a S3 resource as an external asset in the Dagster asset graph — making it visible for lineage without materializing it from Dagster.

## What this does

External assets represent data sources managed outside of Dagster. Adding one to your project:
- Makes the S3 resource visible as a node in the **Dagster asset graph**
- Enables downstream assets to declare `deps` on it, drawing lineage edges
- Records connection metadata in the **Asset Catalog**

This component does not read from or write to S3. It is a **lineage declaration only**.

## Example YAML
```yaml
type: dagster_component_templates.ExternalS3Asset
attributes:
  asset_key: my_service/asset
  bucket_name: my_bucket_name
  # prefix: ""  # optional
  # region_name: None  # optional
  # group_name: None  # optional
  # description: None  # optional
```

## Observation sensor

Set `create_observation_sensor: true` to also get the polling sensor that keeps this asset's
health/data-version current — one component, one YAML, no manual `asset_key` wiring:

```yaml
type: dagster_component_templates.ExternalS3Asset
attributes:
  asset_key: external/s3
  bucket_name: my_bucket
  create_observation_sensor: true
  check_interval_seconds: 300
```

If the sensor needs to observe an `asset_key` declared by a *different* component (or you want the
asset and sensor on independent lifecycles), pair this component with the standalone
`s3_observation_sensor` component instead:

```yaml
# 1. Declare the external asset (lineage node)
type: dagster_component_templates.ExternalS3Asset
attributes:
  asset_key: external/s3
  bucket_name: my_bucket

---

# 2. Observe it on a schedule
type: dagster_component_templates.S3ObservationSensorComponent
attributes:
  sensor_name: s3_asset_observer
  asset_key: external/s3
  bucket_name: my_bucket
```

## Several sources from one component instance

Use `sources:` instead of the top-level `asset_key`/`bucket_name`/`prefix` fields to declare
several bucket/prefix sources from one `ExternalS3Asset` instance, instead of one YAML block per
source:

```yaml
type: dagster_component_templates.ExternalS3Asset
attributes:
  group_name: s3_sources
  sources:
    - key: lake/orders
      bucket_name: my-bucket
      prefix: orders/
    - key: lake/invoices
      bucket_name: my-bucket
      prefix: invoices/
      owners: ["team:finance"]
  create_observation_sensor: true
  sensor_name: s3_sources_observer  # required with sources: -- no single bucket to default from
```

All sources share this instance's `region_name`. With `create_observation_sensor: true`, they also
share **one** sensor that lists every source's objects per tick instead of one sensor per source. A
source whose listing fails doesn't block the rest — it's skipped for that tick and reported again
next time.

`asset_key`/`bucket_name`/`prefix` and `sources:` are mutually exclusive on one component instance.

## Requirements

No additional packages required — this component only creates a `dg.AssetSpec`.
