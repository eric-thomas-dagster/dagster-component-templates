# Databricks Clean Room Notebook Run

Runs a Databricks Clean Room notebook as a Dagster asset.

Clean Rooms has no "submit a run" REST endpoint of its own (confirmed against the real API reference: it only exposes read-only listing endpoints). A clean room notebook actually executes through the standard Databricks **Jobs API**, using a dedicated task type -- `clean_rooms_notebook_task` -- which needs no cluster spec, since it runs inside the clean room's own isolated compute. This component submits that task via the `databricks-sdk` (`client.jobs.submit(...)`), then polls with `client.jobs.wait_get_run_job_terminated_or_skipped(...)` until it reaches a terminal state.

The notebook must already exist in the clean room and already be approved by all of its collaborators. The caller (whoever `token_env_var` authenticates as) must be the clean room's owner or hold the `EXECUTE CLEAN ROOM TASK` privilege -- the notebook's own creator/uploader cannot run it.

## Example YAML

```yaml
type: dagster_community_components.DatabricksCleanRoomNotebookRunComponent
attributes:
  asset_name: shared_attribution_analysis
  clean_room_name: acme_retail_media_room
  notebook_name: attribution_report
  notebook_base_parameters:
    report_month: '2026-10'
  group_name: clean_rooms
  kinds: [databricks, clean_rooms]
```

## Authentication

`host_env_var` (default `DATABRICKS_HOST`) names an env var holding the workspace URL (`https://<workspace>.cloud.databricks.com`); `token_env_var` (default `DATABRICKS_TOKEN`) names an env var holding a personal access token or OAuth bearer token.
