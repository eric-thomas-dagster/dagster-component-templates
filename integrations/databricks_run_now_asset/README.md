# Databricks Run Now

Trigger an **existing** Databricks job by `job_id` via the real `jobs.run_now` API and wait for it to reach a terminal state -- the Airflow `DatabricksRunNowOperator` equivalent.

This is distinct from `integrations/databricks_asset_bundle` (submits ad-hoc tasks defined inline from a `databricks.yml` bundle file, no pre-existing job needed) and `integrations/databricks_clean_room_notebook_run` (ad-hoc Clean Rooms notebook submission). Use this component when the job already exists in the workspace (created via the UI, Terraform, or a bundle deploy) and you just want Dagster to trigger a run of it and materialize on completion.

By default a non-`SUCCESS` `result_state` (`FAILED`, `TIMEDOUT`, `CANCELED`, etc.) fails the Dagster run. Set `fail_on_non_success: false` to materialize anyway with the result state surfaced in metadata.

## Example YAML

```yaml
type: dagster_community_components.DatabricksRunNowAssetComponent
attributes:
  asset_name: nightly_etl_job
  job_id: 123456789
  workspace_host: https://dbc-abc123.cloud.databricks.com
  workspace_token_env_var: DATABRICKS_TOKEN
  job_parameters:
    run_date: "2026-01-15"
  poll_timeout_seconds: 7200
  group_name: databricks
  kinds: [databricks]
```

## Authentication

Reads a Databricks personal access token (or workspace-scoped token) from the environment variable named by `workspace_token_env_var`. No credential caching or refresh logic -- a PAT is a static credential, unlike an OAuth2 bearer token.
