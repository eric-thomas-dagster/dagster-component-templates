# `InformaticaWorkspaceComponent`

Wrap **Informatica IDMC** (Intelligent Data Management Cloud, formerly IICS) behind a Dagster workspace-shape component. Discovers every task in the IDMC org and emits one Dagster asset per task. On materialize, POSTs the task via `/api/v2/job` (with optional runtime parameter overrides) and polls the activity log until termination.

Covers the modern Informatica cloud platform. For legacy on-prem **PowerCenter**, use the companion [`informatica_powercenter_workspace`](../informatica_powercenter_workspace/) component (pmcmd / pmrep subprocess).

## Full workspace shape (parity with other workspace components)

- **`@public`** class + `StateBackedComponent` caching (refresh via `dg utils refresh-defs-state`).
- **`translation:` callable** for per-asset customization (rename, tag by folder, add owners).
- **`task_selector:`** — filter by kind / folder / include / exclude fnmatch patterns.
- **`task_overrides:`** — runtime parameters + input files applied at execute time.
- **`polling_sensor:`** + **`freshness_lag_threshold_seconds:`** — observation surfaces.

## Backing REST (IDMC public API v3 + legacy v2)

| Endpoint | Purpose |
|---|---|
| `POST /public/core/v3/login` | Auth — returns `sessionId` + `baseApiUrl` (POD-specific). |
| `GET /public/core/v3/objects` | Task enumeration. |
| `POST /api/v2/job` | Trigger a task run. |
| `GET /api/v2/activity/activityLog` | Poll for completion + read historical runs. |

**Two-step auth.** Unlike Talend's static bearer token, IDMC uses session-ticket auth: log in first with username/password against the regional login URL, get back a session ID + POD-specific base URL. All subsequent calls hit the POD URL with `Authorization: INFA-SESSION-ID <sessionId>`.

Session tickets expire after ~30 min of inactivity. This component re-logs-in per code-location load + per sensor tick + per materialization run — no session-refresh loop needed.

## Runtime parameters

Real IDMC tasks take parameters — target schemas, batch dates, connection overrides. `task_overrides:` applies them per-task at execute time. The component maps them onto the `POST /api/v2/job` body:

- **MTT tasks** — parameters land in `mtTaskParameters`.
- **DPS / DRS / DMASK / MI_TASK** — parameters land in `runtimeConfig.parameters`.
- **Mass Ingestion** — file paths land in `inputFiles`.
- **Arbitrary keys** — a raw `runtime_config` block appends verbatim to the body's `runtimeConfig`.

```yaml
task_overrides:
  - match: "Sales/Prod/mtt_load_customers"
    parameters:
      p_target_schema: "raw_sales"
      p_batch_date:    "{partition_key}"      # substituted at run time
    runtime_config:
      emailNotification:
        failureEmailIds: "team@corp.com"

  - match: "Sales/Prod/mi_load_files"
    input_files:
      - "/mnt/landing/customers_{partition_key}.csv"
      - "/mnt/landing/orders_{partition_key}.csv"
```

The **`{partition_key}`** token substitutes at run time (via `str.format`) — pair with `PartitionsDefinition` on the asset (via `translation:`) for per-partition IDMC runs.

## Actions

- **`action: noop` (default)** — external asset shape. Every IDMC task becomes a Dagster asset, but materialize does nothing. Use with `polling_sensor: true` + `freshness_lag_threshold_seconds:` for observe-only.
- **`action: execute`** — materialize runs the task via `POST /api/v2/job` (with `task_overrides:` applied to the body). With `wait_for_completion: true`, the op blocks until the run reaches a terminal `runStatus`. On non-success, the op raises `dg.Failure` with the error message from the activity log.
