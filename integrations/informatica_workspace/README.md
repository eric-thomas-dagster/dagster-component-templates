# `InformaticaWorkspaceComponent`

Wrap **Informatica IDMC** (Intelligent Data Management Cloud, formerly IICS) behind a Dagster workspace-shape component. Discovers every task in the IDMC org and emits one Dagster asset per task. On materialize, POSTs the task via `/api/v2/job` and polls the activity log until termination.

Covers the modern Informatica cloud platform. **PowerCenter** (legacy on-prem) uses a different API and is a separate future component.

## Backing REST (IDMC public API v3 + legacy v2)

| Endpoint | Purpose |
|---|---|
| `POST /public/core/v3/login` | Auth — returns `sessionId` + `baseApiUrl` (POD-specific). |
| `GET /public/core/v3/objects` | Task enumeration. |
| `POST /api/v2/job` | Trigger a task run. |
| `GET /api/v2/activity/activityLog` | Poll for completion + read historical runs. |

**Two-step auth.** Unlike Talend's static bearer token, IDMC uses session-ticket auth: log in first with username/password against the regional login URL, get back a session ID + POD-specific base URL. All subsequent calls hit the POD URL with `Authorization: INFA-SESSION-ID <sessionId>`.

Session tickets expire after ~30 min of inactivity. This component re-logs-in per code-location load + per sensor tick + per materialization run — no session-refresh loop needed.

## Task types supported

Discovery filters by IDMC's `type` field. Common values:

| Kind | Meaning |
|---|---|
| `MTT` | Mapping Task |
| `DMASK` | Data Masking task |
| `DPS` | Data Processing Service |
| `DRS` | Data Replication Service |
| `MI_TASK` | Mass Ingestion task |

## Task run status values

Values from `activityLog[].runStatus`:

| Status | Terminal? | Success? |
|---|---|---|
| `RUNNING` | no | — |
| `QUEUED` | no | — |
| `SUCCESS` | **yes** | **yes** |
| `WARNING` | **yes** | **yes** (completed with warnings) |
| `FAILED` | yes | no |
| `STOPPED` | yes | no |

## Actions

- **`action: noop` (default)** — external asset shape. Every IDMC task becomes a Dagster asset, but materialize does nothing. Use with `polling_sensor: true` + `freshness_lag_threshold_seconds:` for observe-only.
- **`action: execute`** — materialize runs the task via `POST /api/v2/job`. With `wait_for_completion: true`, the op blocks until the run reaches a terminal `runStatus`. On non-success, the op raises `dg.Failure` with the error message from the activity log.
