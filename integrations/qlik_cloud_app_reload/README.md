# QlikCloudAppReload

Triggers a reload of a [Qlik Cloud](https://qlik.dev/) app and polls it to completion, surfacing status/duration/error as materialization metadata. Qlik Cloud is a different product from Qlik Compose (ETL-generation/data-warehouse-automation, already covered elsewhere in this registry by `qlik_compose_workspace`) — Qlik Cloud / Qlik Sense is Qlik's BI/analytics/dashboarding product, with no prior registry coverage.

Endpoints verified directly against [qlik.dev's Reloads API reference](https://qlik.dev/apis/rest/reloads/):

- `POST /api/v1/reloads` — trigger (`{appId, partial, resourceType, resourceId}`)
- `GET /api/v1/reloads/{reloadId}` — poll to a terminal status
- Status enum: `QUEUED`, `RELOADING`, `CANCELING` (active) / `SUCCEEDED`, `FAILED`, `CANCELED`, `EXCEEDED_LIMIT` (terminal)

```yaml
  app_id: <fill in>
  tenant_url_env_var: QLIK_CLOUD_TENANT_URL
  api_key_env_var: QLIK_CLOUD_API_KEY
  deps:
    - warehouse/finance_fact
  group_name: bi
```

## Observing externally-triggered reloads

Set `polling_sensor: true` to get a sensor that polls `GET /api/v1/reloads?appId=...` for reloads this component did not itself trigger — e.g. a reload scheduled directly in Qlik Cloud, or someone reloading from the Qlik hub. Every reload this component triggers is tagged `resourceType: "api", resourceId: "dagster"` on the real API request, which the sensor uses to skip its own triggers and only emit `AssetObservation` for the rest.
