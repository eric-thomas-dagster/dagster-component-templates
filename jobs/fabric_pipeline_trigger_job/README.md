# Fabric Pipeline Trigger Job

Op-job that triggers a Microsoft Fabric Data Pipeline / Notebook /
Dataflow Gen2 run via the Fabric REST API. For workspace-wide imports
(one Dagster asset per Fabric pipeline) use the `fabric_workspace`
integration component instead — use this when you want **one** specific
Fabric item run as a Dagster job, with optional schedule.

## Pattern

```yaml
- type: dagster_community_components.FabricPipelineTriggerJobComponent
  attributes:
    job_name: fabric_daily_etl
    workspace_id: ...
    item_id: ...                       # the pipeline GUID
    item_type: DataPipeline
    parameters: { date: "{{run_date}}" }
    schedule: "0 2 * * *"
```

`parameters` is a plain `{name: value}` dict, converted internally to Fabric's documented `Parameter[]` request shape (`{name, value, type}`, type inferred from the Python value) — this is the SAME shape across item types, sent as a top-level `parameters` field, not nested under `executionData`. Not every item/job type accepts parameters; Fabric's own API returns `errorCode: FeatureNotAvailable` for ones that don't, surfaced as a clear `dg.Failure`.

## Failure handling

A Failed, Cancelled, Deduped, or timed-out run raises `dg.Failure` (or `dg.RetryRequested`, once, when Fabric's own `failureReason.isRetriable` flag says the failure is transient) with the real error code/message — not a bare `Exception` dumping the raw state dict. `Deduped` (another instance of the same job type was already running) fails immediately instead of polling until the timeout. A timeout requests cancellation of the orphaned Fabric job via `POST <Location>/cancel`.
