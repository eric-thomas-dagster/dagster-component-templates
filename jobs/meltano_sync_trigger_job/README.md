# MeltanoSyncTriggerJobComponent

Trigger a Meltano Cloud pipeline run via REST API — fire-and-forget or wait for completion.

## Dependencies
- `requests`

## Real API, confirmed

Meltano is open-source and self-hosted by default — it's run via its own
`meltano` CLI/orchestrator, not a single global SaaS API, so there's no
generic "remote-trigger a self-hosted Meltano project" surface to wrap.
**Meltano Cloud** (meltano.com's managed, hosted offering) is different: it
exposes a real, documented REST API confirmed 2026-10 against
[docs.meltano.com](https://docs.meltano.com/reference/cloud/api/resources/jobs/):

- Base URL: `https://app.meltano.com/api`
- Auth: `Authorization: Bearer $MELTANO_CLOUD_API_TOKEN` (create a key via the Cloud UI's API Keys page, or `POST /api/apikeys`)
- Trigger: `POST /pipelines/{pipeline-id}/jobs` → `201 Created` with a Job object
- Poll: `GET /jobs/{job-id}` → Job object; `status` is one of `QUEUED` / `RUNNING` / `COMPLETE` / `ERROR` / `STOPPED`
- Cancel: `PUT /jobs/{job-id}/stopped`

Meltano Cloud's own docs note **only a single pipeline can run at a time per
project** — a failed trigger call may mean another run is already in
flight, not a config error.

If you run self-hosted/OSS Meltano instead of Meltano Cloud, this component
does not apply — there is no remote API to trigger; use Meltano's own CLI
(`meltano run ...`) via whatever scheduler/orchestrator you already run it
with (e.g. a `shell_command_job` that shells out to `meltano run` on a host
where the project is installed).

## What this is
A **Dagster job** (no asset materialized) — the component installs a `dg.job`
plus an optional schedule. Lineage graph stays clean; the work happens
behind the scenes.
