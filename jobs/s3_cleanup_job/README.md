# S3CleanupJobComponent

Delete S3 objects by age, by an explicit key list, or both — cost control + compliance retention.

## Dependencies
- `boto3`

## Deleting by explicit key list

```yaml
keys:
  - tmp/stale-upload-1.csv
  - tmp/stale-upload-2.csv
```

`keys` deletes those exact keys regardless of age. Combine with `older_than_days` and both apply (union of the two sets).

## Upstream-asset-driven deletion

The op accepts a per-run `keys` config override, in addition to the component's own static `keys` field — the mechanism for deleting exactly what an upstream asset produced, without hardcoding anything in YAML:

```python
# A sensor reading an upstream asset's materialized output (e.g. a list of file keys an
# ingestion asset just wrote and wants cleaned up later) launches this job with:
RunRequest(
    run_config={"ops": {"<job_name>_op": {"config": {"keys": [...]}}}},
)
```

Per-run keys and the component's static `keys` field combine (union).

## What this is
A **Dagster job** (no asset materialized) — the component installs a `dg.job`
plus an optional schedule. Lineage graph stays clean; the work happens
behind the scenes.
