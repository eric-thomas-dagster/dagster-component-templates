# Airtable Resource

Register an `AirtableResource` for use by other Dagster components. Ships
with **~10 convenience methods** over the Airtable REST API (bases,
tables, records CRUD + **native server-side upsert**) so your assets can
call `context.resources.airtable.upsert_records(base, table, rows, key_fields=["Name"])`
without touching HTTP.

Airtable's `PATCH /v0/{baseId}/{table}?performUpsert[fieldsToMergeOn][]=<field>`
is a real server-side upsert — you don't need a "search then create or update"
dance. The resource wraps it, chunking automatically at Airtable's 10-records-per-batch
limit.

## Installation

```bash
pip install requests
```

## Convenience methods

Any component with `required_resource_keys={"airtable"}` can call these on `context.resources.airtable`:

### Reads

| Method | Purpose |
|---|---|
| `list_bases()` | List all bases the PAT has access to. |
| `get_base_schema(base_id)` | Retrieve tables + fields for a base. |
| `get_record(base_id, table, record_id)` | Retrieve a single record. |
| `list_records(base_id, table, filter_by_formula=..., fields=..., view=..., max_records=..., page_size=100)` | List records with Airtable formula filtering. First page only. |
| `iter_records(...)` | Auto-paginated variant of `list_records`. |

### Writes

Airtable caps every write at 10 records per API call — the resource batches automatically.

| Method | Purpose |
|---|---|
| `create_records(base_id, table, rows, typecast=False)` | Batch create records. |
| `update_records(base_id, table, rows, typecast=False)` | Batch update by record ID. Each row is `{id, fields}`. |
| `upsert_records(base_id, table, rows, key_fields, typecast=False)` | Native server-side create-or-update, matched on `key_fields`. |
| `delete_records(base_id, table, record_ids)` | Batch delete by ID. |

### Escape hatch

`get_client()` returns an authenticated `requests.Session` pointed at `api.airtable.com/v0`.

## Authentication

`api_key_env_var` accepts an **environment variable name** (not the token itself). Set the corresponding environment variable before running Dagster:

```bash
export AIRTABLE_API_KEY=patXXXXXXXXXXXXXXX.XXXXXXXXXXXXXX
```

Create a Personal Access Token at [airtable.com/create/tokens](https://airtable.com/create/tokens) with the scopes you need:
- `data.records:read` — for `list_records` / `iter_records` / `get_record`
- `data.records:write` — for `create/update/upsert/delete_records`
- `schema.bases:read` — for `list_bases` / `get_base_schema`

Grant the token access to the specific bases it should touch (Airtable PATs are scoped per-base).

## `typecast` flag

Airtable's REST API is strict about types — sending a string to a `singleSelect` field errors by default. Passing `typecast: True` on writes lets Airtable coerce string values into the target field's type (e.g., accept `"Todo"` for a singleSelect, `"2026-08-15"` for a date). Default in the sink component is `true` since DataFrames typically carry stringified values.
