# BigCommerce Resource

Register a `BigCommerceResource` -- a raw-HTTP workhorse for the BigCommerce Catalog API (v3) -- for use by other Dagster components.

## When to use

- As the connection backing `bigcommerce_product_upsert` (reverse-ETL sink).
- From custom Dagster asset code that needs to read or write BigCommerce catalog data beyond what the sink covers (e.g. multi-variant products, categories, brands).

## Installation

No vendor SDK required -- this resource talks to the Catalog API v3 directly over `requests`.

```bash
pip install requests
```

## Authentication

`access_token_env_var` accepts an **environment variable name** (not the secret value itself).
Set the corresponding environment variable before running Dagster:

```bash
export BIGCOMMERCE_ACCESS_TOKEN="xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
```

Create a store-level API account in your BigCommerce control panel under **Settings -> API -> Store-level API accounts -> Create API Account**. Grant it the scopes you need (typically **Products: read/write**). BigCommerce issues the Access Token once, at creation time -- copy it immediately, since it cannot be viewed again after you leave the page.

Auth is a static header on every request, not an OAuth bearer flow:

```
X-Auth-Token: <access_token>
```

## Pairs with

- **`bigcommerce_ingestion`** -- the READ-side counterpart (dlt-based bulk pull).

## Behavior + gotchas

- **No native upsert** -- BigCommerce's Catalog API has no upsert endpoint. `upsert_product_by_sku` does search-then-write: `GET /catalog/products?sku=<sku>&limit=1` then `PUT` (found) or `POST` (not found).
- **SKU uniqueness** -- the main product SKU is unique, case-insensitive, across the *entire* catalog (not per-variant).
- **Create requires `name`, `type`, `weight`, `price`** (plus `categories` if your store has the V2 product experience enabled). `PUT` updates are partial and don't need these re-sent.
- **Response envelope** -- every v3 response wraps its payload as `{"data": ..., "meta": {...}}`. This resource unwraps `data` for you.
- **Pagination** -- list endpoints use `meta.pagination` (`total_pages`, `current_page`), a page/limit model -- not Shopify's Link-header cursor.
- **Rate-limit backoff header** -- BigCommerce does NOT send a standard `Retry-After` header on 429. It sends `X-Rate-Limit-Time-Reset-Ms` (milliseconds until quota reset); this resource reads that header to back off.
