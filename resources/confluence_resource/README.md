# Confluence Resource

Register a `ConfluenceResource` wrapping the Confluence Cloud REST v2 API (`/wiki/api/v2/pages`, `/wiki/api/v2/spaces`) for use by other Dagster components.

## Why a separate component from `jira_resource`

Confluence and Jira are both Atlassian Cloud products and share the same authentication mechanism (Atlassian account email + API token, HTTP Basic auth) and the same site host (`https://<site>.atlassian.net`). This resource does **not** import or reuse `resources/jira_resource` even so: `JiraResource`'s convenience methods (`get_issue`, `search_issues`, `create_issue`, `transition_issue`, ...) are scoped entirely to Jira's issue endpoints under `/rest/api/3/...`. Confluence lives under a different path (`/wiki/api/v2/...`) with entirely different resources (pages/spaces, not issues) and different write semantics (optimistic-concurrency page versioning vs. Jira's field PATCH/transition model). Per this repo's rule that every component is fully self-contained, `confluence_resource` duplicates only the ~10-line Basic-auth-session boilerplate that `jira_resource` also happens to use, and otherwise owns Confluence's own page/space API end-to-end as its own independent component.

## Gotchas

- **Version numbers on update are not optional and must be exact.** `PUT /wiki/api/v2/pages/{id}` requires `version.number` to be exactly one higher than the page's current version (Confluence's optimistic-concurrency protection). `update_page(...)` takes `current_version` as a parameter so the caller controls the GET-then-PUT sequencing; `upsert_page_by_title(...)` handles this automatically by re-fetching the page before every update.
- **Page bodies use "storage format"**, Confluence's XHTML-based wiki markup — not Markdown and not plain HTML. This resource does not convert Markdown into storage format; pass pre-built storage XHTML, or wrap plain text in `<p>...</p>` tags for simple cases. Rich formatting (tables, macros, layouts) needs hand-built storage XML.
- **Title lookups are a single API call.** `GET /wiki/api/v2/pages` supports `space-id` and `title` as direct query parameters, so `find_page_by_title` does not page through every page in a space client-side.

## Configuration

```yaml
type: dagster_component_templates.ConfluenceResourceComponent
attributes:
  resource_key: confluence  # key other components use
  site_domain: yoursite  # for yoursite.atlassian.net
  email_env_var: CONFLUENCE_EMAIL  # env var name holding the Atlassian account email
  api_token_env_var: CONFLUENCE_API_TOKEN  # env var name holding the API token
```

## Usage in other components

Once placed on the canvas, other components can reference this resource:

```yaml
attributes:
  resource_key: confluence
```

## Authentication

`email_env_var` / `api_token_env_var` accept **environment variable names** (not the secret values themselves).
Set the corresponding environment variables before running Dagster:

```bash
export CONFLUENCE_EMAIL="you@company.com"
export CONFLUENCE_API_TOKEN="ATATT3xFfGF0..."
```

Create an API token at [id.atlassian.com/manage-profile/security/api-tokens](https://id.atlassian.com/manage-profile/security/api-tokens) for the Atlassian account that has access to the target Confluence site.

## Example
```yaml
type: dagster_component_templates.ConfluenceResourceComponent
attributes:
  resource_key: confluence
  site_domain: yoursite
  email_env_var: CONFLUENCE_EMAIL
  api_token_env_var: CONFLUENCE_API_TOKEN
```
