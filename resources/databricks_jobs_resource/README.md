# Databricks Jobs Resource

Register a `DatabricksJobsResource` (run_now + wait for an existing job) for use by any
op/asset in this code location -- the reusable Airflow `DatabricksRunNowOperator`-equivalent
action. This component only registers the resource; it does not materialize anything on its
own.

## Usage

Call it from your own asset/op body:

```python
import dagster as dg


@dg.asset
def my_pipeline_step(context: dg.AssetExecutionContext, databricks_jobs_resource) -> dg.MaterializeResult:
    result = databricks_jobs_resource.run_now_and_wait(job_id=123456789)
    return dg.MaterializeResult(metadata={"run_id": result["run_id"]})
```

Wrap it in your own `@dg.asset` only when you want the trigger itself to participate in the
Dagster asset graph (deps, freshness, automation conditions, partitioning, retries). Distinct
from `integrations/databricks_asset_bundle` (submits ad-hoc tasks defined inline from a
`databricks.yml` bundle) and `integrations/databricks_clean_room_notebook_run` (ad-hoc Clean
Rooms notebook submission) -- neither of those calls `run_now` against a pre-existing job.

## Authentication

All secret fields accept an **environment variable name** (not the secret value itself).
Set the corresponding environment variable before running Dagster:

```bash
export DATABRICKS_TOKEN="your-personal-access-token"
```
