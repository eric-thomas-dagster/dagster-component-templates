# Dataproc Resource

Register a `DataprocResource` (Google Cloud Dataproc cluster lifecycle + job submission) for use by other components.

A Dataproc cluster or job isn't data with lineage -- it's a reusable, parameterized action, the Airflow Dataproc provider's `DataprocCreateClusterOperator`/`DataprocDeleteClusterOperator`/`DataprocSubmitJobOperator` equivalent. This is a resource you inject into your own op/asset code, not a dedicated asset component -- call `ensure_cluster()`/`delete_cluster()`/`submit_job_and_wait()` from wherever you need Dataproc orchestration.

## Installation

## Usage in your own ops/assets

```python
import dagster as dg

@dg.asset
def train_job(context: dg.AssetExecutionContext, dataproc_resource):
    dataproc_resource.ensure_cluster(
        project_id="my-project", region="us-central1", cluster_name="ml-cluster",
        cluster_config={"num_workers": 4, "worker_machine_type": "n2-standard-8"},
    )
    result = dataproc_resource.submit_job_and_wait(
        project_id="my-project", region="us-central1", cluster_name="ml-cluster",
        job_type="pyspark",
        job_config={"main_python_file_uri": "gs://my-bucket/train.py", "args": ["--epochs", "10"]},
        log=context.log,
    )
    return dg.MaterializeResult(metadata={"job_id": result["job_id"], "job_status": result["job_status"]})
```

`ensure_cluster()`/`delete_cluster()` are idempotent (a no-op when the cluster is already in the desired state). `cluster_config` is a convenience subset of the real Dataproc `ClusterConfig` (machine types, worker count, disk sizes, zone, service account, network tags, image version, software properties, idle-delete TTL); for anything it doesn't cover, pass `cluster_config_overrides` -- the real `ClusterConfig` shape (e.g. `autoscaling_config`, `initialization_actions`, `lifecycle_config`, `secondary_worker_config`, `endpoint_config`), deep-merged on top of what `cluster_config` generated. An override wins wherever it sets a key the flat fields also set; e.g. `cluster_config_overrides={"master_config": {"machine_type_uri": "n2-standard-16"}}` overrides just that one nested value, leaving the rest of `master_config` as the flat fields generated it. `submit_job_and_wait()` supports `job_type` of `pyspark`, `spark`, `hive`, or `pig` -- see `component.py`'s `_build_job_body()` for the exact `job_config` keys each type accepts (e.g. `main_python_file_uri`/`args` for pyspark, `main_jar_file_uri`/`main_class` for spark, `query_file_uri`/`query_list` for hive/pig; `jar_file_uris`/`file_uris`/`archive_uris`/`properties`/`labels` are shared across types). It polls to a terminal `JobStatus.State`, raising `RuntimeError` on `ERROR`/`CANCELLED` and `TimeoutError` if the job never reaches one within `timeout_seconds`.

`create_batch_and_wait(project_id, region, batch_id, batch_config, timeout_seconds=3600, log=None)` -- the `DataprocCreateBatchOperator` equivalent: creates a Dataproc Serverless batch workload (ephemeral, Google-managed compute -- no cluster to create first) and waits for it to finish. `batch_config` is the real `google.cloud.dataproc_v1.Batch` message shape passed straight through, e.g. `{"pyspark_batch": {"main_python_file_uri": "gs://bucket/job.py", "args": [...]}, "runtime_config": {"version": "2.1"}}` -- exactly one of `pyspark_batch`/`spark_batch`/`spark_r_batch`/`spark_sql_batch` must be set. Returns `{"batch_id", "state"}` once terminal; raises `RuntimeError` on `FAILED`/`CANCELLED`.

## Authentication

All secret fields accept an **environment variable name** (not the secret value itself).
Set the corresponding environment variable before running Dagster:

```bash
export GCP_SERVICE_ACCOUNT_JSON='{"type": "service_account", ...}'
```

Omit `gcp_credentials_env_var` to use Application Default Credentials instead.
