# Dbt Command Resource

Register a `DbtCommandResource` (run an arbitrary `dbt` CLI command) for use by any op/asset
in this code location -- the reusable Airflow-Operator-equivalent action. This component only
registers the resource; it does not materialize anything on its own.

## Usage

Call it from your own asset/op body, adding whatever partitioning, retries, freshness policy,
pool, or schedule you want around it:

```python
import dagster as dg


@dg.asset
def staging_models(context: dg.AssetExecutionContext, dbt_command_resource) -> dg.MaterializeResult:
    result = dbt_command_resource.run(command="build", select="tag:staging")
    return dg.MaterializeResult(metadata={"dbt_node_count": result.get("dbt_node_count")})
```

This is the reusable unit -- wrap it in your own `@dg.asset` only when you want the run to
participate in the Dagster asset graph, the same relationship `shell_command_asset` has to a
full per-step pipeline component. For a per-dbt-model asset graph use
`assets/dbt/enriched_dbt_project`; for a non-asset job/op use `jobs/dbt_run_job`; for triggering
an existing dbt Cloud job use `jobs/dbt_cloud_trigger_job` or
`assets/dbt/enriched_dbt_cloud_workspace`.
