# DocuSign Resource

Register a `DocuSignResource` wrapping DocuSign's eSignature REST API (JWT Grant OAuth2) for use by other Dagster components — specifically the write-side counterpart to `docusign_ingestion`, used by `docusign_envelope_send` to create and send envelopes.

## Installation

```bash
pip install requests pyjwt cryptography
```

## Authentication: JWT Grant (server-to-server)

This resource uses DocuSign's **JWT Grant** flow — the auth method DocuSign
recommends for unattended, server-side integrations (no end-user browser
redirect at run time). It is the same flow this repo's `docusign_ingestion`
component already uses for read access; this resource is the write-side
counterpart.

Setup (one-time, outside this resource):
1. Create an Integration Key in the DocuSign Admin console, generate an RSA
   keypair, and register the **public** key on that Integration Key.
2. Grant one-time JWT consent for the impersonated user — visit
   `https://{account|account-d}.docusign.com/oauth/auth?response_type=code&scope=signature%20impersonation&client_id={integration_key}&redirect_uri={any_registered_uri}`
   once in a browser as that user and approve.
3. Seed the three secrets below:

```bash
export DOCUSIGN_INTEGRATION_KEY="..."
export DOCUSIGN_USER_ID="..."       # GUID, not an email
export DOCUSIGN_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----..."
```

At run time, this resource signs a JWT assertion with `private_key`, exchanges
it for an access token at `/oauth/token`, then calls `/oauth/userinfo` to
resolve the account's `base_uri` (DocuSign accounts are hosted on different
regional API hosts — there is no single fixed base URL). The access token and
resolved base_uri/account_id are cached in-memory for the token's lifetime.

Set `use_demo_env: true` to point at DocuSign's demo/sandbox environment
(`account-d.docusign.com`) instead of production.
