## Authentication

Verified via [docs.figment.io/reference/authentication](https://docs.figment.io/reference/authentication): Figment's API uses a **static API key** sent in the `x-api-key` header (not `Authorization: Bearer`, and not OAuth2):

```bash
export FIGMENT_API_KEY="XXXXXXXXXXXXXXXXXXXX"
```

Create and manage keys in the Figment app's **Developers** section. Keys are environment-scoped (test keys only work against testnets/devnets; production keys only work against mainnets) and permission-scoped (Read/Write vs. Read-Only — a Read-Only key is sufficient for this repo's read-only Rewards API use case).

## Methods

- `get_client()` -- returns an authenticated `requests.Session` (`x-api-key` + `Content-Type: application/json` pre-set). Consuming components build their own request calls against `{base_url}/{network}/rewards` so each stays an isolated, independently-mockable API boundary.

## Scope

Figment's Rewards API is **read-only reporting** -- there is no corresponding reverse-ETL/write-side component in this repo, since staking operations (delegate, create validator, exit validator) are separate deliberate actions, not a warehouse sync.
