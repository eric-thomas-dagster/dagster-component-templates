# GitHub Resource

Register a `GitHubResource` (PAT-based) for use by other Dagster components.
Ships with **21 convenience methods** over the GitHub REST v3 API so your
assets can call `context.resources.github.list_issues("owner/repo")` without
touching HTTP.

Supports GitHub Enterprise Server via `api_base_url`. Auto-paginated via
`Link` headers. For GitHub App auth (installation tokens, higher rate
limits), pair this with the official `dagster_github.GithubResource` under
a different resource key.

## Installation

```bash
pip install requests
```

## Configuration

```yaml
type: dagster_community_components.GithubResourceComponent
attributes:
  resource_key: github
  token_env_var: GITHUB_TOKEN
  # api_base_url: https://ghe.example.com/api/v3   # for GitHub Enterprise Server
```

## Convenience methods

Any component with `required_resource_keys={"github"}` can call these on `context.resources.github`:

### Reads

| Method | Purpose |
|---|---|
| `get_repo(repo)` | Retrieve a repository (`owner/name` form). |
| `list_issues(repo, state='open', labels=..., assignee=..., per_page=100)` | List issues (first page). |
| `iter_issues(...)` | Auto-paginated variant of `list_issues`. |
| `get_issue(repo, number)` | Retrieve a single issue. |
| `list_pull_requests(repo, state='open', per_page=100)` | List PRs (first page). |
| `iter_pull_requests(...)` | Auto-paginated variant. |
| `get_pull_request(repo, number)` | Retrieve a single PR. |
| `list_commits(repo, sha=..., per_page=100)` | List commits. |
| `list_workflow_runs(repo, workflow_id=..., status=..., per_page=100)` | List Actions workflow runs. |
| `get_workflow_run(repo, run_id)` | Retrieve a single workflow run. |
| `list_releases(repo, per_page=100)` | List releases. |
| `list_labels(repo)` | List labels defined on the repo. |
| `whoami()` | Return the authenticated user. |

### Writes

| Method | Purpose |
|---|---|
| `create_issue(repo, title, body='', labels=..., assignees=..., milestone=...)` | Create an issue. |
| `update_issue(repo, number, title=..., body=..., state=..., labels=..., assignees=...)` | Patch an issue's fields. |
| `close_issue(repo, number, reason='completed')` | Close an issue (reason = 'completed' or 'not_planned'). |
| `add_issue_comment(repo, number, body)` | Add a comment (works on issues + PRs — same endpoint). |
| `create_release(repo, tag_name, name=..., body='', draft=False, prerelease=False, target_commitish=...)` | Create a release. |
| `dispatch_workflow(repo, workflow_id, ref='main', inputs=...)` | Fire an Actions workflow. |
| `set_labels(repo, number, labels)` | Replace an issue's/PR's labels. Pass `[]` to clear. |

### Escape hatch

`get_client()` returns an authenticated `requests.Session` pointed at `api_base_url`.

## Companion components

- **`GitHubIssueUpsertComponent`** — mirror DataFrame rows into GitHub issues (keyed by body-embedded HTML comment marker so titles can be edited without breaking sync).
- **`GitHubIngestionComponent`** — dlt-based bulk read into a warehouse.
- **`GithubAuditLogIngestionComponent`** — audit log ingestion.
- **`GithubEventSensorComponent`** — poll the Events API and fire runs on new events.

## Authentication

`token_env_var` accepts an **environment variable name** (not the token itself). Set the corresponding environment variable before running Dagster:

```bash
export GITHUB_TOKEN=ghp_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
```

Create a PAT at [github.com/settings/tokens](https://github.com/settings/tokens). Fine-grained tokens work fine — scope `Issues: Read and write` on target repos is enough for issue upserts.
