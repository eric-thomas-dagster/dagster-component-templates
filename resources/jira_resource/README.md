# Jira Resource

Register a `JiraResource` for use by other Dagster components. Ships with
**16 convenience methods** over the Jira Cloud REST v3 API so your assets
can call `context.resources.jira.search_issues('project = SCRATCH')` without
touching HTTP.

Uses classic email + API-token Basic auth. Supports Jira Cloud
(`*.atlassian.net`) and Jira Data Center — pass the right `base_url`.
Uses Atlassian's new `POST /rest/api/3/search/jql` (the old `GET /search`
was removed by Atlassian in 2025).

## Installation

```bash
pip install requests
```

## Configuration

```yaml
type: dagster_community_components.JiraResourceComponent
attributes:
  resource_key: jira
  email_env_var: JIRA_EMAIL
  api_token_env_var: JIRA_API_TOKEN
  base_url: https://mycompany.atlassian.net
```

## Convenience methods

Any component with `required_resource_keys={"jira"}` can call these on `context.resources.jira`:

### Reads

| Method | Purpose |
|---|---|
| `get_issue(key, fields=...)` | Retrieve an issue by key (e.g. `'PROJ-123'`). |
| `search_issues(jql, fields=..., max_results=100)` | Run a JQL search. First page. Uses `POST /search/jql`. |
| `iter_search_issues(jql, fields=..., page_size=100)` | Auto-paginated variant via `nextPageToken`. |
| `get_project(project_key)` | Retrieve a project by key. |
| `list_projects()` | List all projects visible to the authenticated user. |
| `list_transitions(key)` | List available workflow transitions for an issue. |
| `get_comments(key)` | List comments on an issue. |
| `get_issue_types(project_key)` | Retrieve valid issue types for a project. |
| `whoami()` | Retrieve the authenticated user. |

### Writes

| Method | Purpose |
|---|---|
| `create_issue(project_key, summary, description='', issue_type='Task', labels=..., assignee_account_id=..., priority=..., extra_fields=...)` | Create an issue. Plain text descriptions are auto-wrapped as ADF. |
| `update_issue(key, summary=..., description=..., labels=..., assignee_account_id=..., priority=..., extra_fields=...)` | Patch an issue's fields. |
| `transition_issue(key, transition_name, comment='')` | Move an issue through a workflow transition. Auto-resolves the transition ID by name from current state. |
| `add_comment(key, body)` | Add a comment (plain text → ADF). |
| `assign_issue(key, account_id)` | Assign an issue (pass `None` to unassign). |
| `delete_issue(key, delete_subtasks=False)` | Delete permanently. Prefer `transition_issue` to a Done state. |

### Escape hatch

`get_client()` returns an authenticated `requests.Session` pointed at `base_url`.

## Companion components

- **`JiraIssueUpsertComponent`** — mirror DataFrame rows into a Jira project (keyed by a first-class `dagsterkey-<value>` label so JQL filters server-side).
- **`JiraIngestionComponent`** — dlt-based bulk read into a warehouse.
- **`JiraIssueSensorComponent`** — poll a project's issues and fire runs on changes.

## Authentication

Uses classic email + API-token Basic auth. Both `email_env_var` and `api_token_env_var` accept **environment variable names** (not the values themselves):

```bash
export JIRA_EMAIL=you@company.com
export JIRA_API_TOKEN=ATATT3xFf...
```

Generate an API token at [id.atlassian.com/manage-profile/security/api-tokens](https://id.atlassian.com/manage-profile/security/api-tokens). Classic tokens inherit the user's Jira permissions — no scopes to pick.

For OAuth 2.0 / Atlassian Forge auth, use a custom resource that mints tokens and pass the resulting session into the `get_client()` pattern.
