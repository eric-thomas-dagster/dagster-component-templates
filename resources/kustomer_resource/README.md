## Configuration

```yaml
type: dagster_component_templates.KustomerResourceComponent
attributes:
  resource_key: kustomer_resource  # key other components use
  org_subdomain: acme  # https://acme.api.kustomerapp.com
  api_key_env_var: KUSTOMER_API_KEY  # env var holding your API key
```

## Usage in other components

Once placed on the canvas, other components can reference this resource:

```yaml
attributes:
  resource_name: kustomer_resource
```

## Authentication

The API key env var field accepts an **environment variable name** (not the key value itself).
Set the corresponding environment variable before running Dagster:

```bash
export KUSTOMER_API_KEY="eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...."
```

Create the key under Kustomer **Settings > Security > API Keys**. Requests send it as
`Authorization: Bearer <key>` against your org-scoped base URL (requests to the wrong subdomain
fail, since Kustomer routes by org).

## API shape note

Kustomer's REST responses mostly follow a JSON:API-ish shape (`data` as either an object or an
array of `{id, type, attributes, relationships}`). There is no single simple `GET /v1/conversations`
list-everything endpoint with documented date-range pagination; the best-documented way to bulk
list/filter Conversations is the **Search API** (`POST /v1/customers/search` with
`"queryContext": "conversation"`), which this resource's `post()` helper is built for.
