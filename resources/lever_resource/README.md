## Convenience methods

Any component with `required_resource_keys={"lever_resource"}` can call these on `context.resources.lever_resource`:

| Method | Purpose |
|---|---|
| `search_opportunities_by_email(email)` | `GET /opportunities?email=...` -- exact-match email search. Returns the `data` list (empty if no match). |
| `create_opportunity(body, posting_id=None)` | `POST /opportunities?perform_as=...` -- create a new candidate/opportunity. |
| `add_tags(opportunity_id, tags)` | `POST /opportunities/{id}/addTags?perform_as=...` -- **additive only**, see below. |
| `update_stage(opportunity_id, stage_id)` | `PUT /opportunities/{id}/stage?perform_as=...` -- move to a new pipeline stage. |
| `archive_opportunity(opportunity_id, reason)` | `PUT /opportunities/{id}/archived?perform_as=...` -- archive with a reason. |

### Escape hatch

`get_client()` returns an authenticated `requests.Session` pointed at `base_url`.

## Authentication

`api_key_env_var` accepts an **environment variable name** (not the secret value itself). Lever uses HTTP Basic auth with the API key as the username and a **blank password**:

```bash
export LEVER_API_KEY="xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
```

Generate an API key in Lever under *Settings → Integrations and API → API Credentials*.

## `perform_as` -- a real, non-optional Lever API requirement

Every mutating Lever call (create opportunity, add tags, change stage, archive) requires a `perform_as` query parameter identifying the Lever user ID performing the action on behalf of. This is not a convenience knob -- Lever's API rejects mutating calls without it. Because it identifies a user (not a secret), it is a required **config field**, not an env var.

To find a user ID, call `GET /users` (optionally filtered by `email`) once and copy the `id` of the user you want actions attributed to (e.g. an integration/service account user).

## Tags are additive only

Lever's API has no "replace all tags on an opportunity" call -- only `addTags`. If you need to remove a tag, you must do so manually in the Lever UI or via Lever's bulk actions; this resource (and the Lever API itself) cannot do it programmatically.
