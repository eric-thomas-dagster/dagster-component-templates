# Magento Resource

Register a `MagentoResource` wrapping the Magento/Adobe Commerce REST API for use by other Dagster components.

## When to use

- You need to read or write Magento/Adobe Commerce catalog data (products, orders, customers) from custom Dagster asset code.
- You're pairing with `magento_product_upsert` to push a warehouse-side product catalog back into Magento as a reverse-ETL sink.
- You're pairing with `magento_ingestion` to bulk-pull Magento data (this resource is a lighter-weight, single-record-at-a-time alternative for targeted reads/writes).

## Prerequisites

1. **A pre-generated admin/integration access token.** Magento's REST API auth is a static bearer token, not an OAuth flow this resource drives itself. Generate one either:
   - Admin > System > Integrations -> create an integration, activate it, copy the generated access token, or
   - `POST /V1/integration/admin/token` with admin username/password (returns a token string).
2. Store the token in an environment variable and point `admin_token_env_var` at its name.

## Pairs with

- `magento_product_upsert` -- reverse-ETL sink (search-by-sku upsert).
- `magento_ingestion` -- bulk pull from Magento/Adobe Commerce (dlt-backed).

## Behavior + gotchas

- **`PUT /V1/products/:sku` is update-ONLY, not an upsert.** Magento's catalog product REST endpoint will not create a new product if the SKU in the path doesn't already exist -- it errors instead. To create, this resource's `create_product` does `POST /V1/products` with a body of `{"product": {...}}`. `upsert_product_by_sku` does the required search-then-write dance (GET by sku -> PUT if found, else POST) so you don't have to think about which verb to use.
- **Body `sku` must match the path `sku` on update.** `update_product` always overwrites `body["sku"]` with the `sku` you passed in, so a stray mismatched value in `product_body` can never silently misroute a request to the wrong (or a newly-aliased) product.
- **Minimal fields to create a product:** `sku`, `name`, `price`, and `attribute_set_id` (this resource defaults `attribute_set_id` to the configured `attribute_set_id` field, default `4` -- the "Default" attribute set on a stock Magento install -- if the caller doesn't supply one). In practice you also want `status` (1 = enabled), `visibility` (4 = Catalog, Search is the usual default for a standalone product), and `type_id` (`"simple"` for a basic product) -- omitting these creates a product that silently exists but is disabled/invisible/typeless in the storefront.
- **SKUs can contain slashes and spaces.** `get_product_by_sku` URL-encodes the SKU path segment so Magento's router doesn't split on an un-encoded `/`.
- **Rate limits / transient errors.** `_request` retries on `429` (honoring `Retry-After`) and `5xx` with exponential backoff, up to `max_retries`.
