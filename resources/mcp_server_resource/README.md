# MCP Server Resource

Register one MCP server connection once and reference it by name from any MCP-aware
component (`mcp_tool_call`, `mcp_tool_picker`, and the MCP-capable agent components)
instead of repeating the same `name`/`type`/`url`/`command`/`env`/`headers`/`headers_env`
fields inline in every one of them.

## Why

Every MCP-aware component in this repo accepted an inline server spec. That's fine for a
one-off, but a project with several tools/agents hitting the SAME server (e.g. one shared
Dagster+ MCP endpoint) had to redeclare the whole connection on every single one of them --
and a UI wanting to show "which servers does this project use" had nowhere to look except
every consuming component's own config.

```yaml
type: dagster_community_components.MCPServerResourceComponent
attributes:
  resource_key: dagster_plus_mcp
  name: dgp
  type: http
  url: https://mcp.agent.dagster.cloud/mcp/
  headers:
    Dagster-Cloud-Organization: my-org
  headers_env:
    Authorization: DAGSTER_PLUS_BEARER
```

Then, in any MCP-aware component, instead of its own inline `server:` block:

```yaml
server_resource_key: dagster_plus_mcp
```

Exactly one of `server` (inline) or `server_resource_key` (this resource) is required --
both still work, so existing inline configs keep working unchanged.
