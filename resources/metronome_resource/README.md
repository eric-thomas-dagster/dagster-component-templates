## Usage in other components

Once placed on the canvas, other components can reference this resource:

```yaml
attributes:
  resource_key: metronome_resource
```

- **`metronome_usage_event_send`** (reverse-ETL) -- send usage events to `POST /v1/ingest`.
- **`metronome_invoices_ingestion`** (ingestion) -- pull customers + invoices for finance reporting.

## Authentication

Verified via [docs.metronome.com/api-reference/authentication](https://docs.metronome.com/api-reference/authentication): Metronome's API uses a **static Bearer API token**, not OAuth2. Create one in the Metronome app under **Developer > API tokens**, then:

```bash
export METRONOME_API_KEY="XXXXXXXXXXXXXXXXXXXX"
```

Every request carries `Authorization: Bearer <token>`. `api_key_env_var` accepts an **environment variable name** (not the secret value itself).

## Methods

- `get_client()` -- returns an authenticated `requests.Session` (escape hatch; `Authorization: Bearer <token>` + `Content-Type: application/json` pre-set). Consuming components build their own request calls against `{base_url}/...` so each stays an isolated, independently-mockable API boundary.
