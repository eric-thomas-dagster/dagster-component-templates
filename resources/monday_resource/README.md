## Usage in other components

```yaml
attributes:
  resource_name: monday_resource
```

The resource exposes a single method for consumers:

- `execute(query, variables=None)` — POSTs `{"query": ..., "variables": ...}` to the GraphQL endpoint and returns the `data` object. Raises `MondayGraphQLError` if the response carries a top-level `errors` array (monday.com returns HTTP 200 with `errors` for most query-level failures, not a 4xx — a bad board ID or malformed query doesn't `raise_for_status()`, so this resource checks for that case explicitly).

## Authentication

```bash
export MONDAY_API_TOKEN="your-monday-api-token"
```

Generate a token under **Avatar > Admin > API** (or **Avatar > Developers > My Access Tokens** for a personal token). monday.com sends the token **raw in the `Authorization` header — no `Bearer ` prefix** (unlike most OAuth2 APIs); this resource does that for you.

## API notes

- Single endpoint: `POST https://api.monday.com/v2`. Every operation — reading boards/items, mutating columns, etc — is a GraphQL `query`/`mutation` string in the JSON body, not a REST path.
- **`API-Version` header is required.** monday.com guarantees at least three API versions in parallel (quarterly releases, each stable for 6+ months); omitting the header is the single most common cause of unexpected 4xx errors for new integrations. This resource defaults to `"2026-07"` — override via `api_version` to pin a different version.
- Pagination for list-shaped fields (like a board's items) is cursor-based via `items_page` / `next_items_page`, not offset/limit — see `assets/ingestion/monday_board_items_ingestion` for the walking logic.

Reference: [monday.com API Reference — Getting Started](https://developer.monday.com/api-reference/docs/getting-started)
