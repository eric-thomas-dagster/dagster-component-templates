# Notion Resource

Register a `NotionResource` for use by other Dagster components. Ships with
**19 convenience methods** over the Notion REST API so your assets can call
`context.resources.notion.query_database(...)` without touching HTTP.

Supports Notion's 2025 API redesign (databases → data_sources split) transparently.

## Configuration

```yaml
type: dagster_community_components.NotionResourceComponent
attributes:
  resource_key: notion_resource  # key other components use
  token_env_var: NOTION_TOKEN  # env var name holding the integration token
```

## Convenience methods

Once the resource is registered, any component with `required_resource_keys={"notion_resource"}` can call these directly on `context.resources.notion_resource`:

### Reads

| Method | Purpose |
|---|---|
| `search(query, filter=..., sort=..., page_size=100)` | Search across pages and data sources the integration has access to. |
| `iter_search(...)` | Auto-paginated variant of `search`. |
| `get_page(page_id)` | Retrieve a single page (properties, not block content). |
| `get_page_markdown(page_id)` | Retrieve a page's block content rendered as markdown (notion-client v3+). |
| `get_database(database_id)` | Retrieve a database's schema + metadata. |
| `query_database(database_id=..., data_source_id=..., filter=..., sorts=..., page_size=100)` | Query a database or data source (2025 API compatible). |
| `iter_query_database(...)` | Auto-paginated variant of `query_database`. |
| `get_block_children(block_id, page_size=100)` | List child blocks of a block or page. |
| `iter_block_children(...)` | Auto-paginated variant of `get_block_children`. |
| `get_comments(block_id, page_size=100)` | List comments on a page or block. |
| `list_users(page_size=100)` | List users (bots + humans) the integration can see. |
| `whoami()` | Retrieve the bot user that owns the integration token. |

### Writes

| Method | Purpose |
|---|---|
| `create_page(parent, properties, children=..., icon=..., cover=...)` | Create a page under a database or another page. |
| `update_page(page_id, properties=..., archived=..., icon=..., cover=...)` | Patch a page's properties (or archive it). |
| `append_blocks(block_id, children)` | Append blocks to a page or block. |
| `add_comment(text, page_id=..., discussion_id=...)` | Add a comment to a page or an existing discussion thread. |
| `create_database(parent_page_id, title, properties)` | Create a new database as a child of a page. |
| `upload_file(file_path, filename=..., content_type=...)` | Upload a file to Notion (hides the 3-step File Upload API). |

### Escape hatch

`get_client()` returns the raw `notion_client.Client` for anything not covered above.

## Companion components

- **`NotionDatabaseUpsertComponent`** — mirror DataFrame rows into a Notion database (multi-row upsert, keyed by any property).
- **`NotionPageSyncComponent`** — patch a specific Notion page's properties from a DataFrame's first row (optional markdown body replace).
- **`NotionIngestionComponent`** — dlt-based bulk read from Notion into any warehouse.
- **`NotionDatabaseSensorComponent`** — poll a database and fire a run per changed row.

## Authentication

`token_env_var` accepts an **environment variable name** (not the secret value itself). Set the corresponding environment variable before running Dagster:

```bash
export NOTION_TOKEN="ntn_XXXXXXXXXXXXXXXXXXXXXXXXX"
```

Create an internal integration at [notion.so/my-integrations](https://www.notion.so/my-integrations) to obtain the token, then share whatever pages/databases you want this resource to touch with the integration in the Notion UI.
