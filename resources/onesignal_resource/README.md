# OneSignal Resource

Register a `OneSignalResource` (plain REST API wrapper — app id + REST API key auth) for use by other components. OneSignal has no official Dagster-bindings SDK, so this talks to the REST API directly: `POST https://api.onesignal.com/notifications`, `Authorization: Key <REST_API_KEY>`.

Pairs with `onesignal_push_send` (the reverse-ETL "send a push notification to each row of a warehouse segment" sink).

## Installation

`pip install requests`

## Configuration

```yaml
type: dagster_component_templates.OneSignalResourceComponent
attributes:
  resource_key: onesignal_resource  # key other components use
  app_id: "11111111-2222-3333-4444-555555555555"
  rest_api_key_env_var: ONESIGNAL_REST_API_KEY
```

## Usage in other components

Once placed on the canvas, other components can reference this resource:

```yaml
attributes:
  resource_key: onesignal_resource
```

## Authentication

`rest_api_key_env_var` names an **environment variable** holding the secret (not the secret value itself). Set it before running Dagster:

```bash
export ONESIGNAL_REST_API_KEY="your-onesignal-rest-api-key"
```

Find your App ID and REST API Key under OneSignal dashboard -> Settings -> Keys & IDs.
