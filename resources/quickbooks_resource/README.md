# QuickBooks Resource

Register a `QuickBooksResource` wrapping the **QuickBooks Online Accounting API** for use by other Dagster components.

## Auth: OAuth 2.0 refresh-token flow + `realm_id` on every request

QuickBooks Online auth is standard OAuth2 (unlike NetSuite's OAuth 1.0a) — but every single API call must also include the `realm_id` (QuickBooks' name for the company/tenant id, obtained during the OAuth authorization callback) as a URL path segment: `https://quickbooks.api.intuit.com/v3/company/<realmId>/...`. There's no account-wide endpoint.

Token refresh: `POST https://oauth.platform.intuit.com/oauth2/v1/tokens/bearer` with `grant_type=refresh_token`, Basic-Auth'd with `client_id:client_secret`.

### Refresh-token rotation caveat

Intuit **rotates the refresh token itself** on every refresh call — each refresh returns a *new* refresh token, and the old one is invalidated after a grace window. This resource caches the in-memory **access** token for its ~1hr lifetime within a process, but it does **not** persist newly-rotated **refresh** tokens anywhere. In production, pair this with an external mechanism (secret-manager write-back, a scheduled re-auth job) to keep the stored refresh token current — otherwise access eventually fails with `invalid_grant` once the original refresh token ages out.

## Configuration

```yaml
type: dagster_component_templates.QuickBooksResourceComponent
attributes:
  resource_key: quickbooks
  realm_id: "9130354234523456"
  client_id_env_var: QBO_CLIENT_ID
  client_secret_env_var: QBO_CLIENT_SECRET
  refresh_token_env_var: QBO_REFRESH_TOKEN
  minor_version: 75
```

## Authentication setup

```bash
export QBO_CLIENT_ID="..."
export QBO_CLIENT_SECRET="..."
export QBO_REFRESH_TOKEN="..."
```

1. Create an app at [developer.intuit.com](https://developer.intuit.com) and complete the OAuth2 authorization-code flow once (interactively) to obtain an initial `realm_id` + refresh token.
2. Store the Client ID/Secret and that initial refresh token as env vars / secrets.
3. See the rotation caveat above — this is the main operational gotcha with QBO's OAuth2 compared to a typical static-secret API.

## Usage in other components

```yaml
attributes:
  resource_key: quickbooks
```

Exposes `request(method, path, json_body=None, params=None)` and `query(query_str)` (QBO's SQL-like query language, e.g. `SELECT * FROM Customer WHERE DisplayName = 'Acme Co'`). Higher-level upsert logic (query-then-create-or-update-with-SyncToken) lives in consuming components (e.g. `quickbooks_customer_upsert`), not in this resource, per this repo's no-shared-logic convention.
