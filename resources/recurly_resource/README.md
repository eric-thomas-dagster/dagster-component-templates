# Recurly Resource

Register a `RecurlyResource` wrapping the **Recurly API v3** for use by other Dagster components.

## Auth: HTTP Basic, private API key as username, blank password

No OAuth2, no token refresh — every request is HTTP Basic-authenticated with the Recurly **private** API key as the username and an empty password. Matches the convention already used by this repo's `recurly_ingestion` component.

## Dated API versioning is mandatory

Recurly v3 requires every request to pin an API version via the `Accept` header — `Accept: application/vnd.recurly.v2021-02-25+json`. There's no reliable "latest" fallback if you omit it; Recurly expects integrations to explicitly pin a version. This resource defaults to `2021-02-25` (the long-stable version most client libraries target) but `api_version` can be overridden.

## 404-as-None, not an exception

`request()` returns `None` on a 404 response instead of raising — this is deliberate: Recurly's `PUT /accounts/{account_id}` endpoint only **updates** an existing account and 404s if it doesn't exist (there's no single-call upsert), so callers doing a "does this account exist?" lookup can branch on `None` directly rather than wrapping every call in a try/except.

## Configuration

```yaml
type: dagster_component_templates.RecurlyResourceComponent
attributes:
  resource_key: recurly
  api_key_env_var: RECURLY_API_KEY
  api_version: "2021-02-25"
```

## Authentication setup

```bash
export RECURLY_API_KEY="..."
```

Generate a private API key from Recurly's admin UI: Integrations → API Credentials.

## Usage in other components

```yaml
attributes:
  resource_key: recurly
```

Exposes `request(method, path, json_body=None, params=None)` (returns `None` on 404, parsed JSON otherwise). Higher-level upsert logic (lookup-then-create-or-update) lives in consuming components (e.g. `recurly_account_upsert`), not in this resource, per this repo's no-shared-logic convention.
