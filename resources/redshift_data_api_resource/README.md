# Redshift Data Api Resource

Register a `RedshiftDataApiResource` (Redshift Data API execute + poll logic) for use by other components,
ops, or assets.

This is the Airflow `RedshiftDataOperator`'s real action -- `execute_statement` + a poll loop to a terminal
state via `describe_statement` -- extracted as a reusable `ConfigurableResource` rather than baked into a
dedicated asset. Call `execute_and_wait(...)` from your own op or asset to run a statement as a step in
your pipeline.

Distinct from `redshift_resource` (a JDBC-style connection resource) -- this one calls the `redshift-data`
boto3 client's HTTP API, no JDBC driver or persistent connection required.

## Configuration

```yaml
type: dagster_community_components.RedshiftDataApiResourceComponent

  resource_key: redshift_data_api_resource  # key other components use
  # Required
  region_name: us-east-1
```

## Usage from your own op or asset

```python
import dagster as dg

@dg.asset
def my_redshift_step(context: dg.AssetExecutionContext, redshift_data_api_resource: "RedshiftDataApiResource"):
    result = redshift_data_api_resource.execute_and_wait(
        sql="INSERT INTO my_table SELECT * FROM staging",
        database="my_database",
        workgroup_name="my-workgroup",
        log=context.log,
    )
    return result["result_rows"]
```

Connection: set EITHER `cluster_identifier` (provisioned cluster -- pair with `db_user` or `secret_arn`)
OR `workgroup_name` (Redshift Serverless) when calling `execute_and_wait`, not both.

Request it by `resource_key` the same way any other resource-providing component is referenced:

```yaml
attributes:
  resource_key: redshift_data_api_resource
```
