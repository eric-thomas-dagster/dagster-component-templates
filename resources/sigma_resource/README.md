## Usage in other components

Once placed on the canvas, other components can reference this resource:

```yaml
attributes:
  resource_key: sigma_resource
```

Both `sigma_workbook_ingestion` and `sigma_input_table_upsert` depend on this resource.

## Authentication

Verified against Sigma's own docs — ["Get started with the Sigma REST API"](https://help.sigmacomputing.com/reference/get-started-sigma-api), ["Generate Sigma API client credentials"](https://help.sigmacomputing.com/reference/generate-client-credentials), and ["Get access token"](https://help.sigmacomputing.com/reference/post-token).

1. **Generate credentials** — in Sigma: your avatar → Administration → Developer access → check "REST API" → copy the Client ID + Client Secret (the secret is shown once, at creation time only). Alternatively, `POST /v2/credentials`.
2. **Exchange for an access token** — this resource does this automatically:

   ```
   POST {base_url}/v2/auth/token
   Content-Type: application/x-www-form-urlencoded

   grant_type=client_credentials&client_id=...&client_secret=...
   ```

   Response: `access_token`, `token_type`, `expires_in` (access tokens are valid **~1 hour**). Unlike Outreach's refresh_token grant, there's no rotating refresh token to manage here — this resource just re-requests a fresh token once the cached one is within 60 seconds of expiry.

```bash
export SIGMA_CLIENT_ID="..."
export SIGMA_CLIENT_SECRET="..."
```

### Base URL / region

Sigma hosts a **separate API host per cloud + region** — confirm yours in Sigma's Admin → Account settings before relying on the default:

| Cloud / Region | Base URL |
|---|---|
| AWS-US (West, default) | `https://api.sigmacomputing.com` |
| AWS-US (East) | `https://api.us-a.aws.sigmacomputing.com` |
| AWS-CA | `https://api.ca.aws.sigmacomputing.com` |
| AWS-EU | `https://api.eu.aws.sigmacomputing.com` |
| AWS-UK | `https://api.uk.aws.sigmacomputing.com` |
| AWS-AU | `https://api.au.aws.sigmacomputing.com` |
| Azure / GCP | additional regional variants — see the "Get started" doc above |

## `.get()` / `.post()`

Both methods accept a path relative to `base_url` (or a full URL) and attach `Authorization: Bearer <token>` automatically, fetching/caching the access token as needed. `.post()` is reused by `sigma_input_table_upsert` to call Sigma's inbound **Webhook trigger** endpoint (`POST /v2/webhooks/{workbookId}/{sequenceId}`) — that endpoint takes the same Bearer-token auth as every other Sigma REST call.
