# Smartsheet Resource

Register a `SmartsheetResource` — a bearer-token Smartsheet API client with read/write row methods — for use by other Dagster components.

## Installation

```bash
pip install requests
```

## Configuration

```yaml
type: dagster_component_templates.SmartsheetResourceComponent
attributes:
  resource_key: smartsheet
  access_token_env_var: SMARTSHEET_ACCESS_TOKEN
```

## Usage in other components

Once placed on the canvas, other components can reference this resource:

```yaml
attributes:
  resource_key: smartsheet
```

## Authentication

`access_token_env_var` accepts an **environment variable name** (not the secret value itself).
Set the corresponding environment variable before running Dagster:

```bash
export SMARTSHEET_ACCESS_TOKEN="your-token-here"
```

Generate a personal access token under Account → Personal Settings → API Access, or use the access token issued to an OAuth2 app. Either way it's a static bearer string:

```
Authorization: Bearer <access_token>
```

against the single global base URL `https://api.smartsheet.com/2.0` — there's no per-account subdomain to configure.

## Key behavior: no native upsert

Smartsheet's row API has **no column-match / upsert endpoint**. `POST /2.0/sheets/{sheetId}/rows` always adds new rows; `PUT /2.0/sheets/{sheetId}/rows` always updates existing rows and **requires each row's numeric `id`** — there's no way to ask the API "update the row where column X == value".

So this resource does the matching client-side: `get_sheet(sheet_id)` fetches the sheet's current `columns` and `rows` in one call, builds a `title → columnId` map, and scans the fetched rows for a cell in the key column matching the incoming value. `upsert_rows_by_column(...)` wraps this into a single convenience call — **one sheet fetch total**, not one GET per row, then batched `add_rows` / `update_rows` calls for whatever didn't / did match.

Both `add_rows` and `update_rows` chunk automatically at Smartsheet's **500-rows-per-API-call** limit.
