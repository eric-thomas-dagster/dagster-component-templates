# SQL URL Resource

Register a `SQLUrlResource` (connect via a single SQLAlchemy connection URL, dialect-agnostic)
for use by other components -- the "SQL by URL" shape Airflow's generic SQL hooks/connections
typically use (a single connection string/URI), as opposed to this repo's per-dialect
resources (`mssql_resource`, `doris_resource`, `db2_resource`, ...) which each build a
connection string from separate host/database/user/password fields.

## Installation

## Configuration

```yaml
type: dagster_community_components.SQLUrlResourceComponent
attributes:
  resource_key: sql_url_resource  # key other components use
  connection_url_env_var: DATABASE_URL
```

Set exactly one of `connection_url` (a literal URL -- only for non-secret cases, e.g. a local
sqlite file) or `connection_url_env_var` (the name of an env var holding the real URL,
including any embedded credentials). Set the env var before running Dagster:

```bash
export DATABASE_URL="postgresql://user:pass@host:5432/dbname"
```

## Usage in other components

Once placed on the canvas, other components can reference this resource:

```yaml
attributes:
  resource_key: sql_url_resource
```

From Python (an op or asset requesting `SQLUrlResource` by parameter type):

```python
def my_asset(sql_url_resource: SQLUrlResource):
    rows = sql_url_resource.execute("SELECT id, name FROM users WHERE active = :active", {"active": True})
    # rows: list[dict] -- e.g. [{"id": 1, "name": "Ada"}, ...]

    # Escape hatch for anything execute() doesn't cover (transactions, pandas.read_sql, reflection, ...):
    engine = sql_url_resource.get_engine()
```

`execute()` works for both SELECTs (returns the matched rows as dicts) and DDL/DML (commits,
returns an empty list). Any SQLAlchemy URL scheme whose driver is installed works --
postgresql, mysql, mssql, sqlite, snowflake, bigquery, a `postgresql+psycopg2://` URL for
Redshift, duckdb, and others -- this resource doesn't restrict the dialect itself.
