# Stripe Resource

Register a `StripeResource` for use by other Dagster components. Ships
with **~30 convenience methods** over the Stripe REST API (customers,
charges, payment intents, invoices, subscriptions, products, prices,
refunds, events) so your assets can call
`context.resources.stripe.list_customers(...)` or
`.create_payment_intent(amount=1000, ...)` without touching HTTP.

Every write method accepts an `idempotency_key` — Stripe's native
retry-safety mechanism. Same key sent twice returns the original result.

Stripe uses form-encoded requests and cursor-based pagination via
`starting_after`. Both are handled internally — you pass Python dicts
and get Python dicts back.

## Installation

```bash
pip install requests
```

## Convenience methods

Any component with `required_resource_keys={"stripe"}` can call these on `context.resources.stripe`:

### Reads

| Method | Purpose |
|---|---|
| `whoami()` | Return the current Stripe account. |
| `get_customer(customer_id)` | Retrieve a customer. |
| `list_customers(email=..., page_size=100)` | List customers, optionally filtered by email exact match. |
| `iter_customers(...)` | Auto-paginated variant. |
| `search_customers(query, page_size=100)` | Search customers via the Search API. E.g., `metadata['dagster_key']:'INC-1001'`. |
| `list_charges(page_size=100)` / `iter_charges(...)` | List / auto-paginate charges. |
| `list_payment_intents(page_size=100)` / `iter_payment_intents(...)` | Same for payment intents. |
| `list_invoices(customer=..., status=..., page_size=100)` | List invoices. `status` = draft / open / paid / uncollectible / void. |
| `list_subscriptions(customer=..., status=..., page_size=100)` | List subscriptions. |
| `list_products(active=..., page_size=100)` | List products. |
| `list_prices(product=..., active=..., page_size=100)` | List prices. |
| `list_events(event_type=..., page_size=100)` | List events. Filter by type (e.g. `invoice.payment_succeeded`). |

### Writes

Every write accepts `idempotency_key` — retries with the same key return the original result.

| Method | Purpose |
|---|---|
| `create_customer(email=..., name=..., description=..., metadata=..., idempotency_key=..., **extra)` | Create a customer. |
| `update_customer(customer_id, email=..., name=..., description=..., metadata=..., **extra)` | Patch a customer. |
| `delete_customer(customer_id)` | Soft-delete a customer. |
| `create_payment_intent(amount, currency='usd', customer=..., metadata=..., idempotency_key=..., **extra)` | Create a payment intent. Amount is in the currency's smallest unit (cents). |
| `create_refund(payment_intent=..., charge=..., amount=..., reason=..., idempotency_key=...)` | Refund a payment (partial or full). |
| `create_invoice_item(customer, amount, currency='usd', description=..., idempotency_key=...)` | Add a line item to an upcoming invoice. |
| `create_invoice(customer, auto_advance=True, collection_method='charge_automatically', metadata=..., idempotency_key=...)` | Create an invoice from pending items. |
| `create_product(name, description=..., metadata=..., idempotency_key=...)` | Create a product. |
| `create_price(product, unit_amount, currency='usd', recurring_interval=..., idempotency_key=...)` | Create a price. `recurring_interval` = 'day' / 'week' / 'month' / 'year' for subscriptions. |

### Escape hatch

`get_client()` returns an authenticated `requests.Session` pointed at `api_base_url`.

## Companion components

- **`StripeCustomerUpsertComponent`** — mirror DataFrame rows into Stripe customers, keyed by a `metadata.dagster_key` field (matched via Stripe's Search API).
- **`StripeIngestionComponent`** — dlt-based bulk read into a warehouse.
- **`StripeEventSensorComponent`** — poll events and fire runs on new activity.

## Authentication

`api_key_env_var` accepts an **environment variable name** (not the token itself). Set the corresponding environment variable before running Dagster:

```bash
export STRIPE_API_KEY=sk_test_XXXXXXXXXXXXXXXXXXXX
```

Get a key from the Stripe Dashboard → **Developers → API Keys**. Use `sk_test_...` for development (all writes hit test mode, no real money moves) and `sk_live_...` for production.
