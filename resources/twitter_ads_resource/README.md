# Twitter/X Ads Resource

Register a `TwitterAdsResource` for the X (Twitter) Ads API for use by other Dagster components.

## Installation

```bash

```

## Configuration

```yaml
type: dagster_component_templates.TwitterAdsResourceComponent
attributes:
  resource_key: twitter_ads_resource
  consumer_key_env_var: TWITTER_ADS_CONSUMER_KEY
  consumer_secret_env_var: TWITTER_ADS_CONSUMER_SECRET
  access_token_env_var: TWITTER_ADS_ACCESS_TOKEN
  access_token_secret_env_var: TWITTER_ADS_ACCESS_TOKEN_SECRET
  account_id: "abc123xyz"
```

## Usage in other components

Once placed on the canvas, other components can reference this resource:

```yaml
attributes:
  resource_key: twitter_ads_resource
```

## Authentication

All secret env var fields accept **environment variable names** (not the secret values themselves).
Set the corresponding environment variables before running Dagster:

```bash
export TWITTER_ADS_CONSUMER_KEY="xxxxxxxxxxxxxxxxxxxxxxxxx"
export TWITTER_ADS_CONSUMER_SECRET="xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
export TWITTER_ADS_ACCESS_TOKEN="1234567890-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
export TWITTER_ADS_ACCESS_TOKEN_SECRET="xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
```

The X Ads API still authenticates with **OAuth 1.0a** (consumer key/secret +
access token/secret) — unlike most of X's newer v2 APIs, which moved to
OAuth 2.0. Apply for Ads API access at [developer.x.com](https://developer.x.com),
create a project/app, and generate these four credentials from the app's
"Keys and tokens" page. `account_id` is the Ads API account ID (visible in
Ads Manager's URL, e.g. `ads.x.com/accounts/<account_id>/...`) — it is
**not** the same as your numeric X user ID.
