## Configuration

```yaml
type: dagster_component_templates.VitallyResourceComponent
attributes:
  resource_key: vitally_resource  # key other components use
  subdomain: yourcompany  # from https://yourcompany.vitally.io
  region: us  # or 'eu'
  api_key_env_var: VITALLY_API_KEY  # env var holding your REST API key
```

## Usage in other components

Once placed on the canvas, other components can reference this resource:

```yaml
attributes:
  resource_name: vitally_resource
```

## Authentication

Create a REST API key in Vitally under **Settings -> Integrations -> REST API**. Vitally uses HTTP **Basic auth** with the API key as the username and an **empty password**:

```bash
export VITALLY_API_KEY="your-rest-api-key"
```

## API notes

- Base URL is subdomain + region scoped: `https://{subdomain}.rest.vitally.io` (US) or `https://{subdomain}.rest.vitally-eu.io` (EU).
- List endpoints (e.g. `GET /resources/accounts`) use **cursor-based pagination**: `limit` (max 100) + `from` (opaque cursor echoed back as `next` in the response). Requests are capped at 1000/minute.
- Used by the paired `VitallyAccountsIngestionComponent` (see `assets/ingestion/vitally_ingestion`) to ingest Accounts.
