# Zuora Resource

Register a `ZuoraResource` wrapping the **Zuora REST API** for use by other Dagster components.

## Auth: OAuth2 client-credentials — NOT session-based

Zuora's REST API is authenticated with a standard OAuth2 client-credentials grant: `POST <base_url>/oauth/token` with `grant_type=client_credentials`, `client_id` + `client_secret` as form fields, returning a Bearer access token (~1hr lifetime, cached in-memory per process here).

This is worth stating plainly because Zuora historically also supported a **session-based** auth (`POST /v1/connect` with a username/password, returning a `ZSession` cookie-like token) — some older integration guides and SDKs still reference it. **Zuora deprecated all legacy authentication methods, including Z-Session, for every tenant and environment on August 1, 2024.** OAuth2 client-credentials is the only supported mechanism going forward. This resource implements OAuth2 only, matching the convention already used by this repo's `zuora_ingestion` component.

## Object CRUD vs. the full Accounts endpoint

Zuora exposes two different ways to write an Account:

- **`/v1/accounts`** — the full-featured endpoint that can atomically create an account *plus* its first subscription and payment method in one call. Out of scope for a plain record upsert.
- **Generic Object CRUD** — `POST /v1/object/account` (create) and `PUT /v1/object/account/{id}` (update) — a lightweight create/update pair that only touches the Account object itself. This is what `zuora_account_upsert` uses.

There's no filter-by-field GET on the Object CRUD API (only GET-by-id), so looking an account up by a business key like `AccountNumber` requires Zuora's query language — ZOQL, via `POST /v1/action/query` — which this resource exposes as `query()`.

## Configuration

```yaml
type: dagster_component_templates.ZuoraResourceComponent
attributes:
  resource_key: zuora
  base_url: "rest.na.zuora.com"
  client_id_env_var: ZUORA_CLIENT_ID
  client_secret_env_var: ZUORA_CLIENT_SECRET
```

## Authentication setup

```bash
export ZUORA_CLIENT_ID="..."
export ZUORA_CLIENT_SECRET="..."
```

Create an OAuth client in the Zuora UI (Settings → Administration Setup → Manage Users, or Platform → OAuth Clients depending on edition) to obtain a Client ID/Secret pair.

## Usage in other components

```yaml
attributes:
  resource_key: zuora
```

Exposes `request(method, path, json_body=None, params=None)` and `query(zoql)` (ZOQL via `POST /v1/action/query`). Higher-level upsert logic (query-then-create-or-update) lives in consuming components (e.g. `zuora_account_upsert`), not in this resource, per this repo's no-shared-logic convention.
