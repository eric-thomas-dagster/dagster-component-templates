# AssetJob

Creates a job over the configured asset and/or asset check selection so it shows up as a discrete unit in the Dagster UI's Jobs tab. Useful when you want a one-button 'run this subset' experience without committing to a schedule.

## Example YAML
```yaml
type: dagster_community_components.AssetJobComponent
attributes:
  job_name: backfill_revenue
  asset_keys: [orders_raw, orders_clean, daily_revenue, monthly_revenue]
  description: One-click revenue refresh from raw orders all the way through monthly rollup.
  tags:
    purpose: backfill
```

### One-button "just re-run this check" job

`asset_keys` only ever selected assets -- there was no way to put an asset
check alone in a job. `asset_check_keys` fixes that (as `'<asset_key>:
<check_name>'` strings, asset key segments slash-separated). Confirmed
directly against Dagster's own `AssetSelection.checks(...)`: a check-only
selection really does run with zero re-materialization of the parent asset.

```yaml
type: dagster_community_components.AssetJobComponent
attributes:
  job_name: revalidate_orders_row_count
  asset_check_keys: ["marts/orders:row_count_check"]
```
