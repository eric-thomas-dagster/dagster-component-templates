# Oracle CDC Monitor Sensor

Micro-batch change-data-capture source reading Oracle's redo/archive logs via LogMiner: resumes from a stored SCN (System Change Number), classifies every row change as insert/update/delete with structured column-level before/after values, batches a tick's changes into one run, and stops once it has caught up to the database's current SCN.

## Purpose

This is the ongoing-changes half of a CDC pipeline for Oracle — not a long-running streaming process, a **poll-catch-up-stop sensor** like this registry's `mysql_cdc_monitor`/`s3_monitor`/`kafka_monitor`. Perfect for:

- Replacing a StreamSets "Oracle CDC Client" origin when migrating a continuous CDC pipeline to Dagster
- Feeding a CDC-apply sink (insert/update/delete-by-key) with exactly the row changes it needs to apply
- Keeping a warehouse staging table in sync with an OLTP Oracle database without full-table re-reads

**Not built for:** an initial load of existing rows. Pair this sensor with a separate one-time snapshot (e.g. this registry's own full-table ingestion components) to seed the target before CDC takes over — `on_first_run: start_now` (the default) deliberately skips all historical archived logs and begins from the database's current SCN.

## What's verified vs. a known limitation

**Verified** against Oracle's own current (19c) `DBMS_LOGMNR` PL/SQL Packages and Types Reference:

- `DBMS_LOGMNR.MINE_VALUE(sql_redo_undo, column_name) RETURN VARCHAR2` and `DBMS_LOGMNR.COLUMN_PRESENT(sql_redo_undo, column_name) RETURN NUMBER` read a *specific* column's value out of `V$LOGMNR_CONTENTS.REDO_VALUE`/`.UNDO_VALUE` — this sensor uses these for structured before/after column values, **not** parsing the `SQL_REDO`/`SQL_UNDO` reconstructed-SQL text (which has real documented escaping/quoting quirks that make it a much less reliable source of truth). `column_name` must be fully-qualified `schema.table.column`. Neither function supports `LONG`, LOB, `ADT`, or `COLLECTION` datatypes — a column of one of those types always reads as absent, a documented Oracle limitation, not a bug here.
- `DBMS_LOGMNR.CONTINUOUS_MINE` is confirmed **desupported as of 19c** ("no replacement functionality") — this sensor does not use it. Instead, `DBMS_LOGMNR.ADD_LOGFILE` is called once per archived-log file covering the needed SCN range (resolved via `V$ARCHIVED_LOG.FIRST_CHANGE#`/`.NEXT_CHANGE#`), then `DBMS_LOGMNR.START_LOGMNR(startScn=..., endScn=...)` mines exactly that range.

**Known, deliberate limitation:** this sensor mines **archived** redo logs only, not the current online redo log — a change becomes visible once its containing log is archived (a log switch), not the instant it commits. This trades a small latency tail for the stable, documented `ADD_LOGFILE`/archived-log path instead of the more fragile online-redo-log tracking the now-desupported `CONTINUOUS_MINE` used to paper over. Tune your database's log-switch frequency (e.g. `ARCHIVE_LAG_TARGET`) if you need tighter latency.

## Failure modes handled explicitly

- **Archived log gap** (the covering log for the stored SCN has been deleted/expired): fails loudly via `skip_reason` naming the exact gap, rather than silently skipping changes. Re-snapshot the tracked tables and reset the sensor's cursor to resume cleanly.
- **`oracledb` not installed**: skips with a clear install instruction rather than crashing the sensor daemon.

## Required permissions

The configured `username` needs `SELECT_CATALOG_ROLE` (or explicit `SELECT` on `V$LOGMNR_CONTENTS`/`V$ARCHIVED_LOG`/`V$DATABASE`/`ALL_TAB_COLUMNS`), `EXECUTE` on `DBMS_LOGMNR`, and the tracked tables must have supplemental logging enabled for the columns you need in before/after values (`ALTER TABLE ... ADD SUPPLEMENTAL LOG DATA (ALL) COLUMNS` for full-column capture).

## Output contract

Matches `mysql_cdc_monitor`'s shape so downstream CDC-apply sinks (`dataframe_to_delta_table`/`sql_to_database_asset`/`dataframe_to_databricks`'s `delete_column` support) can consume either source identically:

```json
{
  "table": "ORDERS",
  "_cdc_op": "insert" | "update" | "delete",
  "before": {"STATUS": "NEW"} | null,
  "after": {"STATUS": "SHIPPED"} | null,
  "scn": 123456789
}
```
