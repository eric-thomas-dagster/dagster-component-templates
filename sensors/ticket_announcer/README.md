# ticket_announcer

Posts each new ticket an engineering agent filed -- GitHub Issues carrying a given label, and/or Linear tickets in a given team -- to Slack with a short excerpt, once.

## What ships

One sensor. Per tick: lists open GitHub issues carrying `github_issue_label` (excluding pull requests) if `repo` is set, and/or open Linear issues in `linear_team_id` whose description contains `linear_marker` if set, then posts anything not already announced. Dedup is a plain `{"GitHub:7", "Linear:ENG-12", ...}` set held in this sensor's own Dagster-native cursor -- no file at all.

At least one of `repo` / `linear_team_id` must be set.

## The excerpt

`_excerpt()` looks for an "Analysis" section header in the ticket body (one agents commonly write) and quotes the text between it and a "Suggested change" header, if present; otherwise it quotes the start of the body. Either way it's capped at `excerpt_chars` (default 320).

## Why a label (GitHub) / a marker (Linear), not "every issue"

Without a filter, every issue in a busy repo/team would get announced. `github_issue_label` (default `engineering-agent`) and `linear_marker` (default `"Filed by an engineering agent."`) scope this to tickets the agents themselves filed -- Linear API keys can't always create labels, so a description marker is the more portable filter there.
